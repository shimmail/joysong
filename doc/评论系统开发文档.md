# 评论与评价系统开发文档

> 本文档涵盖日记评论回复功能和订单评价管理功能的开发经验，记录踩坑点，避免重复问题。

# 第一部分：日记评论系统

## 1. 架构概览

### 数据模型
- **Comment** (`parentId: String?`, `replyToUserId: String?`)
  - `parentId == null` → 顶级评论
  - `parentId != null` → 子评论（回复）
- 子评论嵌套在父评论的 `CommentItem` 内渲染，**不是独立的 LazyColumn item**

### 前端 (Android Compose)
- `DetailViewModel.loadComments()` → 加载顶级评论 + 自动加载所有子回复到 `repliesMap`
- `DetailViewModel.loadReplies(parentId)` → 按需加载某父评论的回复
- `repliesMap: Map<String, List<Comment>>` → 缓存已加载的回复

### 后端 (Spring Boot + JPA)
- `CommentEntity` 使用 `@SQLDelete` + `@Where(clause = "deleted_at IS NULL")` 实现软删除
- `CommentController.deleteComment()` 级联软删除父评论及其子回复

## 2. 踩坑记录

### 2.1 JPA 软删除后查询仍返回已删除实体

**现象：** 删除评论后，Android 端调用 `GET /api/comments` 仍返回已删除的评论。

**根因：** `save(entity.copy(deletedAt = now))` 更新了数据库 `deleted_at` 字段，但 JPA Persistence Context（一级缓存）中的实体未被清除。同一事务内的后续查询从缓存读取，`@Where` 过滤条件在 SQL 层生效但缓存层绕过了它。

**解决方案：**
```kotlin
// 软删除后，清除持久化上下文
entityManager.flush()   // 写入数据库
entityManager.clear()   // 清除一级缓存
```
需要在 Controller 中注入 `EntityManager` 并添加 `@Transactional` 注解。

**关键代码：** `CommentController.kt`
```kotlin
@Transactional
@DeleteMapping("/{id}")
fun deleteComment(...): BaseResponse<*> {
    // ... 软删除逻辑 ...
    commentRepository.save(comment.copy(deletedAt = LocalDateTime.now()))
    entityManager.flush()
    entityManager.clear()
    // ... 后续操作 ...
}
```

### 2.2 Compose LaunchedEffect 只触发一次

**现象：** 点击回复后键盘只弹出一次，后续点击同一评论不再弹出。

**根因：** `LaunchedEffect(replyTarget)` 仅在 key 值**变化**时触发。如果 `replyTarget` 不变（如连续点击同一评论），effect 不会重新执行。

**解决方案：** 使用自增计数器作为 key：
```kotlin
var replyTrigger by remember { mutableStateOf(0) }
// 每次点击回复
replyTrigger++

LaunchedEffect(replyTrigger) {
    if (replyTrigger > 0 && replyTarget != null) {
        // 弹出键盘 + 滚动
    }
}
```

### 2.3 键盘弹出后焦点残留

**现象：** 键盘被手动收起后，再次点击回复无法弹出键盘。

**根因：** `BasicTextField` 内部仍持有焦点状态，`requestFocus()` 检测到已有焦点后不再触发 IME 弹出。

**解决方案：** 先 `clearFocus()` 再 `requestFocus()`：
```kotlin
val focusManager = LocalFocusManager.current
focusManager.clearFocus()
delay(50)
focusRequester.requestFocus()
```

---

### 2.4 键盘已弹出时重复弹出

**现象：** 键盘已显示时点击回复，键盘会先收起再弹出，体验不佳。

**解决方案：** 检测键盘状态，仅在未弹出时触发：
```kotlin
val imeInsets = WindowInsets.ime
val density = LocalDensity.current

val imeHeight = imeInsets.getBottom(density)
val isKeyboardVisible = imeHeight > 0

if (!isKeyboardVisible) {
    focusManager.clearFocus()
    delay(50)
    focusRequester.requestFocus()
    delay(300) // 等待键盘完全弹出
}
// 然后执行滚动
```

### 2.5 子评论滚动定位

**现象：** 回复子评论时只能滚动到父评论顶部，子评论不可见。

**根因：** 子评论嵌套在父评论的 `CommentItem` 内部，`LazyColumn.animateScrollToItem()` 只能定位到父评论这个 item，无法直接定位到内部的子评论。

**解决方案：** 使用正向 `scrollOffset` 跳过父评论内容区域：
```kotlin
// 动态估算父评论内容高度（根据文本行数）
val lineHeightDp = 20
val charsPerLine = 22
fun textLines(text: String) = maxOf(1, (text.length + charsPerLine - 1) / charsPerLine)

val parentContentDp = 100 + (textLines(parentComment.content) * lineHeightDp)
// 每条前置回复的高度
val precedingRepliesDp = (0 until replyIndex).sumOf { i ->
    80 + (textLines(replies[i].content) * lineHeightDp)
}
val offsetDp = parentContentDp + precedingRepliesDp
val offsetPx = with(density) { offsetDp.dp.toPx().toInt() }
listState.animateScrollToItem(scrollIndex, offsetPx)
```

**注意：** `scrollOffset` 参数单位为**像素**，需要通过 `density` 转换 dp。

### 2.6 删除日记后列表不更新

**现象：** 发布/删除/编辑日记后，"我的日记"页面不刷新。

**根因：** `ViewModel.init { loadDiaries() }` 只在首次创建时执行。Compose Navigation 中页面保持 composed 状态，`LaunchedEffect(Unit)` 不会重新触发。

**解决方案：** 使用 `LifecycleResumeEffect` 监听页面可见性：
```kotlin
import androidx.lifecycle.compose.LifecycleResumeEffect

LifecycleResumeEffect(Unit) {
    viewModel.loadDiaries()
    onPauseOrDispose { }
}
```

### 2.7 下拉刷新状态管理

**现象：** 下拉刷新图标不消失，或刷新时列表闪烁。

**解决方案：** 分离初始加载和下拉刷新状态：
```kotlin
// 初始加载：设置 isLoading（列表为空时）
private suspend fun loadDiariesFromApi() {
    val isInitialLoad = _uiState.value.diaries.isEmpty()
    if (isInitialLoad) _uiState.value = MyDiariesUiState(isLoading = true)
    // ...
}

// 下拉刷新：使用独立的 isRefreshing 状态
fun refreshDiaries() {
    _isRefreshing.value = true
    viewModelScope.launch {
        // 加载数据（不清空现有列表）
        _isRefreshing.value = false
    }
}
```

### 2.8 子评论自动展开

**现象：** 进入详情页只显示父评论，需要手动点击“查看回复”。

**解决方案：** `loadComments()` 加载父评论后自动获取所有子回复，并通过 `LaunchedEffect` 自动展开：
```kotlin
// ViewModel
fun loadComments(diaryId: String) {
    viewModelScope.launch {
        commentRepository.getComments(diaryId)
            .onSuccess { list ->
                comments.value = list
                list.forEach { comment ->
                    commentRepository.getReplies(comment.id)
                        .onSuccess { replies ->
                            if (replies.isNotEmpty()) {
                                repliesMap.value = repliesMap.value + (comment.id to replies)
                            }
                        }
                }
            }
    }
}

// Screen
LaunchedEffect(repliesMap) {
    repliesMap.keys.forEach { parentId ->
        if (!expandedReplies.contains(parentId)) {
            expandedReplies.add(parentId)
        }
    }
}
```

### 2.9 评论点赞功能

**架构：** 复用多态 `likes` 表，`targetType = "comment"` 实现评论点赞。

**后端实现：**
- `CommentEntity` 新增 `like_count` 字段
- `LikeController` 在 like/unlike 时通过 `JdbcTemplate` 原子更新 `comments.like_count`
- `CommentController` 接受可选 `Authentication?`，查询 `likes` 表返回 `isLiked` 状态

```kotlin
// CommentController - toResponse 检查当前用户是否点赞
private fun toResponse(comment: CommentEntity, currentUserId: String? = null): CommentResponse {
    val isLiked = currentUserId?.let {
        likeRepository.existsByUserIdAndTargetTypeAndTargetId(it, "comment", comment.id)
    } ?: false
    return CommentResponse(..., likeCount = comment.likeCount, isLiked = isLiked)
}
```

**前端实现：**
- `DetailViewModel.likeComment()` 先查 `isLiked`，再调用 `like/unlike`，乐观更新本地状态
- `updateCommentLikeState()` 同时更新 `comments` 和 `repliesMap` 中的点赞状态

**数据库迁移：** `V19__add_comment_like_count.sql`
```sql
ALTER TABLE comments ADD COLUMN like_count INT NOT NULL DEFAULT 0;
```

### 2.10 评论折叠功能

**功能：** 父评论和子评论都有喜欢（❤️ 爱心）和讨厌（😐/😞 表情）按钮。

**讨厌脸图标：**
- 未触发：`Icons.Outlined.SentimentNeutral`（嘴角平直）
- 已触发：`Icons.Filled.SentimentDissatisfied`（嘴角向下，实心高亮）

**折叠行为：**
- 点击讨厌脸 → 折叠评论，显示“该内容已折叠，将为您优化后续评论展示”
- 折叠提示文本**不可点击**，只能再次点击讨厌脸图标取消折叠
- 父评论和子评论都支持折叠，折叠状态统一存储在 `collapsedComments` 集合中

**子评论折叠需传递状态：**
```kotlin
// CommentItem 参数
collapsedReplyIds: Set<String>

// ReplyItem 调用
ReplyItem(
    isCollapsed = collapsedReplyIds.contains(reply.id),
    onToggleCollapse = { onCollapseReply(reply.id) }
)
```

### 2.11 折叠状态持久化

**需求：** 用户折叠评论后，再次进入同一日记详情页时仍保持折叠状态。

**实现：** 使用 DataStore `stringSetPreferencesKey` 持久化存储。

**TokenManager：**
```kotlin
private val collapsedCommentsKey = stringSetPreferencesKey("collapsed_comments")

suspend fun saveCollapsedComments(ids: Set<String>)
suspend fun getCollapsedComments(): Set<String>
val collapsedCommentsFlow: Flow<Set<String>>
```

**DetailViewModel：**
```kotlin
private val _collapsedComments = MutableStateFlow<Set<String>>(emptySet())
val collapsedComments: StateFlow<Set<String>> = _collapsedComments.asStateFlow()

fun loadCollapsedComments()  // 进入详情页时加载
fun toggleCommentCollapse(commentId: String)  // 切换并持久化
```

**Screen：**
```kotlin
val collapsedComments by viewModel.collapsedComments.collectAsState()
LaunchedEffect(diaryId) {
    viewModel.loadCollapsedComments()
}
```

**注意：** `collapsedComments` 存储的是所有评论 ID（父评论 + 子评论），跨详情页共享。如需按日记隔离，可在 key 中加入 diaryId 前缀。

## 3. 最佳实践总结

| 场景 | 推荐方案 |

# 第二部分：订单评价管理系统

> 用户对已完成订单的评价功能，支持提交、查看、编辑、删除操作。

## 5. 架构概览

### 5.1 后端架构

**核心服务：`ReviewService`**
- `submitReview()` — 提交评价，Controller 层使用 `@Min(1)` / `@Max(5)` 注解校验评分范围，Service 层 `require(rating in 1..5)` 作为双重保障
- `getReviewByOrderId(orderId)` — 按订单查询评价
- `updateReview(reviewId, userId, rating, content, tags, images)` — 编辑评价（含权限校验 + 评分重算）
- `deleteUserReview(reviewId, userId)` — 用户删除评价（软删除 + 评分重算 + 重置订单 `hasReview`）
- `recalculateStats(institutionId, doctorId)` — **私有方法**，在提交/编辑/删除三个场景复用，重新计算机构和医生的评分统计

**新建控制器：`ReviewController`（`/api/reviews`）**

| 端点 | 方法 | 说明 |
|------|------|------|
| `POST /api/orders/{id}/review` | POST | 提交评价（已有，OrderController） |
| `GET /api/reviews/order/{orderId}` | GET | 按订单查评价详情（新增） |
| `PUT /api/reviews/{id}` | PUT | 编辑评价，需认证（新增） |
| `DELETE /api/reviews/{id}` | DELETE | 删除评价，需认证（新增） |

**新建 DTO：`ReviewResponse`**
- 精简的评价响应对象
- 字段：`id`, `orderId`, `userId`, `doctorId`, `rating`, `content`, `tags`, `images`, `createdAt`
- 含 `from(ReviewEntity)` 工厂方法，用于实体到 DTO 的转换

### 5.2 Android 端架构

**OrderListScreen — 订单列表**
- 已完成订单卡片（`COMPLETED` / `PENDING_SETTLEMENT` / `SETTLED`）添加"查看评价"按钮
- "查看评价"与"去评价"按钮互斥显示

**OrderDetailScreen — 订单详情**
- 新增 `ReviewInfoCard` 组件展示评价详情
  - 星级评分显示
  - 评价内容与标签
  - 评价图片展示
  - 评价时间
  - 编辑/删除操作入口

**OrderDetailViewModel — 评价数据管理**
- 新增评价加载功能
- 新增评价删除功能（含 Toast 反馈）

**ReviewOrderScreen — 评价提交/编辑页**
- 通过 `editMode` 路由参数支持编辑模式
- 复用组件：星级选择器、文本输入框、图片上传组件
- 编辑模式下预填充已有评价数据

**路由扩展**
- `ReviewOrder` 路由新增 `editMode` 可选布尔参数，区分提交与编辑模式

### 5.3 管理后台（评价管理页）

**页面：`ReviewsPage`**
- 全量加载评价列表，调用 `GET /api/admin/reviews` 获取数据
- 展示字段：ID、订单ID、用户ID、医生ID、评分、内容、标签、创建时间
- 支持按医生ID、内容、ID、订单ID 关键词搜索过滤（前端本地过滤）

- 批量删除：表格支持行选择，批量删除按钮使用 `Promise.all` 并行调用单条删除接口
- 删除成功后自动刷新列表

**后端 API：`AdminReviewController`**

| 端点 | 方法 | 说明 |
|------|------|------|
| `GET /api/admin/reviews` | GET | 查询全部评价（管理端） |
| `DELETE /api/admin/reviews/{id}` | DELETE | 管理员删除评价（含评分重算 + hasReview 重置） |

## 6. 关键实现细节

### 6.1 评分重算机制

`recalculateStats(institutionId, doctorId)` 方法在以下场景自动触发：
1. **提交评价** — 新评分纳入统计
2. **编辑评价** — 评分变更后重新计算
3. **删除评价** — 移除该评分后重新计算

此方法确保机构和医生的平均评分始终与实际评价数据一致。

### 6.2 删除评价的级联操作

用户删除评价时执行以下操作：
1. 软删除评价记录（`deletedAt` 标记）
2. 调用 `recalculateStats()` 重算评分
3. 重置订单的 `hasReview` 字段为 `false`，使"去评价"按钮重新可用

### 6.3 adminDeleteById 修复

**问题：** 管理员删除评价后未执行评分重算和 `hasReview` 重置。

**修复：** 在 `adminDeleteById()` 中补充：
- 调用 `recalculateStats()` 重算关联机构和医生的评分
- 重置对应订单的 `hasReview` 字段

## 10. 预约时间显示修复

**问题：** 订单详情页中预约时间显示为原始 ISO-8601 格式（含 `T` 分隔符），如 `2026-08-01T14:30:00`，用户可读性差。

### 10.1 Android 端发送 ISO-8601 格式

**变更：** `BookingConfirmScreen` 提交预约时，确保 `appointmentTime` 使用标准 ISO-8601 格式（`yyyy-MM-dd'T'HH:mm:ss`）发送到后端。

### 10.2 后端兜底解析

**变更：** `OrderService` 中对预约时间字符串增加兜底解析逻辑：
- 优先按 ISO-8601 格式（含 `T`）解析
- 兜底兼容空格分隔格式（`yyyy-MM-dd HH:mm:ss`），将空格替换为 `T` 后再解析
- 确保前后端格式不一致时仍能正常处理

### 10.3 前端统一日期格式化

**变更：** 所有展示日期字段的地方统一执行格式化：
```kotlin
// 将 ISO-8601 的 T 分隔符替换为空格，截取到分钟
dateString.replace("T", " ").take(16)
// 输出示例："2026-08-01 14:30"
```

**影响范围：**
- `OrderDetailScreen` — 预约时间、创建时间、支付时间等
- `OrderListScreen` — 订单卡片时间显示
- 所有涉及日期展示的组件

## 11. 已完成订单退款白名单扩展

**问题：** 已到达结算阶段（`PENDING_SETTLEMENT` / `SETTLED`）的订单无法申请退款，退款接口返回状态不允许。

**变更：** `RefundService` 退款状态白名单新增两个状态：

| 状态 | 说明 |
|------|------|
| `PENDING_SETTLEMENT` | 待结算，订单已完成但尚未结算 |
| `SETTLED` | 已结算，订单已完成结算 |

**影响：** 已完成并进入结算流程的订单，用户仍可发起退款申请，由管理端审核处理。
