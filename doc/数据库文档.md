# 娇颜颂 数据库文档

> 数据库名：`joysong`（本地工作树验证使用独立库）
> 数据库类型：MySQL 8.0
> 字符集：`utf8mb4`
> 存储引擎：InnoDB
> 主键策略：UUID `VARCHAR(36)`
> 迁移管理：Flyway（B1 权威基线，后续由 V2 起增量迁移）
> 逻辑删除：`deleted_at` 字段（14 张表支持）

### 2.21.2 wallets 与 wallet_ledger_entries（内部钱包及账本，V17/V18）

`wallets` 以 `(owner_type, owner_id, currency)` 唯一，保存当前 `pending_minor`、`available_minor`、`frozen_minor` 三个非负余额桶；`currency` 为 ISO-4217 三位币种代码，所有金额为最小货币单位整数。`wallet_ledger_entries` 是不可变的追加式账本，`operation_key` 全局唯一并用于重试幂等；每行保存三种 delta 和写入后的三个余额快照，禁止依赖客户端重新累计。

| 表 | 关键字段/约束 | 说明 |
|----|---------------|------|
| wallets | `pending_minor`、`available_minor`、`frozen_minor` 非负；`version` 乐观版本 | 当前内部余额 |
| wallet_ledger_entries | `wallet_id`、可选 `allocation_id`、`entry_type`、`source_type/source_id`、唯一 `operation_key` | 变动来源与幂等标识 |
| wallet_ledger_entries | `pending_balance_minor`、`available_balance_minor`、`frozen_balance_minor` 非负 | V18 写入后的余额快照 |

### 2.21.3 reconciliation_issues（收入一致性异常表，V17/V19）

记录内部收入台账的非破坏性对账异常，不触发外部资金操作。活动异常由 `issue_type + object_type + object_id` 的 `active_key` 唯一约束进行 upsert；V19 还记录 `expected_minor`、`actual_minor`、`currency`、`severity`、`status`、首次/最近发现时间和 `occurrence_count`。`status` 通常为 `OPEN` 或 `RESOLVED`。

> **范围边界：** 本台账不包含 Airwallex 集成、beneficiary/KYC、FX、提现/withdrawal 或真实 payout；这些能力及其密钥均不应存储在上述表中。

## 四、逻辑删除设计

### 4.1 设计理念

使用 `deleted_at TIMESTAMP NULL DEFAULT NULL` 字段实现软删除，替代物理删除。

### 4.0 目录数据一致性规则

- 机构、项目、医生和机构项目均采用软删除；订单、日记、评价保留历史快照，不因目录数据下架而被级联删除。
- 删除机构前必须先移除其机构项目和医生绑定；删除项目或医生前必须先移除对应的医生项目绑定；存在进行中订单时一律拒绝删除并返回 HTTP 409。
- 创建或修改机构项目的医生绑定时，医生必须存在且已绑定该机构，避免跨机构的可预约项目关系。
- 医生—机构关系以 `doctor_institutions` 为准，更新医生时在同一事务内同步该关联表及旧的主机构兼容字段。

- **未删除：** `deleted_at IS NULL`
- **已删除：** `deleted_at` 存储执行删除的时间戳

### 4.2 支持的表（共 14 张 + 1 张布尔标记）

使用 `deleted_at` 时间戳：`users`、`banners`、`institutions`、`doctors`、`projects`、`expert_articles`、`diaries`、`orders`、`reviews`、`chat_sessions`、`comments`、`institution_projects`、`doctor_institution_project_configs`、`notifications`

使用 `deleted` 布尔字段：`reports`（举报记录表，支持撤销删除）

### 4.3 JPA 实现方式

通过 Hibernate 注解实现自动过滤：

```kotlin
@SQLDelete(sql = "UPDATE {table} SET deleted_at = NOW() WHERE id = ?")
@Where(clause = "deleted_at IS NULL")
```

- `@SQLDelete`：重写 `delete()` 方法，将 DELETE 转换为 UPDATE
- `@Where`：所有查询自动追加 `WHERE deleted_at IS NULL` 条件

### 4.4 不支持逻辑删除的表

`favorites`、`payments`、`refunds`、`follows`、`doctor_projects`、`chat_messages`、`likes`、`dm_conversations`、`dm_messages` — 这些表使用物理删除或不支持删除操作。
