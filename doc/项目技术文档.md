## 一、项目概述和架构设计

### 1.1 项目简介

**娇颜颂（JoySong）**是一个医美服务平台，为用户提供医美项目浏览、机构/医生查询、在线预约、订单管理、AI咨询、社区分享等完整功能。项目采用前后端分离架构，包含三个主要模块：

```
joysong/
├── joysong-app/     # Android 客户端（Kotlin + Jetpack Compose）
├── joysong-server/  # 后端服务（Kotlin + Spring Boot 3）
└── joysong-admin/   # 管理后台（React + TypeScript + Ant Design）
```

### 1.4 核心业务流程

#### 1.4.1 用户旅程

```
注册/登录 → 首页浏览 → 发现页搜索 → 项目/机构/医生详情
    → AI咨询（上下文感知）→ 预约下单 → 支付面诊金
    → 到店核验 → 支付尾款 → 服务完成 → 评价/日记
    → 结算分账（30天等待期）
```

#### 1.4.2 订单生命周期

```
PENDING_PAYMENT → CONSULTATION_PAID → VERIFIED → BALANCE_PAID
→ PENDING_COMPLETION → COMPLETED → PENDING_SETTLEMENT → SETTLED

异常流程：任意阶段可 → DISPUTE_MEDIATION / CANCELLED / REFUNDED
```

#### 1.4.3 AI对话流程

```
用户进入详情页 → 点击"AI咨询" → 携带上下文（项目/机构/医生）
→ 创建会话（persona + contextType + contextId）
→ 发送消息 → 后端构建system prompt（含上下文信息）
→ 调用OpenAI API → 返回AI回复 → 前端渲染
```

## 二、AI功能模块详细说明

### 2.1 AI角色体系

项目通过 `persona` 字段实现多AI角色共享同一套数据表，每个角色有独立的 system prompt 和业务定位：

| 角色 | persona值 | 名称 | 定位 | 数据表 |
|------|----------|------|------|--------|
| AI闺蜜 | `BESTIE` | 小颜 💕 | 日常闲聊、情感陪伴、术后关怀 | chat_sessions / chat_messages |
| AI美学咨询师 | `CONSULTANT` | 娇娇 💎 | 专业医美咨询、项目分析、方案建议 | chat_sessions / chat_messages |
| 平台客服 | `CS` | 小娇 💬 | 订单售后、平台使用问题 | dm_conversations / dm_messages |

**关键设计决策：** BESTIE 和 CONSULTANT 共享 `chat_sessions` + `chat_messages` 两张表，通过 `persona` 字段区分。CS（客服）使用独立的 `dm_conversations` + `dm_messages` 表（复用私信基础设施，固定对话方为 `CS_ADMIN`）。

**上下文感知对话：**

2. 构建上下文消息（如："我想了解医美项目「热玛吉」的相关信息..."）
3. 延迟500ms后自动发送，确保 session 加载完成

```kotlin
private fun buildContextMessage(): String {

        "doctor" -> "我想咨询一下${state.contextName}医生的相关信息..."
        else -> ""
    }
}
```

### 2.3 后端AI聊天服务

#### 2.3.1 ChatService.kt — 核心AI服务

**文件位置：** `joysong-server/src/main/kotlin/com/joysong/server/chat/service/ChatService.kt`

**依赖注入：**

```kotlin

    private val doctorRepository: DoctorRepository,
```

**发送消息完整流程（sendMessage）：**

```
1. 验证session归属（确保用户只能操作自己的会话）
2. 保存用户消息到 chat_messages 表（role = "USER"）
3. 获取最近10条历史消息作为上下文
4. 构建 LLM 消息列表：
   ├── system prompt（根据persona + contextType + contextId动态生成）
   └── 历史消息（按时间正序排列）
5. 按 `AiAgentProperties.provider` 生成 Qwen 兼容请求并调用 Chat Completions API
6. 保存 AI 回复到 chat_messages 表（role = "ASSISTANT"）
7. 更新 session 的 updatedAt 时间戳
8. 返回 AI 消息实体
```

```kotlin
private fun providerChatCompletionsUrl(): String =

private fun callLLM(messages: List<Map<String, String>>): String {
    check(aiAgentProperties.apiKey.isNotBlank()) { "AI_PROVIDER_UNAVAILABLE" }
```

### 2.4 客服消息模块（CS）

客服模块与AI聊天独立，复用私信（DM）基础设施：

- `CsService.kt` — 业务逻辑，使用 `DmConversationRepository` 和 `DmMessageRepository`

**设计特点：**
- 客服对话方固定为 `CS_ADMIN` 用户
- 复用 `dm_conversations` / `dm_messages` 表

## 五、代码规范和最佳实践

### 5.1 编码规范

#### 5.1.1 后端规范

- **分包策略：** 按业务领域分包（非按技术层分包），每个模块自包含 controller/service/repository/entity/dto
- **命名规范：**
  - Entity: `XxxEntity` (如 `ChatSessionEntity`)
  - DTO: `XxxRequest` / `XxxResponse` (如 `CreateSessionRequest`, `ChatMessageResponse`)
  - Repository: `XxxRepository` (继承 `JpaRepository<XxxEntity, String>`)
  - Service: `XxxService` (标注 `@Service`)
  - Controller: `XxxController` (标注 `@RestController`)
- **主键策略：** 所有表使用 UUID `VARCHAR(36)` 作为主键（`coupons` 和 `user_coupons` 除外，使用自增 BIGINT）
- **逻辑删除：** 使用 `deleted_at TIMESTAMP NULL` 字段，配合 `@SQLDelete` + `@Where` 注解
- **金额字段：** 统一使用 `DECIMAL(10,2)` 类型
- **时间字段：** 统一使用 `TIMESTAMP` 类型

#### 5.1.2 Android端规范

- **架构模式：** MVVM + Clean Architecture 简化版
  - UI层：`XxxScreen.kt` (Composable) + `XxxViewModel.kt`
  - 数据层：`XxxRepository` (实现) + `XxxRepository` (接口)
  - DI层：`AppModule.kt` (Hilt Module)
- **命名规范：**
  - Screen: `XxxScreen` (如 `AiAgentScreen`)
  - ViewModel: `XxxViewModel` (如 `AiAgentViewModel`)
  - Repository接口: `XxxRepository` (如 `UserRepository`)
  - Repository实现: `XxxRepositoryImpl` (如 `UserRepositoryImpl`)
  - DTO: `XxxDto` (如 `ChatMessageDto`)
- **状态管理：** 使用 `MutableStateFlow` + `StateFlow` 管理UI状态
- **协程作用域：** ViewModel中使用 `viewModelScope.launch`
- **字符串国际化：** 所有UI文本使用 `stringResource()` 引用（支持中英文双语）

#### 5.1.3 Flyway迁移脚本规范

- 使用 `CREATE TABLE IF NOT EXISTS`
- `ALTER TABLE ADD COLUMN` 前检查列是否存在
- 确保脚本可重复执行（幂等性）

### 5.2 组件复用策略

#### 5.2.1 共享UI组件

### 5.3 错误处理机制

#### 5.3.1 后端全局异常处理

**文件位置：** `joysong-server/src/main/kotlin/com/joysong/server/common/GlobalExceptionHandler.kt`

```kotlin
@RestControllerAdvice
class GlobalExceptionHandler {
    // IllegalArgumentException → 400 (参数错误)
    // RuntimeException → 500 (服务器错误)
    // ClientAbortException → warn日志（客户端中断）
    // IOException (Broken pipe) → warn日志（网络中断）
    // Exception → 500 (兜底处理，图片请求特殊处理)
}
```

#### 5.3.2 AI服务错误策略

`ChatService.callLLM()` 使用稳定错误契约：

| 场景 | 处理方式 |
|------|---------|
| API Key未配置 | 启动校验失败或返回 `AI_PROVIDER_UNAVAILABLE` |
| 网络不可达/超时 | 返回稳定的 `AI_PROVIDER_TIMEOUT` 或 `AI_PROVIDER_UNAVAILABLE` |
| API认证失败/限流 | 返回 `AI_PROVIDER_UNAVAILABLE`，日志保持脱敏 |
| 查询上下文失败 | 静默降级，不注入上下文信息 |

#### 5.3.3 前端错误处理

- `ApiException` 封装后端返回的错误码和消息
- Repository层统一返回 `Result<T>` (success/failure)
- ViewModel层通过 `errorMessage` 状态传递错误
- UI层通过 `Snackbar` 展示错误提示
- 403 错误特殊处理：清除当前会话，返回空列表

### 6.6 重要提醒

1. **文档同步：** 修改接口或数据库后，必须同步更新 `doc/用户端API文档.md` 和 `doc/数据库文档.md`
2. **Flyway幂等性：** 新的迁移脚本必须支持重复执行（使用 `IF NOT EXISTS` 等检查）
3. **双语支持：** Android端所有UI文本必须使用 `stringResource()` 引用
4. **不要手动编译：** 用户会在IDE中手动编译，无需执行编译命令
5. **逻辑删除：** 新增业务表优先考虑 `deleted_at` 逻辑删除方案
6. **UUID主键：** 新表主键统一使用 `UUID VARCHAR(36)`
