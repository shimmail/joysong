# 系统安全加固开发文档

## 1. 概述

### 背景

随着 Google 登录功能的上线，项目对认证链路进行了全面安全审计。审计发现当前实现在 **安全性、合规性、业务连续性、用户体验** 四个维度存在多项高风险问题，需要集中修复以消除潜在攻击面和运维隐患。

### 目标

本轮 P0 安全修复覆盖以下四个维度：

| 维度 | 风险描述 | 修复措施 |
|------|---------|---------|
| 安全性 | Google Token 远程验证依赖外部网络、JWT Secret 硬编码 | 本地 JWT 签名验证、移除敏感默认值 |
| 合规性 | 缺少 `email_verified` 校验、敏感数据明文存储 | 补全校验逻辑、迁移到加密存储 |
| 业务连续性 | 验证服务单点故障、配置缺失导致启动失败 | 异常降级处理、启动时配置校验 |
| 用户体验 | 认证失败无明确提示、数据迁移无感知 | 完善错误信息、透明迁移 |

## 2. Fix 1：后端 Google Token 验证迁移

### 2.1 背景

原实现通过 `RestTemplate` 调用 Google `tokeninfo` 远程端点（`https://oauth2.googleapis.com/tokeninfo?id_token=...`）验证 ID Token，存在以下问题：

- **外部依赖**：每次登录都需要请求 Google 服务器，网络不稳定时直接影响用户登录
- **延迟高**：国内服务器访问 Google API 延迟显著（通常 500ms+）
- **无 issuer 验证**：`tokeninfo` 端点不校验 `iss` 字段，存在 Token 伪造风险
- **无本地签名验证**：无法离线验证 JWT 签名的合法性

### 2.2 方案

迁移到 `GoogleIdTokenVerifier` 本地 JWT 签名验证。该库会从 Google 公钥端点下载并缓存公钥，在本地完成 JWT 签名验证，无需每次请求都访问远程端点。

验证内容包括：
- **签名验证**：使用 Google 公钥验证 JWT 签名的完整性
- **audience 校验**：验证 Token 的目标受众是否为本应用的 `client-id`
- **issuer 校验**：验证 Token 签发者是否为 `https://accounts.google.com`
- **exp 校验**：验证 Token 是否已过期
- **email_verified 校验**：确保 Google 账号邮箱已验证

### 2.3 修改文件

#### `joysong-server/build.gradle.kts`

添加 Google API Client 依赖：

```kotlin

implementation("com.google.api-client:google-api-client:2.7.0")
```

#### `AuthenticationService.kt`

路径：`joysong-server/src/main/kotlin/com/joysong/server/auth/service/AuthenticationService.kt`

**主要变更：**

1. **移除 RestTemplate**，新增 `GoogleIdTokenVerifier`（使用 `by lazy` 延迟初始化）：

```kotlin
private val verifier: GoogleIdTokenVerifier by lazy {
    val transport = if (googleProxyUrl.isNotBlank()) {
        val proxyUri = java.net.URI(googleProxyUrl)
        val proxy = java.net.Proxy(
            java.net.Proxy.Type.HTTP,
            java.net.InetSocketAddress(proxyUri.host, proxyUri.port)
        )
        NetHttpTransport.Builder()
            .setProxy(proxy)
            .build()
    } else {
        NetHttpTransport()
    }
    GoogleIdTokenVerifier.Builder(transport, GsonFactory.getDefaultInstance())
        .setAudience(listOf(googleClientId))
        .build()
}
```

2. **`loginWithGoogle()` 改为本地验证**，并添加完整的异常捕获：

```kotlin
fun loginWithGoogle(idToken: String): LoginResponse {
    val googleIdToken: GoogleIdToken = try {
        verifier.verify(idToken)
            ?: throw IllegalArgumentException("Invalid Google ID Token")
    } catch (e: java.security.GeneralSecurityException) {
        logger.warn("Google ID Token verification failed: {}", e.message)
        throw IllegalArgumentException("Invalid Google ID Token")
    } catch (e: java.io.IOException) {
        logger.error("Failed to verify Google ID Token (network/key error): {}", e.message)
        throw IllegalStateException("Google 认证服务暂时不可用，请稍后重试")
    }

    val payload = googleIdToken.payload
    val emailVerified = payload["email_verified"] as? Boolean ?: false
    if (!emailVerified) {
        throw IllegalArgumentException("Google 邮箱未验证，无法登录")
    }
    // ... 后续用户查找/创建逻辑
}
```

3. **新增 `email_verified` 校验**：防止未验证邮箱的 Google 账号登录

4. **`@Value` 添加空默认值**避免启动崩溃：

```kotlin
@Value("\${google.client-id:}") private val googleClientId: String,
@Value("\${google.proxy-url:}") private val googleProxyUrl: String
```

#### `RestTemplateConfig.kt`

路径：`joysong-server/src/main/kotlin/com/joysong/server/config/RestTemplateConfig.kt`

移除默认 `restTemplate` Bean（该 Bean 仅被 `AuthenticationService` 使用，迁移后不再需要），保留 `llmRestTemplate`：


## 3. Fix 2：移除敏感配置硬编码默认值

### 3.1 背景

`application.yml` 中多项敏感凭证以默认值形式硬编码，例如：

```yaml
# 修复前（不安全）
jwt:
  secret: ${JWT_SECRET:dev-secret-key-...}  # 硬编码默认值
google:
  client-id: ${GOOGLE_CLIENT_ID:1074438635273-...}  # 硬编码真实 client-id
```

风险：
- 敏感凭证（JWT Secret、阿里云 AccessKey）随代码泄露到 Git 仓库
- 生产环境可能忘记设置环境变量而使用了开发默认值
- 阿里云 AccessKey 已暴露在代码历史中

### 3.2 方案

1. **移除所有敏感默认值** — `application.yml` 中敏感配置仅保留环境变量引用，不设默认值
2. **创建 `ConfigValidator` 启动校验** — 应用启动时检查所有必需配置是否存在，缺失则拒绝启动
3. **提供 `application-dev.yml` 开发环境配置** — 本地开发使用独立 profile，已加入 `.gitignore`

### 3.3 修改文件

#### `application.yml`

路径：`joysong-server/src/main/resources/application.yml`

移除 7 项敏感配置的默认值：

#### `ConfigValidator.kt`（新建）

路径：`joysong-server/src/main/kotlin/com/joysong/server/config/ConfigValidator.kt`

使用 `@Component` + `@PostConstruct` 在应用启动时校验 7 项关键配置：

```kotlin
@Component
class ConfigValidator(
    @Value("\${jwt.secret:}") private val jwtSecret: String,
    @Value("\${google.client-id:}") private val googleClientId: String,
    @Value("\${oss.access-key-id:}") private val ossAccessKeyId: String,
    @Value("\${oss.access-key-secret:}") private val ossAccessKeySecret: String,
    @Value("\${aliyun.sms.access-key-id:}") private val smsAccessKeyId: String,
    @Value("\${aliyun.sms.access-key-secret:}") private val smsAccessKeySecret: String,
    @Value("\${spring.datasource.password:}") private val dbPassword: String,
) {
    @PostConstruct
    fun validate() {
        val missing = mutableListOf<String>()
        if (jwtSecret.isBlank()) missing.add("JWT_SECRET")
        if (googleClientId.isBlank()) missing.add("GOOGLE_CLIENT_ID")
        if (ossAccessKeyId.isBlank()) missing.add("OSS_ACCESS_KEY_ID")
        if (ossAccessKeySecret.isBlank()) missing.add("OSS_ACCESS_KEY_SECRET")
        if (smsAccessKeyId.isBlank()) missing.add("SMS_ACCESS_KEY_ID")
        if (smsAccessKeySecret.isBlank()) missing.add("SMS_ACCESS_KEY_SECRET")
        if (dbPassword.isBlank()) missing.add("DB_PASSWORD")

        if (missing.isNotEmpty()) {
            val message = "Missing required environment variables: ${missing.joinToString(", ")}. " +
                "Please set them via environment variables or application-dev.yml profile."
            logger.error(message)
            throw IllegalStateException(message)
        }
        logger.info("All required configuration values are present.")
    }
}
```

## 4. Fix 3：Android 端敏感数据迁移到加密存储

### 4.1 背景

`TokenManager` 使用 `DataStore`（底层为 XML 文件）明文存储以下敏感数据：

| 数据 | Key | 风险等级 |
|------|-----|---------|
| JWT Token | `jwt_token` | 高 — 可冒充用户身份 |
| 记住的密码 | `remember_password` | 高 — 明文密码 |
| 账号列表 | `saved_accounts` | 中 — 包含 Token |

DataStore 文件存储在应用私有目录（`/data/data/com.joysong.app/shared_prefs/`），Root 设备或备份提取场景下可被直接读取。

### 4.2 方案

采用 **双存储策略**：

- **敏感数据**（JWT Token、密码、账号列表）→ 迁移到 `EncryptedSharedPreferences`（AES-256-GCM 加密）
- **非敏感数据**（用户 ID、记住手机号、折叠评论等）→ 保留 `DataStore`

加密方案：
- **MasterKey**：`AES256_GCM` 密钥方案，由 Android Keystore 保护
- **Key 加密**：`AES256_SIV`（确定性加密，支持 Key 查找）
- **Value 加密**：`AES256_GCM`（认证加密，防篡改）

### 4.3 修改文件

#### `libs.versions.toml`

路径：`joysong-app/gradle/libs.versions.toml`

```toml
[versions]
securityCrypto = "1.1.0-alpha06"

[libraries]
security-crypto = { group = "androidx.security", name = "security-crypto", version.ref = "securityCrypto" }
```

#### `app/build.gradle.kts`

路径：`joysong-app/app/build.gradle.kts`

```kotlin
dependencies {
    implementation(libs.security.crypto)
}
```

#### `TokenManager.kt`

路径：`joysong-app/app/src/main/java/com/joysong/app/data/local/TokenManager.kt`

**主要变更：**

1. **`EncryptedSharedPreferences` 初始化**（MasterKey + AES256_GCM）：

```kotlin
private var isEncryptedFallback = false

private val encryptedPrefs: SharedPreferences by lazy {
    try {
        val masterKey = MasterKey.Builder(context)
            .setKeyScheme(MasterKey.KeyScheme.AES256_GCM)
            .build()
        isEncryptedFallback = false
        EncryptedSharedPreferences.create(
            context,
            "joysong_secure_prefs",
            masterKey,
            EncryptedSharedPreferences.PrefKeyEncryptionScheme.AES256_SIV,
            EncryptedSharedPreferences.PrefValueEncryptionScheme.AES256_GCM
        )
    } catch (e: Exception) {
        Log.e("TokenManager", "Failed to init EncryptedSharedPreferences", e)
        isEncryptedFallback = true
        context.getSharedPreferences("joysong_secure_prefs_fallback", Context.MODE_PRIVATE)
    }
}
```

2. **敏感数据迁移到加密存储**：

   - `jwt_token` → `encryptedPrefs`
   - `remember_password` → `encryptedPrefs`
   - `saved_accounts` → `encryptedPrefs`

3. **`tokenFlow` / `savedAccountsFlow` 改为 `MutableStateFlow` 包装**：

```kotlin
private val _tokenFlow = MutableStateFlow<String?>(null)
private val _savedAccountsFlow = MutableStateFlow<List<SavedAccount>>(emptyList())

val tokenFlow: Flow<String?> = _tokenFlow
val savedAccountsFlow: Flow<List<SavedAccount>> = _savedAccountsFlow
```

4. **一次性异步迁移逻辑**（`CoroutineScope(Dispatchers.IO).launch`，不阻塞构造）：

```kotlin
init {
    _tokenFlow.value = encryptedPrefs.getString("jwt_token", null)
    // ... 初始化 Flow 值

    migrationJob = CoroutineScope(Dispatchers.IO).launch {
        migrateSensitiveData()
        // 迁移完成后重新读取
        _tokenFlow.value = encryptedPrefs.getString("jwt_token", null)
        // ...
    }
}
```

5. **降级处理**：
   - 加密初始化失败 → 回退到普通 `SharedPreferences`（安全性降低但不崩溃）
   - 降级场景（`isEncryptedFallback = true`）→ 不标记 `migration_complete`，不清理 DataStore 旧数据，确保下次启动可重试迁移

6. **所有公开 API 签名保持不变** — 对调用方完全透明，无需修改上层代码

## 5. 风险审计发现与修复

在代码审查过程中发现并修复了以下问题：

| # | 问题 | 影响 | 修复方式 |
|---|------|------|---------|
| 1 | `verifier.verify()` 抛出 `GeneralSecurityException` / `IOException` 等 checked exception 未捕获 | 编译失败 / 运行时崩溃 | 添加 `try-catch` 分别捕获，`GeneralSecurityException` 返回 401，`IOException` 返回 503 |
| 2 | 缺少 `email_verified` 校验 | 未验证邮箱的 Google 账号可登录 | 添加 `payload["email_verified"]` 校验逻辑 |
| 3 | `ConfigValidator` 遗漏 `DB_PASSWORD` 校验 | 数据库密码为空时不报错 | 补充 `@Value("\${spring.datasource.password:}")` 和 `DB_PASSWORD` 检查 |
| 4 | `application-dev.yml` 缺少 `proxy-url` | 本地开发 Google 验证失败 | 补充 `google.proxy-url: "http://127.0.0.1:7890"` |
| 5 | `TokenManager` `init` 中 `runBlocking` 阻塞主线程 | App 启动 ANR | 改为 `CoroutineScope(Dispatchers.IO).launch` 异步执行 |
| 6 | 降级场景不应标记迁移完成 | 下次启动不再尝试迁移 | 添加 `isEncryptedFallback` 判断，仅在真正加密时才标记 `migration_complete` |
| 7 | `verifier` 立即初始化改为 `lazy` | 构造时即触发网络请求（下载 Google 公钥） | 改为 `by lazy` 延迟到首次使用时初始化 |

## 6. 部署注意事项

### 后端部署

1. **启动配置**：后端启动前必须设置环境变量或激活 `dev` profile：

   ```bash
   # 方式一：环境变量
   export JWT_SECRET="your-production-secret"
   export DB_PASSWORD="your-db-password"
   export GOOGLE_CLIENT_ID="your-google-client-id"
   # ... 其他配置项
   java -jar joysong-server.jar

   # 方式二：开发环境 profile
   SPRING_PROFILES_ACTIVE=dev java -jar joysong-server.jar
   ```

2. **代理配置**：国内服务器需要配置代理才能验证 Google Token：

   ```bash
   export GOOGLE_PROXY_URL="http://your-proxy:port"
   ```

   或在 `application-dev.yml` / 自定义 profile 中配置 `google.proxy-url`。

3. **阿里云 AccessKey 轮换**：已暴露在代码历史中的阿里云 AccessKey 建议在阿里云控制台进行轮换（禁用旧 Key → 创建新 Key → 更新环境变量）。

### Android 端部署

4. **数据迁移**：用户升级 App 后自动执行数据迁移（DataStore → EncryptedSharedPreferences），迁移过程对用户透明。若迁移失败，用户需重新登录，不会造成数据损坏。
