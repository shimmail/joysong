# 账号切换功能开发文档

> **模块路径：** `joysong-app/app/src/main/java/com/joysong/app/`
> **后端认证模块：** `joysong-server/src/main/kotlin/com/joysong/server/auth/`

---

## 一、功能概述

### 背景：从「退出其他设备」到「切换其他账号」

原「账号与安全」页面中有一个「退出其他设备」按钮，但该功能前后端均未实现（仅 UI 占位）。现已将其替换为「切换其他账号」功能，支持用户在本台设备上快速切换已登录过的账号。

| 对比 | 退出其他设备（旧） | 切换其他账号（新） |
|------|--------------|----------------|
| 状态 | 仅 UI 占位，未实现 | 已完整实现 |
| 功能 | 踢出其他设备的登录会话 | 在本设备上快速切换账号 |
| 交互 | 无 | 底部弹窗显示账号列表 |
| 实现复杂度 | 需服务端 token 黑名单机制 | 纯客户端本地实现 |

### 什么是账号切换

当用户在本台手机上登录过多个账号时，系统会自动记住这些账号。之后用户可以**一键切换**到任意已登录过的账号，不需要重新输入手机号、密码或验证码。

例如：用户同时拥有个人账号和工作账号，以前每次切换都要先退出再重新登录，现在只需在「账号与安全」中点一下目标账号即可完成切换。

### 登录记录检查机制

切换功能依赖**登录历史记录**：
- 只有在**本台手机**上成功登录过的账号才会出现在切换列表中
- 系统会在每次登录成功后自动保存账号信息（昵称、头像、token）
- 未在本设备登录过的账号**不会**出现在列表中，无法快速切换
- 如需使用新账号，点击「添加新账号」走正常登录流程即可

### 功能要点

| 要点 | 说明 |
|------|------|
| **多账号支持** | 最多保存 **5 个**账号，不限于 2 个，可在所有已保存账号之间自由来回切换 |
| **自动记忆** | 每次登录成功（密码或验证码登录）后自动将账号加入列表 |
| **一键切换** | 点击目标账号即可完成切换，无需重新输入任何凭证 |
| **安全回滚** | 目标账号 token 失效时自动回滚到当前账号，不会丢失登录状态 |
| **管理账号** | 支持移除不再需要的账号，也可通过「添加新账号」登录新账号 |

### 操作入口

```
我的 → 设置 → 账号与安全 → 切换其他账号
    → 底部弹窗显示已保存的账号列表（不含当前账号）
    → 点击目标账号 → 一键切换
    → 或点击「添加新账号」登录新账号
```

## 二、使用场景

### 场景一：登录并自动保存账号

**背景：** 用户首次使用或登录一个新账号。

**用户操作：** 在登录页选择以下任一方式完成登录：

##### 方式一：密码登录

1. 用户输入**手机号 + 密码**，点击登录
2. 客户端 POST `/api/auth/login`，请求体：`LoginRequest(phone, password)`
3. 服务端校验手机号是否已注册 → 校验密码是否匹配 → 生成 JWT token
4. 返回 `LoginResponse { token, user }`

##### 方式二：验证码登录

1. 用户输入**手机号**，点击「获取验证码」→ 服务端发送短信验证码
2. 用户输入**验证码**，点击登录
3. 客户端 POST `/api/auth/login-with-code`，请求体：`LoginWithCodeRequest(phone, code)`
4. 服务端校验验证码 → 查找用户（已注销则重新激活）→ **手机号未注册则自动创建新用户**（密码为空，后续可通过「忘记密码」设置）→ 生成 JWT token
5. 返回 `LoginResponse { token, user }`

##### 方式三：Google 登录

1. 用户点击「Google 登录」按钮 → 系统弹出 Google 账号选择器
2. 用户选择 Google 账号 → 客户端获得 Google `idToken`
3. 客户端 POST `/api/auth/login-with-google`，请求体：`GoogleLoginRequest(idToken)`
4. 服务端通过 Google tokeninfo 端点验证 `idToken` → 校验 `audience` 是否匹配 → 通过 `email` 查找用户（已注销则重新激活，未注册则自动创建）→ 生成 JWT token
5. 返回 `LoginResponse { token, user }`

> Google 用户没有手机号，`phone` 字段使用 `"google_${user.id}"` 作为唯一标识，避免多个 Google 账号互相覆盖。

##### 登录成功后统一处理

三种登录方式均返回相同结构的 `LoginResponse { token, user }`，后续处理一致：

1. `AuthRepositoryImpl` 将 `token` 保存到 `jwt_token`，将 `user.id` 保存到 `user_id`
2. `AuthViewModel` 收到 `AuthUiState.Success(user)`
3. `AuthViewModel` 构建 `SavedAccount(phone, nickname, avatar, token)` 并调用 `tokenManager.addSavedAccount()`
4. `addSavedAccount()` 内部逻辑：
   - 手机号已存在 → 更新 token、昵称、头像
   - 手机号不存在 → 插入列表头部
   - 列表超过 5 个 → 删除末尾
   - 序列化为 JSON 数组写入 DataStore

### 场景二：在已保存账号之间切换

**背景：** 用户已保存了多个账号，当前登录的是 A，想切换到 B。

**用户操作：** 进入「账号与安全」→ 点击「切换其他账号」→ 底部弹窗出现 → 点击账号 B。

**系统行为（对应 `AuthViewModel.switchAccount()`）：**

1. `_switchState = Loading` → 弹窗显示「正在切换...」加载动画
2. 备份当前 `previousToken` 和 `previousUserId`
3. `tokenManager.saveToken(account.token)` → **直接替换**当前 token，不经过 `clear()`
4. `authRepository.getUserProfile()` → 用新 token 请求服务端验证
5. **成功**：
   - `tokenManager.saveUserId(user.id)` → 同步更新 userId
   - `tokenManager.addSavedAccount(...)` → 更新 B 的最新昵称/头像/token
   - `_switchState = Success(user)`
   - 导航层收到 Success → `profileViewModel.loadUser()` → `popBackStack()` 返回 → `resetStates()`
6. **失败**：
   - `previousToken != null` → `tokenManager.saveToken(previousToken)` + `saveUserId(previousUserId)` 回滚
   - `previousToken == null` → `tokenManager.clear()` 清除所有数据
   - `_switchState = Error(message)`
   - 导航层收到 Error → `resetStates()`

**要点：**
- 弹窗中**不显示当前登录的账号**（`savedAccounts.filter { it.phone != currentPhone }`）
- 直接替换 token 而非先 `clear()` 再 `saveToken()`，避免 `authState` 出现 Unauthenticated 中间态导致导航跳转
- 切换成功后通过 `profileViewModel.loadUser()` 刷新用户数据

---

### 场景三：添加新账号

**背景：** 用户想登录一个之前未在本设备登录过的账号。

**用户操作：** 底部弹窗中点击「添加新账号」→ 进入登录页 → 登录新账号。

**系统行为：**

1. 关闭弹窗（`showSwitchDialog = false`）
2. 调用 `onAddNewAccount()` → 导航层执行 `authViewModel.logout()`
3. `logout()` → `authRepository.logout()` → `tokenManager.clear()`
4. `clear()` 内部：先读取 `saved_accounts`，清空所有 key，再恢复 `saved_accounts`
5. `authState` 变为 `Unauthenticated` → 导航跳转到登录页
6. 用户登录新账号 → 新账号自动保存到列表（同场景一）

**完整链路示例（A → 添加 B → 切回 A）：**

```
1. 当前登录 A → 打开切换弹窗 → 点击「添加新账号」
2. 系统退出 A（保留已保存列表）→ 跳转登录页
3. 用户登录 B → B 自动保存到列表
4. 进入主界面（当前为 B）
5. 再次打开切换弹窗 → 列表中出现 A 和 B
6. 点击 A → 一键切回
```

---

### 场景四：删除已保存账号

**用户操作：** 底部弹窗中点击目标账号右侧 `×` 按钮 → 弹出确认对话框 → 确认。

**系统行为：**

- `AuthViewModel.removeSavedAccount(phone)` → `TokenManager.removeSavedAccount(phone)`
- 内部：`getSavedAccounts().filter { it.phone != phone }` → 重新保存
- 删除仅移除本地记录，不影响服务端账号，不影响当前登录状态

---

### 场景五：Token 过期处理

**系统行为：** `getUserProfile()` 返回 401 → 进入失败分支 → 自动回滚到 `previousToken` → 停留当前页。

**用户恢复方式：** 通过「添加新账号」重新登录该账号，系统会用新 token 更新列表中的记录。

## 三、使用限制

| 限制 | 说明 |
|------|------|
| 必须有登录记录 | 只有在本设备登录过的账号才会出现在切换列表中 |
| 最多 5 个账号 | 超过 5 个时，最早的账号会被自动移除 |
| Token 有效性 | 切换依赖已保存的 token 仍然有效，过期需重新登录 |
| 登录方式无关 | 切换时直接用 token 认证，与原始登录方式无关 |

- 点击卡片 → `onSwitch` → 触发 `onSwitchAccount(account)`
- 点击 `×` → `AlertDialog` 确认删除，文案使用 `maskPhone(account.phone)` 脱敏

### maskPhone 脱敏规则

```kotlin
private fun maskPhone(phone: String): String {
    if (phone.startsWith("google_")) return "Google"
    return if (phone.length >= 7) {
        phone.substring(0, 3) + "****" + phone.substring(phone.length - 4)
    } else phone
}
```

| 类型 | 规则 | 示例 |
|------|------|------|
| Google 登录 | 显示 `Google` | `google_abc123` → `Google` |
| 普通手机号 ≥7 位 | 前3 + `****` + 后4 | `13812345678` → `138****5678` |
| 其他 <7 位 | 原文 | `12345` → `12345` |

### 6.2 SavedAccount 数据类

定义在 `TokenManager.kt` 文件顶部（class 外部）：

```kotlin
data class SavedAccount(
    val phone: String,         // 唯一标识。普通用户为手机号，Google 用户为 google_${userId}
    val nickname: String = "", // 昵称，UI 为空时回退显示 phone
    val avatar: String = "",   // 头像 URL，AsyncImage 加载
    val token: String          // JWT token 快照，切换时替换 jwt_token
) {
    fun toJson(): JSONObject        // → { phone, nickname, avatar, token }
    companion object {
        fun fromJson(json: JSONObject): SavedAccount  // optString 兼容旧版本
    }
}
```

### 6.3 AuthViewModel 关键方法

```kotlin
// 状态流
val authState: StateFlow<AuthState>          // 冷启动认证状态（Loading/Authenticated/Unauthenticated）
val switchState: StateFlow<AuthUiState>      // 切换状态（Idle/Loading/Success/Error）
val savedAccounts: StateFlow<List<SavedAccount>>  // 从 tokenManager.savedAccountsFlow 收集

// 登录（三种方式，模式一致）
fun login(phone, password)        // → authRepository.login() → addSavedAccount()
fun loginWithCode(phone, code)    // → authRepository.loginWithCode() → addSavedAccount()
fun loginWithGoogle(idToken)      // → authRepository.loginWithGoogle() → addSavedAccount()

// 切换
fun switchAccount(account: SavedAccount)
// 1. 备份 previousToken + previousUserId
// 2. saveToken(account.token) 直接替换
// 3. getUserProfile() 验证
// 4. 成功: saveUserId + addSavedAccount(更新快照)
// 5. 失败: saveToken(previousToken) 回滚

// 删除
fun removeSavedAccount(phone: String)  // → tokenManager.removeSavedAccount(phone)

// 状态重置
fun resetStates()  // 重置 loginState/registerState/resetPasswordState/codeState/switchState 为 Idle
```

### 6.4 TokenManager 存储键

| Key | 类型 | 说明 |
|-----|------|------|
| `jwt_token` | `stringPreferencesKey` | 当前用户的 JWT token |
| `user_id` | `stringPreferencesKey` | 当前用户 ID |
| `saved_accounts` | `stringPreferencesKey` | JSON 数组，已保存账号快照 |
| `remember_phone` | `stringPreferencesKey` | 记住密码的手机号 |
| `remember_password` | `stringPreferencesKey` | 记住密码的密码 |
| `collapsed_comments` | `stringSetPreferencesKey` | 折叠的评论 ID 集合 |

**`clear()` 方法特殊行为：** 清空所有 key 前，先读取 `saved_accounts`，清空后恢复。确保退出登录不清除账号列表。

### 6.6 导航层 AccountSecurity composable 块

```kotlin
composable(Routes.AccountSecurity.route) {
    val authViewModel: AuthViewModel = hiltViewModel()
    val savedAccounts by authViewModel.savedAccounts.collectAsState()
    val switchState by authViewModel.switchState.collectAsState()
    val profileViewModel: ProfileViewModel = hiltViewModel()
    val currentUser by profileViewModel.user.collectAsState()

    LaunchedEffect(switchState) {
        when (switchState) {
            is AuthUiState.Success -> {
                profileViewModel.loadUser()     // 刷新用户数据
                innerNavController.popBackStack() // 返回上一页
                authViewModel.resetStates()
            }
            is AuthUiState.Error -> {
                authViewModel.resetStates()     // 仅重置状态，停留当前页
            }
            else -> {}
        }
    }

    AccountSecurityScreen(
        savedAccounts = savedAccounts,
        currentPhone = currentUser?.phone ?: "",
        onSwitchAccount = { authViewModel.switchAccount(it) },
        onRemoveAccount = { authViewModel.removeSavedAccount(it) },
        onAddNewAccount = { onLogout() },   // 触发 authState → Unauthenticated → 跳转登录
        isSwitching = switchState is AuthUiState.Loading,
        ...
    )
}
```

### 6.7 登录功能实现

三种登录方式共享相同的返回结构和后处理逻辑，区别仅在于请求参数和服务端校验方式。

#### 请求 DTO

```kotlin
data class LoginRequest(val phone: String, val password: String)       // 密码登录
data class LoginWithCodeRequest(val phone: String, val code: String)   // 验证码登录
data class GoogleLoginRequest(val idToken: String)                      // Google 登录
```

#### 响应 DTO（三种方式统一返回）

```kotlin
data class LoginResponse(
    val token: String,       // JWT token，直接保存到 jwt_token
    val user: UserDto        // 用户信息，用于 UI 展示和构建 SavedAccount
)

data class UserDto(
    val id: String,
    val phone: String?,      // Google 用户可能为 null
    val email: String?,
    val nickname: String,
    val avatar: String,
    val hasPassword: Boolean = true  // 验证码注册且未设置密码的用户为 false
)
```

#### 登录流程总览

```
用户操作 → AuthViewModel.login*()
         → AuthRepositoryImpl 调用 API
         → 收到 LoginResponse { token, user }
         → tokenManager.saveToken(token) + saveUserId(user.id)
         → AuthViewModel 构建 SavedAccount → addSavedAccount()
         → authState = Authenticated → 导航跳转主界面
```

| 步骤 | 说明 |
|------|------|
| 1. 发起请求 | `AuthViewModel` 调用 `authRepository.login()` / `loginWithCode()` / `loginWithGoogle()` |
| 2. 服务端处理 | 校验凭证 → 查找/创建用户 → `jwtTokenProvider.generateToken(userId, phone, role)` |
| 3. 保存凭证 | `tokenManager.saveToken(token)` + `saveUserId(user.id)` 写入 DataStore |
| 4. 保存账号 | `addSavedAccount(SavedAccount(phone, nickname, avatar, token))` 更新已保存列表 |
| 5. 状态更新 | `authState = Authenticated` → 导航层跳转到主界面 |

### 6.8 账号切换实现

账号切换的核心思路是**用已保存的 token 替换当前 token**，然后通过 `/api/user/profile` 验证有效性。

#### switchAccount 完整流程

```kotlin
fun switchAccount(account: SavedAccount) {
    viewModelScope.launch {
        _switchState.value = AuthUiState.Loading

        // ① 备份当前状态（用于失败回滚）
        val previousToken = tokenManager.getToken()
        val previousUserId = tokenManager.getUserId()

        // ② 直接替换 token（不经过 clear()，避免 authState 变为 Unauthenticated）
        tokenManager.saveToken(account.token)

        // ③ 用新 token 请求服务端验证
        authRepository.getUserProfile()
            .onSuccess { user ->
                // ④ 成功：同步 userId + 更新账号快照
                tokenManager.saveUserId(user.id)
                tokenManager.addSavedAccount(
                    SavedAccount(account.phone, user.nickname, user.avatar, account.token)
                )
                _switchState.value = AuthUiState.Success(user)
            }
            .onFailure { error ->
                // ⑤ 失败：回滚到之前的 token
                if (previousToken != null) {
                    tokenManager.saveToken(previousToken)
                    previousUserId?.let { tokenManager.saveUserId(it) }
                } else {
                    tokenManager.clear()
                }
                _switchState.value = AuthUiState.Error(error.message ?: "切换失败")
            }
    }
}
```

#### 导航层响应

```kotlin
LaunchedEffect(switchState) {
    when (switchState) {
        is AuthUiState.Success -> {
            profileViewModel.loadUser()      // 用新 token 刷新用户数据
            innerNavController.popBackStack() // 返回上一页
            authViewModel.resetStates()       // 重置 switchState 为 Idle
        }
        is AuthUiState.Error -> {
            authViewModel.resetStates()       // 仅重置状态，停留当前页
        }
        else -> {}
    }
}
```

| 阶段 | 成功路径 | 失败路径 |
|------|---------|--------|
| Loading | 弹窗显示加载动画 | — |
| Token 替换 | `saveToken(account.token)` | — |
| 服务端验证 | `/api/user/profile` 200 | 401 / 网络错误 |
| 善后 | `saveUserId` + `addSavedAccount` + `loadUser` + 返回 | `saveToken(previousToken)` 回滚 + 停留当前页 |

### 6.10 安全设计

- Token 存储在 Android DataStore（应用私有目录），非 root 设备受沙盒保护
- `switchAccount` 直接替换 token 避免中间态，失败自动回滚
- `clear()` 保留 `saved_accounts`，退出登录不丢失已保存账号
- UI 中手机号和 Google 标识均做脱敏显示

| 已知风险 | 说明 | 建议改进 |
|---------|------|---------|
| Token 明文存储 | root 或备份可读取 | 迁移到 EncryptedSharedPreferences |
| 多 token 泄露面 | 最多 5 个快照 | 服务端 refresh token 机制 |
| 无过期清理 | 过期 token 仍保留 | 定期检查并自动清理 |
| 无二次验证 | 切换无需验证 | 敏感操作要求二次验证 |
