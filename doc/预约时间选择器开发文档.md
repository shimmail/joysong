# 预约时间选择器开发文档

> 本文档记录「预约项目」流程中日期/时间选择功能的实现要点与踩坑过程，重点是一次 ANR（主线程死循环）的排查路径，避免重复踩坑。

## 1. 功能概览

预约时间采用**两段式选择**：先选日期（Material3 `DatePickerDialog`），确定后自动弹出自定义时间选择器（三列滚动）。

| 页面 | 文件 | 说明 |
| --- | --- | --- |
| 预约确认页 | `ui/booking/BookingConfirmScreen.kt` → `AppointmentTimeCard` | 日期 + `ScrollingTimePicker` 三列滚动选时 |
| 预约表单页 | `ui/detail/AppointmentScreen.kt` | 仅选日期，时间固定 `12:00`（与设计图一致） |
| 滚动选择器组件 | `ui/components/ScrollingTimePicker.kt` | 上午/下午 \| 小时(01-12) \| 分钟(00-59) |

设计参考：`UI/发现细分/3.1_机构主页_可预约项目_预约.png`、`UI/发现细分/3.1_预约_预约成功.png`

## 2. ScrollingTimePicker 实现要点

### 2.1 索引映射：首尾垫空白项

`LazyColumn` 无法让首/末项停在视口中央，因此列表结构为：

```
[centerOffset 个空白项] + [真实选项] + [centerOffset 个空白项]
```

`visibleItems = 5`、`centerOffset = 2`，于是 `data[i]` 位于 item 下标 `i + centerOffset`。当 `firstVisibleItemIndex == i` 时，视口第 3 行（高亮行）恰好是 `data[i]`，故：

- 初始定位：`rememberLazyListState(initialFirstVisibleItemIndex = selectedIndex)`
- 反向换算：`centeredIndex = nearest.index - centerOffset`

### 2.2 吸附交给官方 SnapFlingBehavior

```kotlin
val flingBehavior = rememberSnapFlingBehavior(lazyListState = listState)
```

**不要手写吸附动画**（原因见 3.1）。滚动停止后由 fling behavior 自动对齐到整项。

### 2.3 滚动即选中

用 `derivedStateOf` 取距视口中心最近的项，再同步给调用方，无需二次点击：

```kotlin
val centeredIndex by remember(data.size, centerOffset) {
    derivedStateOf {
        val info = listState.layoutInfo
        val visible = info.visibleItemsInfo
        if (visible.isEmpty()) return@derivedStateOf -1
        val viewportCenter = (info.viewportStartOffset + info.viewportEndOffset) / 2
        val nearest = visible.minByOrNull { abs(it.offset + it.size / 2 - viewportCenter) }
            ?: return@derivedStateOf -1
        (nearest.index - centerOffset).coerceIn(0, data.lastIndex)
    }
}
```

程序化滚动只在**点击选项**时触发，且必须加 `!listState.isScrollInProgress` 守卫，避免与用户手势抢滚动权。

### 2.4 三列统一交互

上午/下午列与时/分列使用同一个 `ScrollablePickerColumn`（数据为 `listOf("上午", "下午")`），不做成静态按钮，交互一致。

## 3. 踩坑记录

### 3.1 手写吸附导致 ANR（主线程死循环）⚠️ 最关键

**现象：** 快速滑动时间选择器时应用「崩溃」，但 `adb logcat -b crash` 里**没有任何相关 FATAL EXCEPTION**。

**排查：** 改查主缓冲区的 ANR 关键字，才拿到真实证据：

```
E ActivityManager: ANR in com.joysong.app (com.joysong.app/.MainActivity)
Reason: Input dispatching timed out ... Waited 5000ms for MotionEvent(action=DOWN)
Current message: duration=5907ms ... c=androidx.compose.ui.platform.AndroidUiDispatcher
```

主线程在一条 Compose 消息里卡了 5907ms，输入分发超时 5000ms → 系统弹「应用无响应」，观感等同崩溃。

**根因：** 旧实现用 `Column + verticalScroll` 自己写吸附，形成自我取消的死循环：

```
snapshotFlow { isScrollInProgress to scrollState.value }
      ↓ collectLatest 中启动 animateScrollBy 吸附
animateScrollBy 改变 value → snapshotFlow 再次发射
      ↓ collectLatest 取消刚启动的吸附动画
永远对不齐 → isScrollInProgress 转 false → 再次吸附 → 无限循环
```

**解决方案：** 放弃手写吸附，改用 `LazyColumn + rememberSnapFlingBehavior`，从机制上不存在"自己取消自己"的可能。

**教训：**
1. `snapshotFlow` 的表达式里**不要包含会被自身副作用修改的状态**（此处 `scrollState.value`），否则必然自激。
2. 用户报"崩溃"时不能只看 crash 缓冲区，ANR 不写入该缓冲区，需搜 `ANR in` / `Force finishing` / `not responding`。
3. 排查前先比对 **设备已安装 APK 时间 vs 源码修改时间**（`adb shell dumpsys package <pkg> | grep lastUpdateTime`），否则可能在分析一份根本没跑起来的修复。

### 3.2 Row 中的列不可见

**现象：** 三列只显示第一列（上午/下午），小时和分钟列完全看不到。

**根因：** 列用了 `widthIn(min = 44.dp)` 且内部 `fillMaxWidth()`。`Row` 中非 `weight` 子项按剩余空间依次测量，第一列直接膨胀占满整行宽度，后两列被放置到 `Row` 边界之外。

**解决方案：** 每列固定 `width(56.dp)`，`Row` 用 `horizontalArrangement = Arrangement.Center`。

### 3.3 滚动到位后仍需点击才生效

**根因：** 同步逻辑挂在 `LaunchedEffect(listState.isScrollInProgress)` 上。当手指恰好停在整项边界（吸附偏移量为 0）时不会触发吸附动画，`isScrollInProgress` 状态不再变化，同步逻辑永远不执行。

**解决方案：** 改为监听"居中项下标"这一派生状态（见 2.3），与是否发生滚动动画无关。

### 3.4 滚动时弹窗重组卡顿

**现象：** 滚动选择器时，整个时间弹窗子树持续重组。

**根因：** `onTimeChanged` 回调把实时值写入 Compose `mutableStateOf`，滚动过程每跨一项就触发一轮弹窗重组。

**解决方案：** 实时值写入**非状态容器** `IntArray`，只在点击「确定」时才写入真正的 state：

```kotlin
// 仅在点击"确定"时更新，兼作下次打开选择器的初始值
var confirmedHour by remember { mutableIntStateOf(9) }
var confirmedMinute by remember { mutableIntStateOf(0) }
// 滚动中的实时值：普通数组不参与重组
val livePick = remember { intArrayOf(9, 0) }
```

### 3.5 DatePicker 默认未选中日期

**现象：** 打开日历没有默认选中项，用户可以不选日期直接点「确定」，拼出的时间字符串缺日期部分（形如 `" 09:00"`）。`AppointmentScreen` 更严重——默认值是硬编码的 `"2025-07-06"`，早已过期。

**解决方案：** 默认选中今天，同时把 `selectedDate` 初值设为今天的日期文本作为兜底。

**时区陷阱：** Material3 `DatePickerState` 的毫秒值是 **UTC** 语义。直接传本地 `Calendar.getInstance().timeInMillis`，在东八区凌晨会被判成前一天。必须按本地年月日重新构造 UTC 零点：

```kotlin
val todayUtcMillis = remember {
    Calendar.getInstance(TimeZone.getTimeZone("UTC")).apply {
        clear()
        set(today.get(Calendar.YEAR), today.get(Calendar.MONTH), today.get(Calendar.DAY_OF_MONTH))
    }.timeInMillis
}
rememberDatePickerState(initialSelectedDateMillis = todayUtcMillis)
```

回读侧无需特殊处理：用本地 `Calendar` 接收 UTC 零点毫秒，东八区得到当天 08:00，取年月日仍是同一天。

## 4. 验证要点

- 三列均可见，初始值居中高亮
- 松手后自动吸附居中，居中项即选中（无需点击）
- 快速连续滑动不卡顿、不出现「应用无响应」
- 点击选项可跳转居中
- 打开日历默认选中今天，直接点「确定」能得到完整日期
- 关闭再打开时间选择器，保留上次「确定」的时间
