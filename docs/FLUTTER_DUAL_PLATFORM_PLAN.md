# 娇颜颂 Flutter Android / iOS 开发计划

> 基线日期：2026-08-05  
> 迁移目标：以 `joysong-flutter` 渐进替代现有 `joysong-app`，共用 `joysong-server` REST API，同时发布 Android 与 iOS。

## 1. 交付目标与边界

- 一套 Flutter 业务代码覆盖 Android 与 iOS，平台差异收敛在配置、权限、安全存储和少量原生适配中。
- 首期复刻现有 Android 用户主路径：登录 → 首页/发现 → 项目、机构、医生详情 → 预约下单 → 订单履约，并保留 AI 伙伴与个人中心入口。
- 服务端真实实现和 `docs/FLUTTER_API_CONTRACT.md` 是唯一接口基线；禁止使用仓库中的旧 OpenAPI 快照生成客户端。
- 管理后台继续使用 `joysong-admin`。Flutter 只调用服务端 API，不连接后台页面或数据库。
- 当前支付接口仅是流程占位。首期可完成支付页面和状态机对接，但生产支付必须等待预下单、渠道回调、验签、幂等和退款查询契约齐备。
- Android 继续支持 minSdk 26；iOS 首期建议支持 iOS 13 及以上。生产包沿用 `com.joysong.app` 前必须完成签名、商店迁移和覆盖安装验证，开发/测试包使用独立后缀。

## 2. 产品范围与优先级

### P0：可发布用户闭环

1. 应用启动、环境配置、网络状态、统一错误和空状态。
2. 手机号密码/验证码登录、注册、重置密码、令牌恢复/刷新、退出。
3. 首页、发现筛选和项目/机构/医生/文章/日记详情。
4. 预约确认、优惠券、订单创建、订单列表/详情、核销码和退款入口。
5. 个人资料、我的订单、我的日记、收藏、设置与账号安全。
6. Android/iOS 安全存储、权限声明、隐私文案、崩溃与关键行为日志接入点。

### P1：留存与互动

- 日记发布/编辑、评论、点赞、收藏、举报、评价。
- 通知、私信、客服，基于时间游标加载并按消息 ID 去重。
- AI 伙伴的普通会话和 SSE 流式消息；断流不自动重放 POST。
- Google 登录、头像/图片上传、国际化和基础无障碍完善。

### P2：专业能力

- 官方身份认证和私有材料上传。
- 医生/机构法人专业管理入口，进入时实时请求 `management/context`。
- 医生档案、机构项目、文章、协作申请、分账提案与专业订单处理。
- 平台角色和职业身份分离；客户端只按服务端能力布尔值展示入口，不在本地推导权限。

## 3. 技术架构

```text
lib/
  app/                 应用入口、路由、主题、环境配置
  core/
    network/           API envelope、鉴权、刷新、重试边界
    storage/           Keychain / Keystore 封装
    error/             失败模型与用户提示
    widgets/           跨业务通用组件
  features/
    auth/              登录、注册、账号恢复
    home/              首页聚合
    discover/          搜索、筛选、各类详情
    booking/           预约、优惠券、创建订单
    orders/            履约、核销、退款、评价
    social/            日记、评论、点赞、收藏、举报
    messaging/         通知、私信、客服
    agent/             AI Chat、SSE、Agent 计划
    profile/           资料、设置、账号安全
    identity/          职业身份认证
    management/        医生/机构专业管理
```

架构约束：

- UI、状态、仓储、远端数据源分层；业务模块不得直接发 HTTP 请求或读取平台安全存储。
- 环境地址通过 `--dart-define=API_BASE_URL=...` 注入，代码内部统一补 `/api`，图片使用服务端返回的完整 URL。Flutter 通过 `PublicMediaUrlResolver` 统一消费媒体地址；切换阿里云 OSS/CDN 时不得在客户端保存 OSS AccessKey，私有媒体仅通过服务端换取短期签名 URL。
- 所有 JSON 接口同时判断 HTTP 状态和 envelope `code`；业务错误优先展示 `message`。
- access token 和 refresh token 原子更新；并发 401 只允许一次 single-flight 刷新，原请求最多重放一次。
- 下单、支付、身份申请、项目申请、分账确认等写操作禁止网络层自动重试。
- 多图逗号字符串只在数据映射层转成 `List<String>`；金额使用十进制安全表示，不用浮点数参与支付计算。
- 列表首期统一采用 `offset/limit` 或服务端指定的时间游标，不在客户端伪造 `total`。

## 4. 双端适配清单

| 能力 | Android | iOS |
|---|---|---|
| 开发 API | 模拟器 `10.0.2.2` | 模拟器 `127.0.0.1` |
| 凭证存储 | Android Keystore | iOS Keychain |
| 本地 HTTP | 仅 debug 网络安全配置放行 | 仅 debug ATS 例外 |
| 图片/相机 | 运行时媒体/相机权限 | `Info.plist` 隐私用途说明 |
| 深链 | App Links 预留 | Universal Links 预留 |
| 推送 | FCM 预留 | APNs 证书与能力预留 |
| 发布验证 | AAB、签名、混淆、覆盖安装 | Archive、签名、隐私清单、TestFlight |

生产环境强制 HTTPS；日志、埋点和崩溃信息不得包含令牌、短信验证码、身份证号、认证材料或聊天敏感内容。

## 5. 分阶段计划

### Sprint 0：工程底座（当前执行）

- 创建 Android/iOS Flutter 工程、应用主题、四栏 App Shell、环境配置和基础测试。
- 建立统一响应、错误模型、网络客户端接口和鉴权存储边界。
- 补充项目运行说明和 CI 命令；通过格式化、静态分析和单元/组件测试。

验收：两端工程可生成；四个主入口可导航；dev/staging/prod 地址不写死；基础测试通过。

### Sprint 1：认证、首页与发现

- 接入登录、验证码、注册、重置密码、令牌恢复/刷新/退出。
- 接入首页五类聚合数据、发现筛选与分页。
- 完成项目、机构、医生、文章、日记基础详情。

验收：冷启动可恢复登录；并发 401 只刷新一次；游客/登录态路径清晰；列表具备加载、空、错误和重试状态。

### Sprint 2：预约与订单闭环

- 机构项目、可选医生、面诊费、预约时间、优惠券和订单创建。
- 订单状态机、核销码、尾款占位、确认完成、取消与退款。
- 所有提交按钮防重复，客户端价格只作展示。

验收：测试环境完成一条从发现到订单完成/退款的端到端路径；用户端不调用专业核销接口。

### Sprint 3：内容与社交

- 日记增删改、公共上传、评论/回复、点赞、收藏、举报和订单评价。
- 图片压缩、上传进度、失败恢复和内容安全提示。

验收：关键写操作有乐观更新回滚或明确结果；私有身份材料绝不进入公共上传接口。

### Sprint 4：AI 与消息

- AI 会话、历史记录、非流式与 SSE 流式响应。
- 通知、私信和客服会话；时间游标翻页和消息 ID 去重。
- Agent 评估/方案展示风险、限制、替代方案和待确认项。

验收：SSE 完成、错误、主动取消和断流均有确定 UI 状态；断流后不自动重发消息。

### Sprint 5：身份与专业管理

- 私有认证材料和身份申请。
- 专业登录、实时管理上下文、对象级受限的医生/机构/文章/项目/订单能力。
- 协作申请与分账提案双向确认。

验收：身份撤销后专业入口立即回退且普通用户数据保留；页面能力展示与服务端权限一致。

### Sprint 6：发布硬化

- 真机兼容、性能、无障碍、弱网、崩溃恢复和安全审计。
- Android AAB 与 iOS TestFlight 流程、隐私政策、权限说明、商店素材。
- 与原生 Android 对照回归，制定灰度、监控和回滚方案。

验收：P0 自动化回归通过；无高危安全问题；生产支付契约未完成时隐藏真实支付入口或保持受控测试开关。

## 6. 测试与质量门禁

- 每次提交：格式化、`flutter analyze`、单元测试、关键 Widget 测试。
- 每次合并：Android debug 构建；在 macOS CI 执行 iOS 无签名构建。
- 每个 Sprint：至少一条真实服务端集成测试，覆盖 envelope 非 200、HTTP 401/403、超时、断网和重复提交。
- 发布前：Android/iOS 真机冒烟、中文长文本/大字体、键盘遮挡、图片内存、冷启动、后台恢复和深色模式检查。
- 核心模块目标：状态/仓储/映射逻辑分支覆盖率不低于 80%；页面像素复刻不以覆盖率替代人工视觉验收。

## 7. 当前阻塞与决策点

1. 仓库旧 OpenAPI 不完整，暂不做自动生成；服务端提供自动生成且 CI 校验的新规范后再切换。
2. 第三方支付尚未形成生产契约，是正式上架的硬阻塞项，但不阻塞其余页面和订单状态机开发。
3. Windows 可开发/构建 Android，iOS 最终构建、签名和真机测试必须进入 macOS/Xcode 环境。
4. Google 登录的 Android SHA、iOS URL Scheme/Client ID 和商店配置需要在发布前由账号持有人提供。
5. 仓库当前存在大量其他模块的未提交修改；Flutter 迁移只新增/修改 `joysong-flutter` 与本计划，避免覆盖既有工作。

## 8. 完成定义

一个功能只有在以下条件全部满足时才算完成：

- Android 与 iOS 使用同一业务实现，平台差异已有明确封装。
- 成功、加载、空、失败、未登录、无权限和弱网状态均可操作。
- API 字段、权限、分页和重试行为符合迁移契约。
- 包含相应单元或 Widget 测试，并通过静态分析和目标平台构建。
- 不泄漏敏感数据，具备无障碍标签和必要的中文/英文文案入口。
- 已记录服务端依赖、监控点、灰度方式和可回滚版本。
