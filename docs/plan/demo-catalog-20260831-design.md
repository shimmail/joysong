# 可重放虚构演示数据设计规格

> 日期：2026-08-31
>
> 状态：设计已确认，待规格审阅
>
> 适用范围：`joysong-server`、演示数据脚本，以及现有 Flutter 中英文切换与 AI 翻译验收

## 1. 背景与目标

当前空库仅由 `AdminBootstrapInitializer` 初始化管理员。机构、医生、顾问、平台项目、机构项目等供给侧数据需要通过人工联调逐项创建，不适合主管快速查看，也不利于重复验证真实业务接口。

本设计提供双层能力：

1. **主管快照**：通过一个命令在隔离演示数据库中生成完整、稳定、可重复验证的虚构供给侧目录。
2. **真实接口重放**：从仅有管理员的隔离数据库开始，按现有 `SMOKE-00` 至 `SMOKE-08` 主链结构调用真实接口，记录动态 ID 和各步证据。本期完整执行 `SMOKE-00` 至 `SMOKE-05`；订单相关 `SMOKE-06` 至 `SMOKE-08` 明确标记为 `DEFERRED_ORDER_SCOPE`。

两条路径共用同一份中文数据目录，避免快照和接口脚本各维护一套数据。

完成后，可优先将应用部署到**独立远程演示环境**供主管查看；不得在生产环境或共享开发数据库启用演示数据功能。

- 新增可从 HTTP 触发的数据初始化或清理接口。

## 3. 核心设计决策

### 3.1 单一数据源

仓库中的 `docs/test/catalog-v1.json` 是两条执行路径唯一的业务数据源。不要复制到第二个目录，以免同一数据集出现双源。目录包含：

- `schemaVersion`：结构版本，首版为 `1`。
- `datasetVersion`：数据版本，当前为 `2026.09.02.1`。
- `namespace`：固定为 `demo-cn-v1`，用于日志、校验和清理边界。
- 每个对象的稳定逻辑编码，例如 `INST-SH-01`、`DOCTOR-BJ-03`、`PROJECT-SKIN-01`。
- 主管快照使用的固定 UUID。
- 中文展示字段、USD 价格、状态和对象关系。
- 不含密码、验证码、令牌、API Key 或其他秘密。

Kotlin 快照执行器使用目录中的固定 UUID。PowerShell 接口重放脚本只使用逻辑编码组织流程，忽略固定 UUID，并将接口返回的动态 ID 写入本次运行清单。

目录文件按原始 UTF-8 字节计算 SHA-256。每次 Apply、Verify 和 Replay 都输出 `datasetVersion` 与摘要，便于证明使用的是同一版数据。

### 3.2 两种执行路径

| 能力 | 主管快照 | 真实接口重放 |
| --- | --- | --- |
| 主要用途 | 快速得到最终可展示状态 | 证明注册、申请、审核和公开展示接口可重放 |
| 写入方式 | 后端事务内受控持久化 | 调用真实 HTTP 接口 |
| ID | JSON 中固定 UUID | 接口动态返回并写入运行清单 |
| 起点 | 仅有管理员的隔离数据库 | 仅有管理员的另一隔离数据库 |
| 失败恢复 | 整体事务回滚 | 从同一运行清单的最后成功步骤续跑 |
| 数据清理 | 仅清理 JSON 列出的固定演示 ID | 失败后优先换全新隔离数据库重新执行 |

不使用接口重放结果直接生成主管快照，也不从数据库反向导出目录，以免产生第三套事实来源。

### 3.3 不新增演示管理接口

快照执行器通过 Spring Boot 的命令行运行器触发，仅在明确的演示配置下装配。这样可以复用后端实体、密码编码器和事务能力，同时避免在已部署服务上暴露高风险的初始化或删除端点。

### 4.5 中文和 AI 翻译

目录内所有用户可见文本只保存中文，不使用“中文 / English”并列字段，也不增加 `name_en`、`description_en` 等列。

英文由现有 `POST /api/translations` 在运行时生成：

- 目标语言统一使用 Flutter 当前采用的 BCP 47 标签 `en-US`。
- 覆盖 `institution`、`doctor`、`project`、`project_html` 四类代表文本。
- 在全新后端进程中，同一请求第一次返回 `cached=false`，第二次返回 `cached=true`；已运行实例的首次验收调用允许直接命中缓存。
- 缓存只存在于 `TranslationService` 的内存 LRU 中；服务重启后自然失效。
- 译文不得写回机构、医生、项目或任何演示目录表。
- 翻译失败时继续展示中文，不产生空白页面，也不改变目录准备结果。

## 5. 主管快照设计

### 5.1 后端组件

在 `com.joysong.server.demo` 下维护三个高内聚组件：

- `DemoCatalogModels.kt`：严格映射 JSON；拒绝未知字段。
- `DemoCatalogService.kt`：读取、校验、应用和验证固定演示图谱。
- `DemoCatalogRunner.kt`：首阶段根据演示配置选择 `APPLY` 或 `VERIFY`，输出机器可识别的最终状态并结束进程。

配置集中放在 `application-demo.yml`。默认配置和生产配置不装配运行器，也不自动生成数据。

`application-demo.yml` 默认关闭短信外发、支付调度以及共享对象存储等非必要外部能力。身份占位材料使用隔离的本地演示存储；只有在显式提供 `TRANSLATION_*` 配置时，翻译阶段才允许访问外部 AI 服务。接口重放所需固定验证码使用第 6.2 节的无外发适配器。

根目录脚本 `scripts/demo-data.ps1` 提供统一入口：

```powershell
./scripts/demo-data.ps1 -Action Apply
./scripts/demo-data.ps1 -Action Verify
```

脚本负责检查环境变量、解析并打印数据库主机与数据库名、传入绝对目录路径、启动后端命令行任务，以及根据退出码报告结果。日志不得打印密码、验证码、令牌、完整翻译源文或翻译响应。本地与远程服务器使用同一入口；远程只需传入发布 JAR、当前目录文件和远程数据库环境变量。

### 5.1.1 2026-09-02 快速 Demo 实施状态

当前首阶段已按“尽快交付非交易 Demo”收口为：

- `Apply`：只允许在唯一管理员基线的独立数据库中，以单事务写入当前目录图谱；中途失败全部回滚。
- `Verify`：只读核对目录版本、原始字节 SHA-256、378 行受管记录、80 份隔离身份占位材料、账号密码和关键关系。
- 重复 `Apply`：完整一致时零写入；部分数据或字段漂移时直接失败。
- 数据库门禁：`demo` profile 在 Flyway 迁移前打印实际主机和数据库名，并要求库名以 `myapp_worktree_` 开头且与 `DEMO_DATABASE_NAME` 完全一致。
- 外发门禁：Demo 默认关闭 OSS、短信、支付、对账、账号删除和调度任务，禁止与 `prod` 或 `dev` profile 混用。
- 撤销：首阶段不提供对象级 `Reset`；本地销毁隔离数据库，远程使用 RDS 快照恢复或销毁独立 Demo 库/实例。这是当前更快且更低风险的撤销路径。

完整的接口重放和固定验证码仍属于后续阶段；下文的 `Reset` 与重放章节保留为未来设计，不代表当前可执行能力。

2026-09-02 验证记录：严格目录单测通过；MySQL 8.0.39 隔离测试覆盖后段故障全回滚、首次 Apply 378 行、只读 Verify 和重复 Apply 零写入；发布 JAR 的真实 PowerShell Apply/Verify 入口均输出 `CATALOG_READY`。远程 RDS、HTTPS、管理端和 APK 仍需独立留证。

### 5.2 安全门槛

执行任何写操作前必须同时满足：

1. 激活 `demo` profile。
2. 明确设置 `seed.demo.enabled=true`。
3. active profiles 不包含 `prod`；发现 `prod` 立即失败。
4. 运行时数据库名与 `DEMO_DATABASE_NAME` 完全相同。
5. 数据库处于管理员基线，或已经是当前版本的完整演示图谱；发现非演示业务数据立即失败。
6. Apply 所需的演示账号密码只通过环境变量提供，不能为空，也不写入文件。
7. Reset 的数据库名还必须以 `myapp_worktree_` 开头，满足项目的数据库清理限制。

`Verify` 为只读操作，但仍检查 profile、目标数据库和目录摘要，防止误认环境。

其中第 5 项按 Apply 阶段细化：首次 Apply 只接受管理员基线；重复 Apply 只接受“管理员基线 + 当前 namespace、相同 datasetVersion、目录固定 ID 集合内的完整演示数据”。出现任何目录外业务行、未知引用、版本不一致或部分演示图谱时立即失败。

脚本不能只相信调用者同时提供的 JDBC URL 和 `DEMO_DATABASE_NAME`。它从当前工作目录规范化得到 `WORKTREE_ID=worktree_<目录标识>`，据此推导并断言数据库名 `myapp_<WORKTREE_ID>` 和 Compose 项目名 `myapp-<WORKTREE_ID>`；同时从实际数据源连接信息解析主机和数据库名，写操作前明确打印解析值。该规范不要求创建新的 Git worktree，但确保当前目录也得到独立的 `myapp_worktree_*` 数据库。

### 5.3 事务、幂等和漂移处理

Apply 在一个数据库事务中完成：

- 固定 ID 不存在：按依赖顺序创建。
- 固定 ID 已存在且所有受管理业务字段一致：跳过。
- 固定 ID 已存在但业务字段、关系或状态不一致：报告首批差异并整体失败，不覆盖现有值。
- 同一逻辑业务键已被其他 ID 占用：视为冲突并整体失败。
- 固定 ID 对应软删除记录：视为漂移并失败，不自动恢复。

时间戳、乐观锁版本等运行时字段不参与目录摘要。密码使用现有 `PasswordEncoder.matches` 校验是否匹配当前演示密码，而不是比较随机盐生成的哈希文本。

Apply 第二次执行必须为无写入的成功操作。任何异常都回滚本次事务，不留下半套数据。

### 5.4 Verify

Verify 读取 JSON 列出的所有固定 ID，并校验：

- 对象数量、必需字段、状态、关系和逻辑业务键。
- 用户角色、身份状态、机构管理关系和医生/顾问关系。
- 价格、币种、启用状态及各类申请状态。
- 业务统计为 0，且订单、支付和评价数据没有因演示准备产生。
- 数据库中的中文源字段与目录一致。

成功输出 `CATALOG_READY`、数据版本、SHA-256 和精确数量；失败输出 `CATALOG_FAILED` 及不含敏感值的差异摘要，并返回非零退出码。

### 5.5 Reset

未来的 Reset 不是全库重置。它只删除 `docs/test/catalog-v1.json` 明确列出的固定演示 ID，并按外键依赖逆序执行。

目录必须枚举主管快照创建的全部从属行，包括账号角色、身份申请、机构成员关系、医生执业关系、顾问关系、钱包、项目申请和医生项目配置。主管快照不得调用会随机生成机构或关系 ID 的现有审批路径；这些业务规则由服务复用或显式校验，实际持久化全部使用目录固定 ID，保证 Reset 的删除集合完备。

执行前先做只读预检：

- 数据库名必须以 `myapp_worktree_` 开头。
- 运行时数据库名必须与 `DEMO_DATABASE_NAME` 完全一致。
- 待删除对象不得被目录之外的行引用。
- 不得存在订单、支付、评价等非本期对象对演示对象的引用。

任一条件不满足时拒绝清理。禁止使用全表截断、Flyway clean、删除非固定 ID、模糊名称匹配或级联猜测。

## 6. 真实接口重放设计

### 6.1 脚本和运行清单

未来新增 `scripts/replay-demo-catalog.ps1` 时，读取同一份 `docs/test/catalog-v1.json`，以 `-BaseUrl` 指定已启动的演示后端。

脚本按逻辑编码保存接口返回 ID：

```text
INST-SH-01 -> 运行时 institutionId
DOCTOR-SH-01 -> 运行时 userId/doctorId
PROJECT-SKIN-01 -> 运行时 projectId
INST-PROJECT-SH-01 -> 运行时 institutionProjectId
```

运行清单位于 `.runtime/demo-replay/manifest.json`，并确保 `.runtime/` 被 Git 忽略。清单只保存：

- 数据版本和目录 SHA-256。
- 本次运行 ID、目标 Base URL 的非敏感标识。
- 已完成步骤、逻辑编码与动态 ID。
- 每步响应状态和时间。

清单不保存密码、验证码、访问令牌、刷新令牌、认证材料内容或翻译全文。

### 6.2 验证码和凭据

为支持无人值守重放，可在后端增加严格受限的固定演示验证码：

- 仅 `demo` profile 下启用。
- 还必须显式设置 `seed.demo.replay-code-enabled=true`，值从 `DEMO_VERIFICATION_CODE` 环境变量读取。
- 与 `prod` 同时出现时应用启动失败。
- 默认、开发和生产配置仍使用现有随机验证码逻辑。

固定码能力实现为 demo-only 的无外发投递适配器，只替换验证码生成值和投递方式；现有手机号与用途绑定、有效期、重发间隔、失败次数及一次性消费语义全部保留。禁止实现绕过验证码存储校验的万能码。

管理员密码、共享专业账号密码和固定验证码均由执行环境提供。脚本只在内存中使用，不写入清单或日志。

### 6.3 九步结构和本期执行范围

脚本保留 `SMOKE-00` 至 `SMOKE-08` 的步骤编号和输出矩阵：

- `SMOKE-00`：验证隔离环境和管理员。
- `SMOKE-01`：通过真实注册/登录接口创建演示专业账号。
- `SMOKE-02`：提交并批准法人及机构。
- `SMOKE-03`：提交并批准医生身份和执业关系。
- `SMOKE-04`：提交并批准顾问身份和机构关系。
- `SMOKE-05`：提交/批准平台项目和机构项目，建立医生价格绑定并验证公开目录。
- `SMOKE-06` 至 `SMOKE-08`：本期输出 `DEFERRED_ORDER_SCOPE`，不创建订单、支付或评价。
- `TRANSLATION`：在目录完成后独立验证中文到英文的运行时翻译和缓存。

因此，本期成功状态代表“供给侧目录真实接口重放完成”，不宣称交易九步已全部完成。以后恢复订单范围时，可在不更换目录格式和前六步逻辑的前提下补充后三步。

`SMOKE-02` 内部进一步记录两个子流程：4 家首建机构来自法人申请审批；上海和北京各 1 家附加机构来自管理员机构创建接口，并通过管理员成员关系接口绑定和批准既有法人。两种操作均经过当前受管理员角色保护的真实接口。

### 6.4 续跑和失败处理

- 每个步骤成功后立即原子更新运行清单。
- 续跑必须使用同一个清单、相同目录 SHA-256 和相同目标环境。
- 续跑前读取服务端状态，确认清单中的动态 ID 和实际对象匹配。
- 实际状态与清单不一致时立即失败，不猜测对象、不按名称重新绑定。
- 明确收到 2xx 且运行清单已原子保存的步骤可以续跑；明确收到业务冲突时，只能按手机号、许可证编号或前序接口返回 ID 等唯一业务证据核对。
- 写请求发生超时、断连或其他提交结果不确定时，禁止自动重试，输出 `AMBIGUOUS_COMMIT`，改用新的隔离数据库和新清单从头重放。当前接口没有统一幂等键，因此不宣称可从任意不确定提交点安全续跑。
- 不得绕过真实接口直接补数据库。
- 需要完全重放时使用新的隔离数据库和新的运行清单，不依靠脚本模糊删除动态 ID。

目录阶段成功、翻译阶段失败时输出 `CATALOG_READY_TRANSLATION_FAILED`。中文目录仍可用于主管查看，修复翻译配置后可单独重跑翻译验收。

## 7. 校验规则

加载目录时必须在连接数据库前完成静态校验：

- `schemaVersion`、`datasetVersion`、`namespace` 存在且受支持。
- 所有逻辑编码和 UUID 在全目录唯一。
- 所有关系引用都能解析到同目录对象。
- 机构城市分布和各类对象数量符合第 4 节。
- 用户可见字段包含中文内容，不包含预置英文译文。
- 金额非负、使用 USD、最多两位小数，并处于约定价格带。
- 暂停项目、待审申请和拒绝申请数量正确；拒绝申请有审核意见。
- 销量、评价、案例、咨询等统计为 0。
- 不存在订单、支付、评价或支付供应商字段。
- 路径字段不能指向 `doc/`、`docs/`、工作区之外或 Git 对象。

静态校验失败时不得建立写事务。

## 8. 测试策略

### 8.1 目录单元测试

- 版本、UUID、逻辑编码、引用、数量和城市分布校验。
- 全中文展示字段校验。
- USD、两位小数、价格带和同城价格差校验。
- 无订单、支付、评价和支付供应商字段校验。
- 非法路径、未知 JSON 字段和重复业务键校验。

### 8.2 主管快照 MySQL 集成测试

按照项目数据库隔离规则，在全新空 MySQL 数据库上执行 Flyway 和快照测试。迁移或写入前打印解析后的数据库主机和数据库名。

测试夹具必须从当前目录派生并打印 `WORKTREE_ID`、`myapp_<WORKTREE_ID>` 和 `myapp-<WORKTREE_ID>`，再与实际连接及 Compose 配置交叉校验；不得让两个独立输入值相互“证明”目标安全。

测试覆盖：

- 第一次 Apply 创建精确数量的数据。
- 第二次 Apply 成功且不新增、不更新、不重复。
- 人为制造一个受管理字段漂移后，Apply 失败且不覆盖。
- Reset 后再次 Apply，数量和业务投影摘要一致。
- 新增一条目录外外键引用后，Reset 被拒绝。
- 任意中途异常都不留下部分数据。

### 8.3 安全配置测试

- 默认配置不创建演示数据。
- `demo + prod` 启动失败。
- `DEMO_DATABASE_NAME` 与实际数据库名不一致时失败。
- 派生数据库名、JDBC 实际数据库名和 Compose 项目名任一不一致时失败。
- 非空业务数据库上 Apply 失败。
- 缺少所需演示密码或固定验证码时，对应模式失败。
- Reset 目标不以 `myapp_worktree_` 开头时失败。
- 普通用户仍不能访问 `/api/admin/**`。

### 8.4 真实接口重放测试

- 从仅有管理员的隔离数据库运行 `SMOKE-00` 至 `SMOKE-05`。
- 从明确完成且已写入清单的步骤续跑，不产生重复账号、机构、项目或申请。
- 模拟写请求结果不确定时输出 `AMBIGUOUS_COMMIT`，不自动重试，也不继续后续步骤。
- 最终逻辑图、状态和精确数量与 JSON 一致。
- `SMOKE-06` 至 `SMOKE-08` 明确输出延期状态且不写入交易数据。
- 运行清单中不存在秘密或认证材料内容。

### 8.5 翻译测试

CI 在全新的后端应用上下文中使用受控的兼容聊天补全模拟网关，覆盖机构、医生、项目和 HTML 项目详情：

- 首次请求 `cached=false`，相同请求再次调用 `cached=true`。
- 模拟网关确定性返回合法 HTML 时，Flutter 富文本校验通过。
- 模拟网关返回标签、URL 或结构被破坏的 HTML 时，Flutter 拒绝译文并安全回退中文。
- 翻译前后数据库中文字段完全不变。
- 上游失败时中文展示不消失，目录状态不回滚。

主管演示前可在明确提供 `TRANSLATION_*` 环境变量时执行一次受控真实翻译验收。真实验收断言认证调用成功、译文非空、第二次调用 `cached=true` 以及中文不落库；第一次调用允许 `cached=false` 或 `cached=true`。真实 AI 若返回无效 HTML，验收安全回退中文，不宣称后端保证 HTML 合法，也不断言 AI 的逐字译文。

### 8.6 Flutter 验收

- 默认展示中文源数据。
- 用户已登录、切换英文并开启“AI 翻译”设置后触发认证翻译请求，而不是读取预置英文字段。
- 翻译失败时保留中文且页面可继续使用。
- 城市筛选能分别展示上海 2 家、北京 2 家机构。
- 公开列表和详情页显示启用项目，不把暂停项目误显示为可下单项目。

## 9. 验收标准

主管快照通过时必须同时满足：

- 6 家机构、10 名医生、6 名顾问、4 名法人代表。
- 12 个已批准平台项目、1 个待审平台项目申请、1 个已拒绝平台项目申请。
- 18 个启用机构项目、3 个暂停机构项目、3 个待审机构项目申请。
- 医生项目绑定为 30 条，其中 27 条启用、3 条停用。
- 上海和北京各有 2 家机构；深圳和成都各 1 家。
- 所有源数据为中文，所有价格为 USD 且两位小数。
- 所有业务统计为 0；不存在演示订单、支付、评价和交易会话。
- Apply 可重复执行，Verify 为只读，Reset 只处理固定演示 ID。
- 运行时英文翻译可用且不落库；翻译失败不破坏中文目录。
- 默认和生产启动路径无法误触发演示写入。

接口重放通过时必须同时满足：

- `SMOKE-00` 至 `SMOKE-05` 均通过真实接口完成并有清单证据。
- `SMOKE-06` 至 `SMOKE-08` 明确标记为本期延期，而不是伪造通过。
- 最终供给侧逻辑图与同版本 JSON 一致。
- 从同一清单中明确完成的检查点续跑不会产生重复数据；不确定提交按 `AMBIGUOUS_COMMIT` 终止。
- 日志和清单不包含秘密、真实私密材料或已删除支付文档内容。

## 11. 远程演示环境使用边界

该方案可用于主管远程 Demo，但环境必须满足：

- 独立应用实例、独立数据库，以及本地或完全隔离的对象存储前缀；不得连接共享 OSS。
- 网络访问范围受控，不使用生产域名和生产凭据。
- 先执行 Apply 和 Verify，再启动常规服务供主管查看。
- 演示服务常规运行期间关闭 `seed.demo.enabled`，避免每次启动重复触发命令行任务。
- 主管查看前关闭 `seed.demo.replay-code-enabled`、清除 `DEMO_VERIFICATION_CODE` 并重启，确保固定演示验证码不可用。
- AI 翻译密钥由远程环境秘密管理器注入，不写入镜像、仓库或快照。
- 演示结束后优先销毁整个隔离环境；需要 Reset 时仍必须满足固定 ID 和数据库名前缀门槛。

这使主管可以看到具有真实城市分布、机构差异、人员关系、项目层级和动态英文翻译的应用状态，同时不引入交易数据或真实隐私材料。
