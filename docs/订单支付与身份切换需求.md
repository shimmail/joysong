# 订单支付与身份切换需求

> 当前优先合同：`TRAVEL_GROUND_SERVICE_ONLY` 旅游地接服务费流程。
> 本文后续保留的面诊金、尾款、Stripe、核销、分账和结算内容仅服务 `LEGACY_MEDICAL` 历史兼容，不得用于创建或操作新流程订单。

## 0. 当前旅游地接服务费流程（优先）

### 0.1 两个业务环节

1. 平台订单环节：平台只收取一笔 USD `旅游地接服务费`，用于地接服务及平台监督。
2. 医院环节：用户到院确认后直接向医院支付医疗费；平台不为医疗费创建支付、退款、分账、结算或钱包记录。

医生维护医疗套餐优惠前金额 `medicalListPrice`，平台维护只读比例 `platformServiceRate`。服务费不乘数量、不使用优惠券，计算结果 HALF_UP 舍入到 USD 分币：

```text
travelGroundServiceFeeMinor = roundHalfUp(
    medicalListPriceMinor * platformServiceRateBps / 10000
)
```

下单前由 `GET /api/discover/travel-ground-service-quote?doctorId=...&institutionProjectId=...` 获取报价。创建订单时必须发送 `consultantId`；服务端校验顾问属于所选机构并立即绑定，同时固化金额、比例、币种和顾问快照。新请求不发送 `quantity`、`couponId`、面诊金或尾款。

### 0.2 信息开放与平台监督

- `PENDING_SERVICE_FEE`：只返回 `consultantBound=true` 等显式权限，不向用户暴露顾问 ID、履约资料或订单会话。
- `SERVICE_ACTIVE`：只有验签渠道事件或服务端主动查单确认支付成功后，才显示允许公开的顾问姓名、头像、机构，并开放订单专属会话。
- `REFUND_REVIEW` / `REFUND_PROCESSING`：保留顾问资料和历史读取，暂停发送。
- `REFUNDED`：隐藏顾问履约资料，保留已有会话受控只读，撤销发送权限。

订单会话固定使用 `POST /api/orders/{orderId}/service-conversation`，请求体为空。响应必须是 `conversationType=ORDER_SERVICE` 且 `orderId` 匹配。售前 `DIRECT` 会话与订单履约分离；顾问不得通过普通私信绕过支付状态自行接单。

### 0.3 订单、支付和退款状态

```text
PENDING_SERVICE_FEE
  -> SERVICE_ACTIVE
  -> REFUND_REVIEW
       -> SERVICE_ACTIVE          （拒绝或用户取消申请）
       -> REFUND_PROCESSING       （人工批准并提交原渠道）
            -> REFUNDED           （渠道确认全额退款成功）
```

支付合同固定为 `TRAVEL_GROUND_SERVICE_FEE + ALIPAY_PLUS + ALIPAY_PLUS_CASHIER + USD`：

```http
POST /api/orders/{orderId}/service-fee-payment-attempts
Idempotency-Key: <稳定的 8..100 字符值>
```

请求无 body，客户端不能选择金额、类型或渠道。用户在境内外均直接点击支付，不判断 GPS、IP 或国家；只打开服务端提供的受信任 HTTPS 托管收银台。

每次尝试有效 30 分钟，但只有超时的 `CREATED`、`REQUIRES_ACTION` 可以本地变为 `EXPIRED`。`PROCESSING` 或结果未知必须保持待查并由主动查单/对账解决；尝试过期不取消订单，订单仍可重新支付。

Alipay+ 商户注册及收单参数仍在安排，仓库尚无真实 gateway。当前创建请求应返回 HTTP 503 / `PAYMENT_PROVIDER_UNAVAILABLE`，且在拒绝前产生零条本地支付尝试；禁止 DEMO 或客户端伪造成功。

退款仅支持已成功支付的整笔服务费、人工审核、原渠道退回。退款记录真实状态为 `PENDING`、`REFUND_PROCESSING`、`APPROVED`、`REJECTED`、`CANCELLED`，不存在 `COMPLETED`。医院医疗费不适用本退款链路。

### 0.4 当前不做与旧链路安全门

- 本期不做姓名、护照、航班、酒店等来华资料备案。
- 订单、退款、身份审核和机构关系审核的业务事件会写入用户系统消息；它们不替代订单服务会话、也不发送营销或推送通知。点击消息按服务端 `targetType` 打开订单、订单服务会话或对应审核/申请历史；重放支付、退款或审核不会重复创建消息。
- Stripe、面诊金、尾款和医疗分账只保留历史兼容；新订单不可选择。
- `STRIPE_LEGACY_ENABLED=false` 默认关闭旧 adapter。若仍有历史查询/退款责任或责任查询失败，启动安全门 fail-closed；只有核对后处理历史责任才可受控启用，不能作为新支付方案。
- 结构迁移不删除旧订单或账务数据。

## 1. 目标

统一订单、预约、支付、履约和分账规则，作为用户端、医美顾问端、医生端、机构端和平台管理端身份切换及权限设计的共同契约。

## 2. 角色与工作态

同一用户可以同时拥有普通用户、医美顾问、医生和机构法人身份。登录账号不变，进入业务页面时选择当前工作态；服务端根据用户的有效身份、机构挂靠关系和资源归属重新校验权限，客户端不能仅凭身份名称放行功能。

| 工作态 | 核心能力 | 不能执行 |
|---|---|---|
| 普通用户 | 浏览项目、选择机构/医生/医美顾问、提交当前订单、支付旅游地接服务费、激活后进入订单会话并申请全额退款；历史订单仍可确认、展示核销码和确认完成 | 创建订单后修改绑定顾问；代他人确认、支付或执行历史核销 |
| 医美顾问 | 查看本人服务范围内的机构项目；在当前订单激活后查看和服务本人绑定订单；历史兼容中可回答售前咨询并从消息栏发起预约 | 支付前私下联系用户自行接单；代用户确认/支付/核销；修改已固化订单归属；超出挂靠机构范围创建订单 |
| 医生 | 管理本人档案、参与项目和服务订单、维护医疗套餐优惠前金额；历史兼容中可执行专业核验/申请完成并维护分成配置 | 代用户确认/支付；对当前新流程执行核销、完成或医疗分账；修改机构确认后的历史分成；操作非本人或非授权机构数据 |
| 机构法人 | 管理本人机构、审核医美顾问挂靠、确认医生/项目合作；历史兼容中可确认机构分成并执行机构侧核验/申请完成 | 代用户确认/支付；对当前新流程执行医疗收款、核销或结算；修改已支付订单的金额或归属 |
| 平台管理员 | 全量审核身份、合作关系、项目、订单、退款、争议、结算和人工纠错 | 绕过审计直接修改支付事实或删除账务记录 |

## 3. 预约与订单入口（仅 `LEGACY_MEDICAL` 兼容）

正式订单只能通过以下两种入口生成，用户始终拥有最终确认和支付权：

### 3.1 用户发起

1. 用户选择机构项目、医生、医美顾问（可选）和预约时间。
2. 服务端校验项目上架状态、机构合作状态、医生与机构关系、医美顾问挂靠关系、排期和价格。
3. 直接创建 `PENDING_USER_CONFIRMATION` 订单，不再增加医美顾问二次确认步骤。
4. 锁定项目、机构、医生、医美顾问归属、金额、优惠、币种和分账配置版本快照。
5. 用户确认后进入 `PENDING_PAYMENT`，再支付面诊金。

### 3.2 医美顾问从消息栏发起

1. 医美顾问在与用户的会话中选择“发起预约”。
2. 服务端校验医美顾问对机构和项目的服务权限，并校验医生、排期和价格。
3. 创建 `PENDING_USER_CONFIRMATION` 订单，记录 `initiatedBy=CONSULTANT` 和 `ownerConsultantId=当前医美顾问`。
4. 用户确认后进入 `PENDING_PAYMENT` 并完成支付。

医美顾问专属链接/邀请码只用于建立咨询关系和默认归因；订单正式创建时固化 `ownerConsultantId`。订单创建后，聊天转接、排班变化或再次点击其他邀请码都不能覆盖订单归属。

没有医美顾问时，`ownerConsultantId` 为空；尾款中的医美顾问份额并入医生收入。

## 4. 订单状态（以下仅 `LEGACY_MEDICAL` 兼容）

```text
PENDING_USER_CONFIRMATION
  -> PENDING_PAYMENT
  -> CONSULTATION_PAID
  -> VERIFIED
  -> BALANCE_PAID
  -> PENDING_COMPLETION
  -> COMPLETED
  -> PENDING_SETTLEMENT
  -> SETTLED
```

异常分支包括 `REJECTED`、`CANCELLED`、`REFUND_REQUESTED`、`REFUNDED` 和 `DISPUTE_MEDIATION`。

## 5. 支付规则（以下仅 `LEGACY_MEDICAL` 兼容）

- 面诊金 `CONSULTATION_FEE` 全额归平台，不参与医生、机构和医美顾问分账。
- 面诊金支付成功后，只有 Stripe Webhook 验签或服务端查单确认才推进订单。
- 尾款 `BALANCE` 支付金额由服务端订单/方案快照计算，客户端金额只用于展示。
- 尾款支付成功后按原订单快照生成分账台账。
- 支付阶段分别建立支付尝试和幂等键；重复点击、重复回调不能重复收款或推进状态。
- 用户不能代替医美顾问、医生或机构执行专业核验；医美顾问、医生和机构不能代替用户确认或支付。

## 6. 履约、退款与结算（以下仅 `LEGACY_MEDICAL` 兼容）

1. 用户展示核销码，医生或机构在线下核验；用户确认后订单进入 `VERIFIED`。
2. 项目实际完成后，机构或医生发起完成确认，用户确认后进入 `COMPLETED`。
3. 从用户确认完成或提交评价的约定结算起点开始，尾款分账冻结30天；存在退款或争议时暂停结算。
4. 退款前后均保留原支付和分账记录，通过反向分录冲正；已转账部分使用渠道转账撤销能力。
5. 每日对账支付、退款、转账、提现和本地台账，异常进入人工复核。

## 7. 尾款分账（以下仅 `LEGACY_MEDICAL` 兼容）

项目发布时由医生填写机构比例和医美顾问比例，机构确认机构比例，平台审核项目后生效。平台服务费固定为尾款的40%。

```text
platform = balance * 40%
institution = balance * institutionRate
consultant = ownerConsultantId != null ? balance * consultantRate : 0
doctor = balance - platform - institution - consultant
```

医生承担最小货币单位舍入余数，保证各分录合计等于尾款。分账配置按版本保存，不能回算读取最新配置。

## 8. 身份切换模块必须提供的上下文

`GET /api/management/context` 或等价接口至少返回：

- 当前用户的有效身份列表及状态。
- 当前工作态：`USER`、`CONSULTANT`、`DOCTOR`、`INSTITUTION`、`ADMIN`。
- 当前医美顾问可服务的机构列表。
- 当前医生可服务/管理的机构和项目列表。
- 当前机构法人可管理的机构列表。
- 当前订单服务费、订单会话和退款能力开关，以及仅供历史订单使用的预约、核验、分账和结算能力开关。
- 当前工作态切换失败原因和身份撤销/挂靠失效提示。

切换工作态只改变当前操作上下文，不改变登录账号；每个写接口仍需服务端按对象、机构关系、订单归属和订单状态重新鉴权。

## 9. 最低验收场景

当前流程首先验收：顾问必选并立即绑定；支付前信息裁剪；USD 分币和 HALF_UP 报价；Alipay+ 不可用时 503 且零尝试；只有渠道事实激活；仅 `CREATED/REQUIRES_ACTION` 超时；全额人工退款；审核/处理中只读；`REFUNDED` 隐藏履约资料；医疗费和来华资料备案不进入当前实现。订单/退款及身份、机构关系审核结果会创建系统消息，但不增加推送通道或重复聊天消息。

以下场景仅用于仍需维护的 `LEGACY_MEDICAL` 历史链路：

- 用户选择医美顾问发起预约，订单确认后医美顾问归属固化。
- 医美顾问从消息栏发起预约，用户确认后才能支付。
- 医美顾问转接给其他客服，原订单分佣归属不变，服务人员可变。
- 同一用户兼具医生和医美顾问身份，切换工作态后菜单、数据范围和可执行动作正确变化。
- 没有医美顾问的订单，尾款医美顾问份额归医生。
- 面诊金全归平台，尾款按四方规则分账。
- 撤销医美顾问身份或机构挂靠后，不能创建新订单；历史订单继续按快照结算并支持人工冻结。
- 重复支付回调、部分退款、拒付和30天结算观察期均可重试且不重复入账。
