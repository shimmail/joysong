# 订单支付与身份切换需求

## 1. 目标

统一订单、预约、支付、履约和分账规则，作为用户端、咨询师端、医生端、机构端和平台管理端身份切换及权限设计的共同契约。

## 2. 角色与工作态

同一用户可以同时拥有普通用户、咨询师、医生和机构法人身份。登录账号不变，进入业务页面时选择当前工作态；服务端根据用户的有效身份、机构挂靠关系和资源归属重新校验权限，客户端不能仅凭身份名称放行功能。

| 工作态 | 核心能力 | 不能执行 |
|---|---|---|
| 普通用户 | 浏览项目、选择机构/医生/咨询师、提交预约、确认订单、支付、核销展示、确认完成、退款/争议 | 创建已生效订单后修改咨询师归属；代他人确认、支付或核销 |
| 咨询师 | 查看本人服务范围内的机构项目；回答用户咨询；从消息栏向用户发起预约；查看和服务本人归属订单 | 代用户确认订单/支付/核销；修改已固化订单归属；超出挂靠机构范围创建订单 |
| 医生 | 管理本人档案、参与项目和服务订单；执行专业核验/申请完成；发布项目及分成配置 | 代用户确认/支付；修改机构确认后的历史分成；操作非本人或非授权机构数据 |
| 机构法人 | 管理本人机构、审核咨询师挂靠、确认医生/项目合作和机构分成；执行机构侧核验/申请完成 | 代用户确认/支付；修改已支付订单的金额或归属 |
| 平台管理员 | 全量审核身份、合作关系、项目、订单、退款、争议、结算和人工纠错 | 绕过审计直接修改支付事实或删除账务记录 |

## 3. 预约与订单入口

正式订单只能通过以下两种入口生成，用户始终拥有最终确认和支付权：

### 3.1 用户发起

1. 用户选择机构项目、医生、咨询师（可选）和预约时间。
2. 服务端校验项目上架状态、机构合作状态、医生与机构关系、咨询师挂靠关系、排期和价格。
3. 直接创建 `PENDING_USER_CONFIRMATION` 订单，不再增加咨询师二次确认步骤。
4. 锁定项目、机构、医生、咨询师归属、金额、优惠、币种和分账配置版本快照。
5. 用户确认后进入 `PENDING_PAYMENT`，再支付面诊金。

### 3.2 咨询师从消息栏发起

1. 咨询师在与用户的会话中选择“发起预约”。
2. 服务端校验咨询师对机构和项目的服务权限，并校验医生、排期和价格。
3. 创建 `PENDING_USER_CONFIRMATION` 订单，记录 `initiatedBy=CONSULTANT` 和 `ownerConsultantId=当前咨询师`。
4. 用户确认后进入 `PENDING_PAYMENT` 并完成支付。

咨询师专属链接/邀请码只用于建立咨询关系和默认归因；订单正式创建时固化 `ownerConsultantId`。订单创建后，聊天转接、排班变化或再次点击其他邀请码都不能覆盖订单归属。

没有咨询师时，`ownerConsultantId` 为空；尾款中的咨询师份额并入医生收入。

## 4. 订单状态

```text
PENDING_USER_CONFIRMATION
  -> PENDING_PAYMENT
  -> CONSULTATION_PAID
  -> VERIFIED
  -> BALANCE_PAID
  -> PENDING_COMPLETION
  -> COMPLETED
  -> PENDING_SETTLEMENT
  -> SETTLED
```

异常分支包括 `REJECTED`、`CANCELLED`、`REFUND_REQUESTED`、`REFUNDED` 和 `DISPUTE_MEDIATION`。

## 5. 支付规则

- 面诊金 `CONSULTATION_FEE` 全额归平台，不参与医生、机构和咨询师分账。
- 面诊金支付成功后，只有 Stripe Webhook 验签或服务端查单确认才推进订单。
- 尾款 `BALANCE` 支付金额由服务端订单/方案快照计算，客户端金额只用于展示。
- 尾款支付成功后按原订单快照生成分账台账。
- 支付阶段分别建立支付尝试和幂等键；重复点击、重复回调不能重复收款或推进状态。
- 用户不能代替咨询师、医生或机构执行专业核验；咨询师、医生和机构不能代替用户确认或支付。

## 6. 履约、退款与结算

1. 用户展示核销码，医生或机构在线下核验；用户确认后订单进入 `VERIFIED`。
2. 项目实际完成后，机构或医生发起完成确认，用户确认后进入 `COMPLETED`。
3. 从用户确认完成或提交评价的约定结算起点开始，尾款分账冻结30天；存在退款或争议时暂停结算。
4. 退款前后均保留原支付和分账记录，通过反向分录冲正；已转账部分使用渠道转账撤销能力。
5. 每日对账支付、退款、转账、提现和本地台账，异常进入人工复核。

## 7. 尾款分账

项目发布时由医生填写机构比例和咨询师比例，机构确认机构比例，平台审核项目后生效。平台服务费固定为尾款的40%。

```text
platform = balance * 40%
institution = balance * institutionRate
consultant = ownerConsultantId != null ? balance * consultantRate : 0
doctor = balance - platform - institution - consultant
```

医生承担最小货币单位舍入余数，保证各分录合计等于尾款。分账配置按版本保存，不能回算读取最新配置。

## 8. 身份切换模块必须提供的上下文

`GET /api/management/context` 或等价接口至少返回：

- 当前用户的有效身份列表及状态。
- 当前工作态：`USER`、`CONSULTANT`、`DOCTOR`、`INSTITUTION`、`ADMIN`。
- 当前咨询师可服务的机构列表。
- 当前医生可服务/管理的机构和项目列表。
- 当前机构法人可管理的机构列表。
- 订单、预约、消息、核验、分账和结算能力开关。
- 当前工作态切换失败原因和身份撤销/挂靠失效提示。

切换工作态只改变当前操作上下文，不改变登录账号；每个写接口仍需服务端按对象、机构关系、订单归属和订单状态重新鉴权。

## 9. 最低验收场景

- 用户选择咨询师发起预约，订单确认后咨询师归属固化。
- 咨询师从消息栏发起预约，用户确认后才能支付。
- 咨询师转接给其他客服，原订单分佣归属不变，服务人员可变。
- 同一用户兼具医生和咨询师身份，切换工作态后菜单、数据范围和可执行动作正确变化。
- 没有咨询师的订单，尾款咨询师份额归医生。
- 面诊金全归平台，尾款按四方规则分账。
- 撤销咨询师身份或机构挂靠后，不能创建新订单；历史订单继续按快照结算并支持人工冻结。
- 重复支付回调、部分退款、拒付和30天结算观察期均可重试且不重复入账。
