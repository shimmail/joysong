# 娇颜颂 AI 翻译功能调研与落地方案

更新日期：2026-08-04

## 1. 目标与边界

娇颜颂首版翻译服务于日记、评论、回复和私信等用户内容，让不同语言用户在不离开当前页面的前提下理解和沟通医美经验。所谓“覆盖原文”只指当前界面的展示替换，原始数据、搜索索引和审核记录均不修改；译文不得生成原文中不存在的疗效、风险、诊断或推广表述。

首版目标：

- 日记正文一键 AI 翻译；成功后译文替换正文，可点击“显示原文/显示译文”。
- 评论和回复在“回复”右侧使用翻译图标按钮；同一图标负责翻译及原文/译文切换，不显示文字切换按钮。
- 项目、机构、医生和文章详情等平台数据库内容暂不翻译，后续版本单独开发。
- 私信中的双方文本消息均可翻译；译文替换消息文本，可点击“显示原文/显示译文”。
- 目标语言始终跟随用户在应用内设置的语言；译文只保留“AI 译文”标识。

## 3. 推荐交互

### 首版：按内容类型采用不同交互

1. 日记正文下显示“AI 翻译”。点击后轻量加载，成功时译文直接替换正文；状态区显示“AI 译文”及“显示原文/显示译文”。
2. 评论、回复只在“回复”右侧显示翻译图标。首次点击翻译，再次点击在原文与译文间切换；图标高亮表示正在显示译文。
3. 私信双方的文本消息均可从长按菜单翻译，成功后替换消息正文，并保留“显示原文/显示译文”。图片消息不进入首版翻译。
4. 各条内容独立维护加载、成功和失败状态；任何翻译失败都不阻塞页面，不使用伪译文或其他内容替代。
5. 项目、机构、医生和文章详情保持展示数据库原文，首版不发起翻译请求。

### 第二阶段：偏好与批量翻译

- 扩充应用语言设置；翻译目标继续跟随应用语言，无需在每条内容上重复选择。
- 记录“始终翻译这些语言”“从不翻译这些语言”。
- 在详情页提供“翻译全部评论”，并限制并发与可见范围。
- 根据语言检测结果隐藏同语言内容的翻译入口。

### 第三阶段：多模态与沟通闭环

- 图片文字 OCR 翻译，保留原图并提供文字层。
- 视频字幕翻译；语音配音需单独征得创作者授权并明确 AI 标识。
- 私信增加“自动翻译本会话”偏好；发送内容仍保留原文，避免医疗沟通误解。
- 创作者可维护人工校正译文，人工版本优先于 AI 版本。

## 4. 当前实现

### 服务端

- 新增 `POST /api/translations`，请求字段为 `text`、`targetLanguage`、`contentType`。
- 接口沿用现有 Bearer 登录鉴权；Qwen 与 OpenAI 密钥均只在服务端读取，不向客户端下发。
- 默认 Provider 为百炼 `qwen3.7-flash`：评论、回复、私信和日记正文共用精简翻译提示词，低温度且只返回译文，以降低等待。OpenAI 中转作为可配置兜底，也可手动设为 Provider。
- 翻译复用 `AI_AGENT_API_KEY` 与 `AI_AGENT_BASE_URL`，但模型在代码中固定为 `qwen3.7-flash`，不使用聊天或意图模型。
- 翻译 Provider、请求形状和模型均为代码策略，不提供供应商回退或独立翻译环境变量。
- 部署前需在百炼开通 `qwen3.7-flash` 并配置五项 Agent 变量。所有密钥不得写入客户端或提交到仓库。
- 单次最多 12000 字符，以覆盖常见富文本文章；目标语言使用 BCP 47 标签；内容类型采用白名单。
- 模型提示词要求保留段落、emoji、@用户名、#标签、产品/项目名、数量、日期和不确定语气，禁止补充医疗建议或疗效声明。
- 日记、评论/回复与私信合并为同一“用户内容”翻译通道：共用 Qwen 提示词和缓存；相同原文翻向相同目标语言时，即使来自不同入口也可复用结果。
- 短文本按字符数动态收紧模型输出预算，长日记仍保留足够译文空间，避免固定 5000 tokens 带来的额外等待。
- 使用文本、目标语言与用户内容范围的 SHA-256 作为进程内缓存键，最多保存 1000 条，重复查看不重复调用模型。
- 返回译文、检测语言、目标语言、提供方和缓存命中状态。

### Android 客户端

- 新增翻译 DTO、领域模型、仓库和依赖注入绑定。
- 日记正文、顶级评论、回复及私信文本均支持独立翻译；日记和私信保留文字式原文/译文切换，评论仅使用图标切换。
- 项目、机构、医生和文章详情未接入翻译，继续直接展示数据库原文。
- ViewModel 按内容 ID 管理加载、成功、失败和显示状态，列表中某条失败不影响其他内容。
- 中英文资源均已补齐，目标语言直接读取应用的 `app_language` 设置，而非单独维护翻译语言。
- 发起请求前，客户端会跳过已完全为目标语言的文本：中文模式只跳过纯中文，英文模式只跳过纯英文；标点、数字和 emoji 不影响判断，混合语言及其他语种仍会调用 AI。

### 语言显示一致性

- 翻译请求只能读取 `app_language` 作为目标语言，不能调用 `LocaleHelper.setLocale` 或写入该偏好；翻译成功也只能更新当前内容的 `TranslationUiState`。
- 当前 `LocaleHelper` 通过 `Resources.updateConfiguration()` 修改资源，而设置页直接读取偏好值；异步请求完成触发重组或 Activity 生命周期刷新时，页面资源可能回退到系统语言，造成“设置显示 English、页面显示中文”的不一致。
- 后续应将语言机制改为在 `attachBaseContext` 调用 `super` 前包装 Context，或迁移至 AndroidX 应用级 Locale API。修复前不得以翻译接口返回的 `targetLanguage` 改写应用 Locale。

## 5. 生产化架构建议

### 能否在前端完成

可以，但有两种完全不同的含义：

- **前端负责交互，服务端负责 AI 推理（当前实现，首版推荐）**：Android 管理点击、加载、原文/译文切换和页面展示，服务端持有模型密钥、调用大模型并统一缓存、限流、术语提示与审计。这样不会把可提取的模型密钥打包进 APK，也最适合医美术语和网络语。
- **端侧模型直接翻译**：可接入 Android ML Kit，在设备上下载约 30 MB 的语言模型后离线翻译。它不需要上传正文，适合私信隐私、弱网和低成本场景；但官方定位偏日常、简单文本，医美术语、长富文本、网络语和非英语语言对的质量需要专项验证，也缺少服务端统一术语表与快速纠错能力。

不建议 Android 直接调用云端大模型 API：编译进 APK 的 API Key 可被反编译提取，难以可靠控制盗刷、限流和供应商切换。

如果后续优先考虑隐私与成本，可采用混合路线：数据库内容使用服务端预翻译与缓存，日记/评论使用服务端高质量模型，私信默认使用端侧模型，并允许用户主动选择“更高质量 AI 翻译”后再上传处理。

参考：[ML Kit Android 端侧翻译](https://developers.google.com/ml-kit/language/translation/android)、[Android API Key 安全建议](https://developer.android.com/privacy-and-security/risks/api-keys)

首版的进程内缓存适合验证需求。上线放量前建议将缓存升级为 Redis：

- Key：`translation:v1:{model}:{promptVersion}:{targetLanguage}:{contentType}:{contentHash}`。
- Value：译文、检测语言、创建时间、模型、提示词版本。
- TTL：日记 30 天、评论 7 天；内容修改后因哈希变化自然失效。
- 对相同 Key 使用分布式锁或 single-flight，避免热门内容并发击穿。
- 不在普通日志记录原文和完整译文，只记录散列、字符数、耗时、模型、状态和 token 数。

建议为用户与设备设置限流，并增加熔断：连续超时或上游限流时立即返回可重试状态，不阻塞内容阅读。翻译接口保持登录后可用，可以降低匿名滥用与不可归因成本。

私信属于高敏感内容。上线前应在首次使用私信翻译时明确告知内容会发送给 AI 服务商处理，并取得用户确认；同时与服务商约定不用于训练、最短留存或零留存，服务端日志不得记录私信原文与译文。若这些条件尚未满足，应通过功能开关关闭私信翻译，而不是静默降级到不合规的处理链路。

## 6. 医美场景专项质量策略

- 建立术语表：项目名、器械、药械品牌、成分、部位、单位、禁忌相关词，默认不意译品牌名。
- 数量与单位做翻译前后自动比对，例如剂量、价格、日期、次数和恢复期不得丢失或改变。
- 对“可能、个人体验、因人而异”等不确定语气做保真检查，禁止翻译为确定疗效。
- 审核和举报始终基于原文；译文只作为阅读辅助，举报页面同时携带原文 ID 与译文版本。
- 用户反馈应区分“译错”“不通顺”“术语错误”“有害增译”，用于术语表和提示词版本迭代。

## 7. 指标与验收

产品指标：翻译入口点击率、译文展开后停留、评论互动提升、收起率、重试率、负反馈率。

工程指标：P50/P95 延迟、成功率、缓存命中率、每千次翻译 token 成本、限流率、上游错误率。

首版建议验收线：

- 正常请求成功率不低于 99%。
- 缓存命中请求 P95 小于 200 ms；模型请求 P95 目标小于 5 s。
- 数字、单位、@用户名、#标签自动保真通过率 100%。
- 20 组中英日韩医美术语与网络语人工评测中，无新增医疗结论或确定性疗效表达。
