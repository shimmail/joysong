# 娇颜颂全模块接口审查报告

审查日期：2026-08-05

## 结论

当前服务端、Android 用户端和管理后台已经完成一轮契约对齐，具备开始 Flutter 网络层、登录注册、身份认证、内容浏览、咨询聊天和专业工作台开发的条件。

支付仍按当前决定保留接口和模拟流程，不影响 Flutter 页面与状态流开发，但真实支付、签名验签、异步回调和退款通道完成前不能用于生产交易。

Flutter 接入必须以 [FLUTTER_API_CONTRACT.md](./FLUTTER_API_CONTRACT.md) 和服务端实际 DTO 为准。仓库内旧 `openapi.yaml/json` 是不完整快照，不得用于生成客户端。

## Flutter 接入约束

1. 同时判断 HTTP 状态码和响应体 `code`，兼容历史接口的 `HTTP 200 + 业务错误码`。
2. 新客户端只使用 `accessToken`；收到 401 时单飞调用 `/api/auth/refresh`，轮换成功后必须原子替换 Access/Refresh Token。
3. UI 权限只信任 `/api/identity/overview` 和 `/api/management/context`，不能依据本地角色自行放行。
4. 列表严格传递 `offset/limit` 或 `before/limit`；订单金额、医生归属、优惠和权限均以服务端结果为准。
5. 身份审核资料只能走私有上传接口；公开证书不能标为“平台审核资质”，除非后续增加独立审核状态。
6. AI 流式响应按文档中的 SSE 事件解析，不再接入已删除的旧 `/api/ai/*` 或 Chat SSE 路径。
