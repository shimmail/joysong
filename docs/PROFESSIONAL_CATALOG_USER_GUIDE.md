# 专业目录使用说明 / Professional Catalog Guide

医生和机构法人可从各自的专业管理分组进入“专业目录 / Professional catalog”。入口会携带显式医生或法人 scope，避免多身份账号因角色顺序进入错误页面；当前兼容目录 API 本身不按该 scope 再拆分两套服务端结果。

## 目录展示什么

目录是只读的业务实体目录，展示当前账号可见的机构、机构内医生、平台项目和机构项目。机构可进入详情与医生列表，医生项可继续查看该医生在该机构下的项目。搜索只过滤已经由服务端返回的内容。

机构列表来自兼容只读 `GET /admin/institutions`。对非管理员，服务端按账号级
`visibleInstitutionIds` 过滤；该集合是以下三类当前有效关系 ID 的并集：

- 本人作为已确认机构法人的 `managedInstitutionIds`；
- 本人作为医生的 `doctorInstitutionIds`；
- 本人作为顾问的 `consultantInstitutionIds`。

因此，当前任职机构或本人管理机构出现在“专业目录”是正常的：它在这里仍是一条普通可见机构实体，供查看名称、详情、医生与项目，并不是机构关系申请或绑定记录“混入”目录。多身份账号的医生入口和法人入口可能看到同一个账号级并集；当前 API 不保证按医生/法人角色分别过滤。

## 与机构关系管理的边界

专业目录不得显示机构关系状态徽标、当前绑定列表、申请历史或候选资格，也不提供 `JOIN`、`LEAVE`、撤回、批准或驳回操作。上述能力只存在于“机构关系 / Institution relationships”页面，并分别使用 `/owned`、`/reviewable`、候选与 typed mutation 接口。目录中出现一个机构不代表用户可加入、可退出或可审核它；服务端候选和写接口仍独立校验权限与当前关系。

- 支持中英文搜索、无匹配、空目录、错误和重试状态。
- 机构详情的 403 与 404 使用相同不可用提示。
- 目录不提供机构、平台项目或机构项目的创建、编辑、删除。
- 与项目协作有关的申请、审核或撤回位于独立专业管理页面，不属于目录行为。

管理员系统、管理员接口实现与页面不变 / Admin system, admin API implementation, and pages are unchanged.
