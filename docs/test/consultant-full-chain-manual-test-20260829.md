# 医美顾问完整链路手工联调测试

统一执行入口：[全角色生命周期联调测试总流程](README.md)。本文件只负责医美顾问（代码角色 `CONSULTANT`，下文简称“顾问”）从普通用户开始的身份、机构关系和账号终态专项细节。

最后更新：2026-08-29

## 1. 测试目标

验证 `C-01` 从注册普通用户、完善公开资料、申请顾问身份，到平台审核、加入机构、进入公开预约候选、退出机构、身份撤销、重新认证及账号注销边界的完整前后端链路。

本轮重点确认：

- 普通用户账号、顾问专业身份和顾问机构关系是三套独立状态；
- 顾问身份申请的六个字段和三份认证材料只能用于受控审核，不会变成公开档案；
- 顾问审核通过只激活 `CONSULTANT` 角色并创建或复用顾问 USD 钱包，不创建顾问专业档案，也不自动加入机构；
- 顾问公开名称和头像来自普通用户资料，申请中的真实姓名、联系电话、从业经历及证明材料不会公开；
- 三笔独立 LEAVE 申请分别留存，撤回、驳回和批准不会覆盖旧记录；
- `I-01`、`I-02` 两个机构的关系、审核范围、公开候选和退出结果互不污染；
- 当前顾问项目目录为全局只读，且没有独立订单工作台、专业文章、排班或专业档案；
- 账号暂停、单个机构关系强制撤销、顾问身份撤销和账号注销不会留下错误权限。

## 2. 测试范围与重要边界

### 2.1 完整主链路

`注册普通用户 → 完善普通资料 → 首次申请顾问身份 → 平台驳回 → 修正并重新申请 → 平台批准 → 顾问钱包与专业入口生效 → 加入 I-01 → 法人审核 → 加入 I-02 → 公开预约候选 → 账号暂停与恢复 → 退出 I-01 → 单关系强制撤销 → 身份撤销冲突与级联 → 重新认证 → 注销边界`

### 2.2 审核职责

| 阶段 | 发起人 | 正常审核人 | 正常入口 |
|---|---|---|---|
| 顾问身份申请 | 普通用户 `C-01` | 平台管理员 `A-01` | Web 管理端“身份与入驻审核 → 身份申请” |
| 待审身份取消诉求 | `C-01` 通过客服或运营提出 | 平台管理员 `A-01` | 在同一审核入口以 `REJECTED` 终结，并填写“申请人请求取消”原因；不得记为用户 `WITHDRAWN` |
| 顾问加入或退出 `I-01` | 已认证顾问 `C-01` | `I-01` 目标机构法人 `L-01` | 用户端“专业管理 → 法人 → 机构关系审核” |
| 顾问加入或退出 `I-02` | 已认证顾问 `C-01` | `I-02` 目标机构法人 `L-02` | 同上，只能看到本人管理机构的申请 |
| 单个顾问机构关系强制撤销 | 无用户自助强制入口 | 平台管理员 `A-01` | 管理端机构成员关系投影页 |
| 顾问专业身份撤销 | 顾问退出诉求或平台合规触发 | 平台管理员 `A-01` | 管理端“职业身份 → 撤销”；结果为 `REVOKED` |
| 账号暂停或恢复 | 无用户自助入口 | 平台管理员 `A-01` | 管理端用户管理 |

平台管理员在后端具有关系审核兜底权限，但标准 GUI 主链路必须由目标机构法人审核。管理端旧顾问成员页不是新 `JOIN/LEAVE` 申请账本的正常审核入口；“机构成员 → 新增任职关系”属于平台人工覆盖路径，顾问关系会立即生效，不得用它代替“本人申请、目标法人审核”的主流程。

### 2.3 当前能力边界

顾问身份批准后的当前能力只有：

- “专业管理 → 顾问 → 机构关系”；
- “专业管理 → 顾问 → 项目目录”，仅查看全局平台项目；
- 普通“我的 → 钱包”中的顾问 USD 钱包。

当前明确没有：

- 顾问专业公开档案或顾问档案编辑页；
- 顾问专业文章、排班或专属内容管理；
- 顾问独立订单工作台和完整履约入口；
- 用户直接执行专业身份撤销的按钮；当前正式规则是由平台管理员代办撤销。

管理员代办身份撤销是本期正式运营规则，不是用户自助能力；测试人员必须记录申请人或合规触发来源、管理员、原因和时间。其他不存在的入口不得写成“功能通过”，也不得将普通用户昵称和头像误称为顾问专业档案。

- 创建新的独立身份申请并批准，`CONSULTANT` 角色恢复 `ACTIVE`；
- 复用原顾问 USD 钱包，不创建重复钱包；
- 普通用户昵称、头像及其他资料保持不变；
- 不创建顾问专业档案；
- 已撤销的 `I-01`、`I-02` 关系不会自动恢复，`consultantInstitutionIds=[]`；
- 未重新 JOIN 前不进入任何机构公开顾问列表或预约候选。

### CON-P0-19 账号注销边界与终态

状态：条件可执行；生产环境当前阻断。

先对 `C-01` 验证阻断：

1. 在重新认证后发起账号注销预检；
2. 核对有效 `CONSULTANT` 角色产生 `PROFESSIONAL_ROLE` blocker；
3. 若重新加入机构，核对有效成员关系产生 `INSTITUTION_MEMBERSHIP` blocker；
4. 若存在待审身份或关系申请，核对对应 blocker；
5. 确认系统不会为了注销自动绕过或静默删除这些专业状态。

实际终态只使用无交易数据的 `C-DEL`：

1. 若 `C-DEL` 已按用户分册 `USR-P0-07` 准备，先复核其为 `ACTIVE + CONSULTANT`、无机构关系、无待审申请且没有成功订单，再直接复用；否则按第 4.4 节独立数据完成一次注册、顾问申请和批准。随后由管理员撤销身份，并确认无有效关系和待审申请；
2. 核对顾问钱包余额为 `0` 且没有流水、冻结、结算或提现；先执行注销预检，如零余额空钱包仍产生 commerce blocker，则保存证据并停止；
3. 仅在非生产隔离环境开启账号注销；
4. 不得给有订单、支付、退款、钱包余额或结算数据的账号启用 commerce bypass；
5. 只有预检明确 eligible 时，才完成短信二次验证、严格输入大写 `DELETE` 和最终确认；
6. 核对旧会话失效、账号进入 `ERASED`；
7. 使用原手机号重新注册，记录新 userId。

预期结果：

- 生产环境或功能开关关闭时明确返回不可用，不能伪装为注销成功；
- 专业身份、待审身份申请、有效成员关系或待审关系申请存在时注销被阻止；
- 隔离终态通过后旧账号为永久 `ERASED`，管理员不能恢复；
- 原手机号重新注册必须生成新 userId，不能复活旧角色、钱包或机构关系；
- 当前交易 blocker 服务尚未形成完整生产闭环，因此 `C-DEL` 的隔离结果不能外推为真实业务账号已可安全注销。

## 14. 放行标准

身份与关系部分需满足：

- `CON-P0-01` 至 `CON-P0-12`、`CON-P0-15` 至 `CON-P0-18` 全部通过；
- 首次驳回、修正重申和批准使用独立身份申请记录；
- `C-REL-L01`、`C-REL-L02`、`C-REL-L03` 三笔 LEAVE 申请独立保留；
- 身份审批和机构关系审批职责正确，没有使用管理端旧投影页替代目标法人审核；
- 私有身份数据和三份认证材料没有进入公开资料、公开顾问列表或预约响应；
- 多机构加入、退出、强制撤销和身份撤销不会串机构或遗留专业权限；
- 重新认证不重复创建钱包，也不自动恢复旧机构关系。

完整业务发布还必须满足：

- `CON-P0-13` 的顾问订单工作台和履约入口不再阻断；
- `CON-P0-14` 暂停与恢复回归通过，且并发下单不会留下半成品订单或状态日志；
- 生产账号注销具备真实交易 blocker，且不用开发 bypass 也能正确判定；
- P1 不存在影响权限、隐私、状态一致性或资金范围的未解决问题；
- P2 问题不影响提交、审核、撤回、机构选择、公开候选和关键证据阅读。

在上述当前阻断未解决前，可以确认身份和机构关系子链路，但不得宣布“顾问全生命周期和订单履约已完成生产放行”。
