# 平台管理员完整链路手工联调测试

最后更新：2026-08-29

统一执行入口：[全角色生命周期联调测试总流程](README.md)。本文负责唯一固定管理员从 Bootstrap 初始化、独立管理登录、身份与项目审核、关系人工覆盖、用户账号暂停恢复、专业身份与机构关系撤销，到改密、退出和会话失效的独立完整链路。

## 1. 测试目标

验证 Web 管理端、Kotlin 后端与 Flutter 用户端之间的管理控制面一致，并确认：

- `ADMIN_PHONE` 唯一指定固定管理员，空库可安全初始化，正常重启只校验同一账号；
- 动态创建管理员、平台角色变更、暂停或恢复管理员均为不适用的产品边界，服务层拒绝路径由自动化测试留证；
- `users.role=ADMIN` 与医生、顾问、法人等 `user_roles` 专业身份严格分离；
- 管理员使用独立 `/api/admin/login`，普通 App 登录不能绕过管理登录策略；
- 待审专业身份只由管理员执行 `APPROVE/REJECT`，申请人提出取消时由管理员以 `REJECTED` 代办并记录原因；
- 已生效专业身份只由管理员执行 `REVOKE`，形成正式运营闭环；
- 项目审核、项目价格、关系人工覆盖和撤销的对象权限正确；
- 用户暂停、恢复与管理员改密立即使相关旧会话失效；
- 当前缺少统一、不可篡改管理审计的能力被明确列为发布缺口。

本文不把所有 `/api/admin/**` URL 自动视为“只有管理员可用”。部分历史兼容接口在安全配置中只要求已登录，仍须验证具体服务对象授权。

## 2. 状态标记与角色模型

| 标记 | 含义 |
|---|---|
| 可执行 | 当前管理端和后端能力已存在，应按 P0 验收 |
| 条件可执行 | 依赖隔离环境、同一管理员的并行会话或其他角色先完成数据准备 |
| 当前阻断 | 统一审计、生产等价能力或标准 GUI 尚未完成，只记录缺口 |

管理员完整链路：

```text
配置 Bootstrap A-01
  → 空库服务启动校验/初始化
  → 不携带 ADMIN_PASSWORD 的正常重启校验
  → 独立管理登录
  → 身份审批与代办取消/项目与价格/用户/关系管理
  → A-01 管理密码修改、退出和重新登录
  → A-01 旧管理会话失效且保持可用
```

必须分开记录：

| 维度 | 值 | 含义 |
|---|---|---|
| 平台角色 | `USER` / `ADMIN` | 是否具有平台管理权限 |
| 账号状态 | `ACTIVE` / `ADMIN_SUSPENDED` / `ERASED` | 是否可登录及是否可恢复 |
| 专业身份 | `DOCTOR` / `CONSULTANT` / `INSTITUTION_LEGAL_REPRESENTATIVE` | 专业能力，不等于管理员 |
| 机构关系 | `PENDING` / `APPROVED` / `REVOKED` 等 | 对具体机构的对象范围 |

固定管理员 `ADMIN` 平台角色不会自动授予医生、顾问或法人身份；撤销专业身份也不会改变固定管理员平台角色。

专业身份采用管理员运营闭环，且必须区分“申请”和“已生效身份”：

- 待审专业身份申请：管理员执行 `PENDING → APPROVED/REJECTED`；申请人提出取消时仍由管理员选择驳回并填写“申请人请求取消”的原因，终态为 `REJECTED`，不得记为 `WITHDRAWN`；
- 已生效专业身份：只有管理员可执行 `ACTIVE → REVOKED`，不把缺少用户自助撤销视为链路缺口；
- 以上规则不改变医生/顾问机构关系 `JOIN/LEAVE` 和项目申请的原职责。关系申请仍由目标机构法人审核，项目申请仍由相应业务角色提交和审核，不能统称为“管理员撤回”。

## 3. 环境和安全约束

1. 仅在本地或隔离测试数据库执行，不修改共享开发或生产账号；
2. 管理员测试手机号必须由 Bootstrap 配置在隔离库中创建，不触发真实短信；
3. 下列号码仅为隔离测试夹具，禁止当作真实用户联系方式；
4. 生产或共享环境的 Bootstrap 真实密码只能通过安全配置注入，不得提交到仓库、截图、缺陷正文或日志；本文 `Admin@Test2026!` 只是公开的本地隔离夹具占位值，禁止复用于任何共享或生产环境，执行证据仍需对实际密码打码；
5. 正常重启必须移除 `ADMIN_PASSWORD`；已有管理员时不要求或使用该变量，且配置不得重置现有密码；
6. 强制关系撤销、硬删除订单、人工状态修改等高风险入口仅对虚构对象操作，并在操作前保存对象 ID 和快照；
7. 身份材料全部为带 `TEST SAMPLE / 仅用于测试` 水印的虚构文件。

## 5. P0 主链路用例

### ADM-P0-00 隔离环境与配置检查

状态：可执行。

步骤：

1. 记录三端版本、数据库标识和 active profiles；
2. 确认 Bootstrap 配置解析为 `13800009001`，密码只存在于安全配置；
3. 确认当前数据库为空，或尚未执行首次 Bootstrap；若已有账号，必须明确使用全新的主隔离库执行 `ADM-P0-01`；
4. 记录测试对象和高风险操作范围。

预期结果：测试数据可重复准备且与真实账号隔离；如果数据库已有普通用户但不存在可用管理员，系统应拒绝悄悄创建新的 Bootstrap 管理员，需先修复受控环境状态。

### ADM-P0-01 Bootstrap 初始化与幂等启动

状态：可执行。首次空库、正常重启和配置漂移拒绝路径均在隔离环境执行。

步骤：

1. 在空隔离库使用 `A-01` 配置启动服务；
2. 核对创建的账号；
3. 使用相同配置重启服务；
4. 移除 `ADMIN_PASSWORD` 后正常重启，比较两次启动前后的 userId、角色、状态、账号数量和密码登录结果；
5. 在可恢复副本中分别配置不同手机号、等价手机号格式，或使该手机号指向非管理员/不可用管理员，验证服务启动失败；完成后丢弃副本，不修改主隔离库。

预期结果：

- 首次启动创建 `A-01`：`ACTIVE + ADMIN`、裸 11 位手机号、非空密码；
- 已有管理员的再次启动不要求或使用 `ADMIN_PASSWORD`，只校验同一账号，不重复创建、不重置密码、不改变 userId；
- 配置漂移、等价手机号 owner、同一配置手机号已被不可用或非管理员账号占用时启动失败，而不是篡改账号；
- Bootstrap 账号不自动拥有任何专业身份。

### ADM-P0-02 独立管理登录和错误保护

状态：基础登录可执行；限流分支仅在测试环境已启用且能读取实际阈值时执行。

步骤：

1. 打开 Web 管理端登录页；
2. 使用 `A-01` 的裸 11 位手机号和安全配置密码登录；
3. 记录 `/api/admin/login` 响应头、token 和管理员 userId；
4. 用 `A-01` 尝试普通 `/api/auth/login` 和验证码登录；
5. 使用不存在手机号、普通用户手机号、错误密码、`+86` 格式和非 11 位号码分别登录；
6. 记录本环境管理登录限流阈值、计数窗口和客户端/IP 识别方式，再从一个隔离测试客户端连续失败直至触发 429；不预设固定次数；
7. 保存 `Retry-After` 后按其等待，或重启仅供本轮使用的隔离服务实例，再验证正确凭据恢复可登录。若无法读取限流配置或环境未启用限流，本分支标记“条件未满足”，不得猜一个次数写为通过。

预期结果：

- 只有 `/api/admin/login` 成功，返回 `role=ADMIN`；
- 管理登录要求裸 11 位中国大陆手机号和密码；
- 普通登录入口拒绝管理员，验证码不能绕过管理员密码；
- 不存在、非管理员、暂停、错误密码等统一返回 401“管理员账号或密码错误”，不泄露账号是否存在；
- 限流返回 429、`Retry-After`，登录响应带 `Cache-Control: no-store`；
- 密码不出现在 URL、日志或错误信息。

### ADM-P0-03 固定管理员权限与角色隔离

状态：可执行。

步骤：

1. `A-01` 打开数据概览、用户、身份、项目、订单、财务和内容菜单；
2. 查看 `A-01`、`U-01`、`D-01`、`C-01` 和 `L-01`；
3. 核对平台角色列与职业身份列；
4. 使用普通用户 token 请求 `/api/admin/users` 和 `/api/admin/identity/applications`；
5. 未登录请求相同接口；
6. `A-01` 尝试使用医生、顾问或法人自助入口执行专业写操作。

预期结果：

- `A-01` 具有严格平台管理入口权限；普通用户为 403，未登录为 401；
- 平台角色和职业身份分别显示，一个账号可同时存在但不互相推导；
- 固定管理员不能冒充某个医生、顾问或法人执行其本人自助动作；
- 管理员使用全局管理接口时仍受对象存在性、状态和业务前置约束；
- 管理端没有动态创建、角色变更、暂停或恢复管理员入口；服务层相关失败路径由自动化测试留证。

### ADM-P0-04 动态管理员生命周期（不适用）

状态：不适用。产品只支持由 `ADMIN_PHONE` 指定的唯一固定管理员，不提供动态创建、平台角色变更、暂停或恢复管理员能力。

留证：不构造第二管理员或手工改库夹具；保存 `AdminAccountCommandServiceTest` 中固定管理员变更被拒绝的服务层证据，并在 `ADM-P0-12` 核对管理端入口和 `ERASED` 边界。

### ADM-P0-05 身份申请驳回、代办取消与通过

状态：可执行，依赖三类专业申请。`D-R01` 是共享夹具；若已由医生或用户分册完成 R1 驳回、R2 重提和批准，本用例直接复核共享证据，或从其未提交申请的独立可恢复副本重跑，不得在主库重复申请。`ID-CANCEL-01` 固定复用 `U-01` 在用户分册 `USR-P0-06` 提交的顾问 `PENDING` 申请，不再创建匿名夹具。

步骤：

1. 在“身份与入驻审核 → 身份申请”筛选 `PENDING`；
2. 若 `D-R01` 尚未准备，使用医生分册第 4.2/4.3 节的首次申请作为专用驳回对象，逐项查看字段和五份私有材料；若共享夹具已批准，则打开既有 R1/R2 两个 applicationId 复核同样证据，并跳过第 3、9 步的重复写操作；
3. 仅在 R1 仍为 `PENDING` 时，驳回先不填说明，再填写 `ADM-REJECT-001`；
4. 让 `ID-CANCEL-01` 的申请人通过本轮客服工单或外部执行记录提出取消，并记录申请人、applicationId、申请时间和请求原因；管理员打开该 `PENDING` 申请，选择“驳回”，填写 `ADM-CANCEL-001`；
5. 核对 `ID-CANCEL-01` 变为 `REJECTED`，审核人、时间和原因可追踪，且没有出现 `WITHDRAWN`；
6. 分别打开 `L-01` 法人、`D-01` 医生和 `C-01` 顾问的有效申请；
7. 使用 `ADM-APPROVE-001` 通过三类申请；
8. 刷新申请、职业身份、用户和对应专业对象；
9. 仅在本用例实际执行 R1 驳回时，`D-R01` 使用明确的 `R2` 材料重新提交；使用 `A-01` 的两个独立并行会话对这笔 applicationId 同时点击通过，保存并发证据。

预期结果：

- 私有文件只有管理员受保护预览，响应禁止缓存，不形成公开 URL；
- 驳回必须有说明；驳回不创建角色、档案、机构或钱包；
- 待审专业身份没有用户直接撤回状态变更；申请人请求取消时由管理员代办驳回，状态固定为 `REJECTED`，原因明确包含“申请人请求取消”，不得写成 `WITHDRAWN`；
- 法人通过：激活法人角色，创建或恢复已认证机构、法人 `APPROVED` 关系和机构 USD 钱包；
- 医生通过：激活医生角色，创建或恢复医生档案与医生 USD 钱包，但不自动加入机构；
- 顾问通过：激活顾问角色并创建或复用顾问 USD 钱包，但不创建专业档案、不自动加入机构；
- 三类账号的平台角色仍为 `USER`；
- 并发审核只有一个成功，另一个提示状态已变化，不重复创建副作用。

### ADM-P0-06 关系审核边界与平台人工覆盖

状态：标准链路可执行；管理端对新 JOIN/LEAVE 的 GUI 审核不是正常入口。

先验证标准职责：

1. `D-01`、`C-01` 各提交一笔加入 `I-01` 的请求；
2. 确认 React 管理端旧“医生执业”和“机构成员”投影页不能把新请求当作标准审核队列；
3. 由 `L-01` 在 Flutter 法人关系审核入口批准；
4. 管理员刷新投影，核对批准结果、确认人和时间。

再验证平台人工覆盖。此分支需等 `C-01` 顾问身份、`L-03` 法人身份、`I-02/I-01B` 均已准备后执行，并先制作可恢复的隔离库副本；所有操作只发生在副本中：

1. 为 `C-01` 通过“机构成员 → 新增任职关系”绑定 `I-02`；
2. 核对顾问关系立即 `APPROVED`；
3. 为 `L-03` 创建 `I-01B` 法人成员关系；
4. 核对关系先为 `PENDING`，再由管理员点击“通过”；

### ADM-P0-11 管理员撤销已生效专业身份

状态：可执行；这是已生效专业身份的正式运营闭环，只能由管理员执行 `ACTIVE → REVOKED`。必须在 `ADM-P0-10` 完成且医生、顾问仍为 `ACTIVE` 后执行。

步骤：

1. `D-01`、`C-01` 的 `I-01` 关系已在上一用例撤销；两人分别重新提交 JOIN，由尚有效的 `L-01` 批准，使其重新同时加入 `I-01/I-02`；
2. 准备并批准 `L-03` 对 `I-01/I-01B` 的替代法人关系，在医生、顾问仍活跃于 `I-01` 时撤销 `L-01` 法人身份；

4. `D-01`、`C-01` 分别对 `I-01` 提交一笔 `LEAVE/PENDING`；
5. `A-01` 使用 `ADM-REVOKE-001` 尝试撤销对应身份；
6. 核对冲突后没有部分变化，再由本人撤回各自的待审机构关系 LEAVE 申请，并按原职责处理完待审项目申请；

预期结果：

- 撤销原因必填，重复撤销被拒绝；
- 已生效专业身份只允许管理员撤销；不提供用户自助撤销不再作为生命周期缺口；
- 医生/顾问存在待审关系时撤销冲突，角色和现有关系不部分更新；
- 法人身份先撤销时，机构继续有效，活动医生和顾问关系、项目、钱包及历史订单不受误伤；
- 医生撤销：角色 `REVOKED`、医生档案未认证、包括 `I-02` 在内的全部医生机构关系撤销、医生会话回退普通用户；
- 顾问撤销：角色 `REVOKED`、包括 `I-02` 在内的全部顾问机构关系撤销、顾问会话回退普通用户；钱包记录保留但不再按顾问权限返回；
- 法人撤销：法人角色和法人任职关系撤销，但不会自动停用机构或撤销机构内医生、顾问、项目和历史订单；
- 基础普通用户能力保留，历史订单不删除；
- 重新认证不会自动恢复已撤销机构关系。
- 本用例中的“撤销专业身份”与用户撤回待审机构关系 `LEAVE`、提交或处理项目申请是不同对象和权限，不得合并描述为“管理员撤回全部”。

## 9. 管理审计现状和验收要求

当前只有局部业务字段可追踪：身份审核有审核人/时间/说明，专业身份撤销有撤销人/时间/原因，部分关系、项目和订单状态有确认人或状态日志。以下操作缺少统一的操作者、原因、前后快照和不可篡改审计：

- 用户暂停与恢复；
- 部分人工关系撤销；
- 部分订单、内容和财务人工修正。

手工测试期间必须使用外部执行记录补充“谁、何时、对哪个对象、为什么、前后状态、响应和截图”，但这不能替代产品审计能力。生产放行前至少应满足：

1. 所有权限、账号和资金相关写操作记录管理员 userId；
2. 高风险操作原因必填；
3. 保存前后状态或可重建差异；
4. 审计记录普通管理员不可修改和删除；
5. 支持按管理员、对象、动作和时间检索；
6. 敏感材料访问也应有审计且不记录材料正文。

当前未满足时标记 `ADMIN-BLOCK-01`，不能宣称管理控制面已达到生产审计要求。

## 13. 放行标准

- `ADM-P0-00` 至 `ADM-P0-05`、`ADM-P0-09` 至 `ADM-P0-13` 全部通过；
- `A-01` 只在空库由 `ADMIN_PHONE` 首次创建；已有管理员的正常重启不要求或使用 `ADMIN_PASSWORD`，且不重置现有密码；
- 平台角色、专业身份和机构关系没有混写、提前授权或残留权限；
- 待审专业身份由管理员 `APPROVE/REJECT`；申请人请求取消时由管理员代办为 `REJECTED` 并保留原因，已生效专业身份仅由管理员 `REVOKE`；
- 专业身份、机构关系 `JOIN/LEAVE` 与项目申请各自遵循独立职责，未被统一包装为“管理员撤回”；
- 身份审批、关系兜底、项目审核、项目价格、订单视图和账号管理不存在跨用户、跨机构或跨角色越权；
- 管理员改密、退出以及用户暂停后旧 access token 和 refresh token 按规则失效；
- 暂停医生、顾问不会公开展示或进入新预约，恢复后无需重建专业关系即可恢复；
- 固定管理员边界不允许动态生命周期变更，服务层拒绝证据已留存；
- `ADM-P0-06` 至 `ADM-P0-08` 的条件数据链通过，且管理员兜底没有替代标准业务职责；
- 分账功能按 `ADMIN-SCOPE-01` 记为本期 `N/A`，不执行、不取证，也不影响本轮放行判定；
- `ADMIN-BLOCK-01` 的统一审计补齐并复测后，才可宣称管理控制面达到生产放行标准；
- P2 问题不影响登录、审核、权限变更、暂停恢复、撤销和危险操作确认。
