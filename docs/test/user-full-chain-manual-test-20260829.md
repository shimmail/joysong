# 普通用户完整链路手工联调测试

最后更新：2026-08-29

统一执行入口：[全角色生命周期联调测试总流程](README.md)。本文负责普通用户从注册、登录、资料、公开浏览、专业身份待审期间的普通能力、预约下单、完成评价，到账号暂停、恢复、注销和重新注册的独立完整链路。

## 1. 测试目标

验证普通用户的账号与消费链路在 Flutter 用户端、Kotlin 后端和 Web 管理端之间保持一致，并确认：

- 密码注册、密码登录和验证码登录不会产生重复账号；
- 未注册手机号验证码登录会创建一个无密码普通账号；
- 普通资料和公开头像与私有认证材料严格分离；
- 专业身份处于 `PENDING` 时，普通用户能力继续可用，但专业能力不能提前开放；
- 订单必须使用有效机构、机构项目、医生项目绑定及同机构顾问；
- 用户只能操作自己的订单，只有满足状态条件的订单才能完成和评价；
- `ACTIVE → ADMIN_SUSPENDED → ACTIVE` 可恢复，`ERASED` 为不可恢复终态；
- 生产注销、真实交易清理和完整顾问履约尚未实现的部分被明确标为条件或阻断。

本文不替代医生、顾问、法人和管理员分册。跨角色对象及执行顺序以总流程为准。

## 2. 状态标记与生命周期

| 标记 | 含义 |
|---|---|
| 可执行 | 当前用户端、管理端和后端能力已存在，应按 P0 验收 |
| 条件可执行 | 依赖隔离环境开关、测试短信、模拟支付或跨角色数据 |
| 当前阻断 | 产品能力尚未完成，只记录拒绝结果或缺口证据 |

本分册使用的账号状态链：

```text
未注册
  ├─ 密码注册 + 验证码 ───────────────→ ACTIVE + USER + hasPassword=true
  └─ 未注册手机号验证码登录 ─────────→ ACTIVE + USER + hasPassword=false

ACTIVE ──管理员暂停──→ ADMIN_SUSPENDED ──管理员恢复──→ ACTIVE
ACTIVE ──隔离环境注销──→ ERASED（不可恢复）
ERASED ──原手机号重新注册──→ 新 userId 的 ACTIVE 新账号
```

`users.role=USER` 是平台基础权限；医生、顾问、法人属于独立的 `user_roles` 专业身份。提交专业身份申请不会把平台角色改成管理员，也不会在审核通过前授予专业能力。

## 3. 测试环境和安全约束

1. 仅使用隔离测试数据库、测试短信服务、测试对象存储和测试支付商户；
2. 不连接共享开发数据库，不使用真实手机号、身份证、交易或私聊数据；
3. 下列手机号仅为测试夹具，必须加入隔离环境短信白名单或映射到本地固定验证码，禁止向真实公网号码发送短信；
4. 账号注销只能在非 `prod` 环境执行；不得为了让有交易账号通过注销而启用 commerce bypass；
5. 记录 App、后端、管理端版本，Android/iOS、语言、屏幕宽度和网络环境；
6. 所有写操作保存请求、响应和对象 ID，不直接修改数据库制造“通过”结果。

## 5. P0 主链路用例

### USR-P0-00 隔离环境与空账号确认

状态：可执行。

步骤：

1. 记录三端版本和测试环境标识；
2. 确认 `U-01`、`U-02` 不是真实号码，且仅由测试短信服务接管；
3. 确认 `U-01`、`U-02` 当前没有可复用的活动账号；
4. 独立执行本分册时，确认 `A-01`、`I-01`、`D-01`、`C-01` 已准备；按总流程执行时，本步只确认 `A-01`，其余对象尚未创建，登记为计划前置并推迟到 `ALL-P0-10` 后核对；
5. 记录账号注销、开发自动支付和真实支付开关值。

预期结果：环境与账号来源可追溯；任何生产配置、真实交易或共享数据出现时立即停止相关危险步骤。

### USR-P0-01 `U-01` 手机号注册

状态：可执行，依赖测试短信。

步骤：

1. 打开用户端注册页；
2. 输入 `+8613900004001` 并获取验证码；
3. 输入测试验证码和密码 `Joysong@Test2026!`；
4. 提交注册；
5. 记录返回的 userId、access token 到期时间和 refresh token 证据；
6. 进入“我的”核对账号状态。

预期结果：

- 注册成功并自动登录，只创建一个 `ACTIVE + USER` 账号；
- `hasPassword=true`，没有医生、顾问或法人专业身份；
- 手机号保存为 E.164 形式，不被改成管理端使用的裸 11 位号码；
- 使用相同手机号重复注册被拒绝，不产生第二个 userId；
- 验证码不正确、过期或已使用时不创建账号。

### USR-P0-02 密码登录、验证码登录和退出

状态：可执行。

步骤：

1. `U-01` 正常退出；
2. 使用手机号和 `Joysong@Test2026!` 密码登录；
3. 核对 userId 与注册时相同；
4. 再次退出，获取新验证码并使用验证码登录；
5. 再次核对 userId、资料和平台角色；
6. 使用错误密码和错误验证码各尝试一次。

预期结果：

- 两种登录方式进入同一个 `U-01`，不创建重复账号；
- 错误凭证不返回 token；
- 用户端普通登录不能用于 `ADMIN` 平台账号；
- 退出后 refresh token 失效；复制的 access token 是否仍可使用直到到期作为 `USR-AUTH-RISK-01` 单独记录，不能用来否定退出按钮本身的结果。

- 没有有效专业身份时不显示专业写入口，直接请求应被拒绝；

### USR-P0-06 专业身份待审期间仍保持普通用户能力

状态：可执行。

步骤：

1. `U-01` 按 `4.3` 提交顾问身份申请；
2. 确认申请状态为 `PENDING`；
3. 在管理员不处理申请时，重新执行资料查看、公开浏览、收藏和订单列表读取；
4. 尝试进入顾问机构关系、顾问项目目录或其他专业写接口；
5. `U-01` 通过客服或运营提出取消诉求，`A-01` 使用 `USR-E2E-CANCEL-001 申请人请求取消，由管理员代办终结待审申请` 作为原因驳回申请；
6. `U-01` 查看驳回原因，再次核对普通能力。

预期结果：

- 待审和驳回期间 `U-01` 始终为 `ACTIVE + USER`；
- 普通资料、浏览、收藏和本人订单能力不受影响；
- `PENDING` 不创建 `ACTIVE CONSULTANT` 角色、顾问钱包或机构关系；
- 私有申请材料不出现在普通资料或公开页面；
- 待审专业身份由管理员批准或驳回；用户提出取消诉求时，当前以管理员 `REJECTED` 加明确原因代办终结，不生成用户 `WITHDRAWN`。这是本期正式运营规则，不影响机构关系申请仍由本人按各自流程撤回。

### USR-P0-07 订单前置校验与创建 `O-01`

状态：条件可执行，依赖完整跨角色数据链。

前置条件：

- `I-01` 已认证且机构项目 `IPJ-01` 有效；
- `D-01` 医生身份有效，与 `I-01` 关系为 `APPROVED`，并已加入 `IPJ-01`；
- `C-01` 顾问身份有效，与同一个 `I-01` 关系为 `APPROVED`；
- 机构项目的价格和币种配置有效。
- `D-R01` 必须按管理员分册 `ADM-P0-05` 使用医生分册第 4.2/4.3 节数据完成 R1 驳回、R2 重提和 `A-01` 两个独立并行请求/会话的重复批准；保持医生身份有效但不加入任何机构或机构项目，并复用同一份共享证据；
- `C-DEL` 按顾问分册第 4.3/4.4 节完成顾问申请和批准，在身份撤销/注销前保持无机构关系；本用例的失败请求不得为其生成订单。

步骤：

1. `U-01` 从公开项目或医生详情进入预约；
2. 选择 `I-01 + IPJ-01 + D-01 + C-01`；
3. 选择未来预约时间并填写约定备注；
4. 提交一次，保存请求和响应；
5. 查看订单列表和详情；
6. 使用其他普通用户猜测 `orderId` 读取或操作；
7. 分四笔独立失败请求验证：用 `D-R01` 替换 `D-01` 构造医生未绑定机构/项目；用 `C-DEL` 替换 `C-01` 构造顾问不属于 `I-01`；其余两笔分别使用过去预约时间和 501 字备注。每笔都保存响应并确认未创建订单。

预期结果：

- 创建 `O-01`，支付流为 `TRAVEL_GROUND_SERVICE_ONLY`；未启用开发自动支付时返回 `PENDING_SERVICE_FEE`；若环境明确启用创建后自动支付，响应可能已是 `SERVICE_ACTIVE`，但状态日志仍须包含先创建为 `PENDING_SERVICE_FEE` 的事实；
- 价格、币种、机构、项目、医生和顾问均来自服务端有效对象及快照，不能由客户端篡改；
- 其他用户不能读取或操作 `O-01`；
- 任一服务端前置不成立时不创建订单；
- 创建接口当前没有稳定幂等键。重复点击若产生多笔订单，记录 P0 数据一致性缺陷。

### USR-P0-08 支付与服务开放

状态：条件可执行；真实 Alipay+ 生产链路当前未放行。

步骤：

1. 在隔离环境使用明确启用的开发自动支付，或在预发布使用真实测试商户；
2. 创建旅游地接服务费支付尝试；
3. 记录 Idempotency-Key、paymentId、渠道状态和服务端订单状态；
4. 模拟成功页返回但服务端未确认成功；
5. 再完成一次服务端确认成功的支付；
6. 刷新订单详情和消息入口。

预期结果：

- 客户端只能支付服务端固定的旅游地接服务费，不能提交医疗项目价作为支付金额；
- 相同 Idempotency-Key 返回原支付尝试，不重复收费；
- 只有服务端确认支付成功后，订单才从 `PENDING_SERVICE_FEE` 进入 `SERVICE_ACTIVE` 并记录 `serviceActivatedAt`；
- 浏览器或 App 成功页不能单独开放服务；
- 模拟支付通过不等于真实 Alipay+ 生产放行。

## 6. 注销数据清理边界

注销通过不代表所有历史业务表都被物理删除。必须按当前实现分别验收：

| 数据类别 | 当前处理和测试判定 |
|---|---|
| 账号与凭证 | 手机号、邮箱、密码和普通资料清空；账号标记 `ERASED`；refresh token、auth session 撤销 |
| 日记与分享 | 日记内容和作者信息清空并标记删除；已有分享撤销 |
| 评论与社交关系 | 本人评论、点赞、收藏、关注和通知删除，并重算受影响计数 |
| 举报 | 举报人改为不可逆审计主体，描述和目标摘要清空 |
| AI 数据 | 会话、消息、计划、评估及用户画像删除；安全事件改为审计主体并清空证据 |
| 身份历史 | 非活动关系和身份数据按当前清理规则删除或清空；任何待审申请、有效角色、有效机构关系会先成为 blocker |
| 媒体 | 符合条件的用户媒体标记为待异步删除；不能只凭数据库状态断言对象存储已即时删除 |
| 商业数据 | 订单、支付、退款、钱包和结算未纳入完整清理，必须由真实 commerce blocker 阻止；不得在有交易账号上使用 bypass |
| 评价和私信 | 当前清理边界未完整定义；`U-02` 必须预先没有这些数据，并记录产品保留/删除策略缺口 |

## 13. 放行标准

- `USR-P0-00` 至 `USR-P0-06`、`USR-P0-10` 全部通过；
- 注册、两种登录、普通资料、公开浏览和平台/专业角色隔离不存在 P0/P1 缺陷；
- `USR-P0-07` 至 `USR-P0-09` 在生产等价环境通过，且顾问工作台和真实支付不再阻断，才可宣称消费业务全链路通过；
- 旧 token 在密码修改、暂停、平台角色变化和注销后按规则失效；
- 暂停医生、顾问不会公开展示或进入新预约，恢复后无需重建专业关系即可恢复；
- `USR-P0-11` 至 `USR-P0-14` 仅能证明隔离环境终态；生产注销需等功能开放、真实 commerce blocker 和数据保留策略完成后重新验收；
- 私有身份材料没有进入公开资料，跨用户订单和账号数据不存在越权；
- P2 问题不影响注册、登录、支付、完成、评价、暂停恢复或注销确认。
