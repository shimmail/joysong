## 1. 文档层级与使用方法

按以下顺序使用，避免在多份文档之间来回跳转：

1. 先执行本文的全角色主流程；
2. 机构法人独立执行时，进入[机构法人完整链路手工联调测试](legal-representative-full-chain-manual-test-20260829.md)；
3. 医生独立执行时，进入[医生完整链路手工联调测试](doctor-full-chain-manual-test-20260829.md)；
4. 医美顾问独立执行时，进入[医美顾问完整链路手工联调测试](consultant-full-chain-manual-test-20260829.md)；
5. 普通用户独立执行时，进入[普通用户完整链路手工联调测试](user-full-chain-manual-test-20260829.md)；
6. 平台管理员独立执行时，进入[平台管理员完整链路手工联调测试](admin-full-chain-manual-test-20260829.md)；
7. 所有跨角色执行结果最终回填到本文的总记录表。

本文负责角色间依赖、统一数据链、执行顺序和发布门槛；五份角色分册负责各角色可独立执行的完整生命周期、字段、边界和排版细节。跨角色规则以本文为准，角色内部步骤以对应分册为准。

## 2. 全生命周期范围

本轮“全生命周期”包括：

`账号创建 → 普通用户基线 → 专业身份申请 → 平台审核 → 角色能力初始化 → 加入机构 → 机构法人审核 → 项目与订单协作 → 账号暂停/恢复 → 退出机构 → 撤销专业身份 → 账号注销或终态验证`

其中“角色能力初始化”不是同一种副作用：法人会创建或恢复机构、法人关系和机构钱包；医生会创建或恢复医生公开档案和医生钱包；咨询师只激活角色并创建或复用咨询师钱包，当前不会创建咨询师专业档案。

### 2.1 一眼看懂执行顺序

| 顺序 | 主执行人 | 本阶段产物 | 下一阶段前置门槛 |
|---:|---|---|---|
| 0 | 管理员、普通用户 | 可登录管理员、普通用户基线账号 | 管理接口和普通用户端可用 |
| 1 | 法人、管理员 | 已认证机构、法人关系、机构档案 | `I-01` 可公开访问和管理 |
| 2 | 医生、管理员、法人 | 医生身份、档案、机构关系 | 医生已加入 `I-01` |
| 3 | 咨询师、管理员、法人 | 咨询师身份、钱包、机构关系 | 咨询师已加入 `I-01` |
| 4 | 医生、法人、管理员 | 平台项目、机构项目、医生项目绑定 | 订单全部服务端前置成立 |
| 5 | 普通用户及各履约角色 | 订单、支付、履约、评价证据 | 完整业务闭环可判定 |
| 6 | 管理员 | 暂停/恢复及新业务暴露结果 | 账号状态边界已确认 |
| 7 | 医生、咨询师、法人、管理员 | 退出关系、撤销身份及级联证据 | 专业权限无残留 |
| 8 | 普通用户、管理员 | `ERASED` 或明确的生产阻断证据 | 旧账号不可恢复 |

不在本文穷举的独立模块：AI 对话、日记、评论、收藏、支付渠道对账、退款、结算和完整内容审核。主流程只验证这些模块与角色权限的关键交点。

## 3. 三套状态机必须分开记录

### 3.1 账号状态

| 当前状态 | 操作 | 下一状态 | 结果 |
|---|---|---|---|
| 未注册 | 注册，或未注册手机号验证码登录 | `ACTIVE` | 创建普通 `USER` 账号 |
| `ACTIVE` | 管理员暂停 | `ADMIN_SUSPENDED` | 旧访问令牌和刷新令牌失效，不能登录 |
| `ADMIN_SUSPENDED` | 管理员恢复 | `ACTIVE` | 原 userId 和业务数据保留，必须重新登录 |
| `ACTIVE` | 用户完成注销 | `ERASED` | 永久终态，不可恢复 |
| `ERASED` | 原手机号重新注册 | 新账号 `ACTIVE` | 必须生成新 userId，不能复活旧账号 |

`users.role` 只表示平台权限：`USER` 或 `ADMIN`。

### 3.2 专业身份状态

| 阶段 | 身份申请 | `user_roles` | 专业能力 |
|---|---|---|---|
| 未申请 | 无 | 无 | 只有普通用户能力 |
| 待审 | `PENDING` | 尚未激活 | 不能使用该专业能力 |
| 驳回 | `REJECTED` | 尚未激活 | 显示原因，可以创建新申请 |
| 通过 | `APPROVED` | `ACTIVE` | 按角色开放专业能力 |
| 撤销 | 历史申请仍保留 | `REVOKED` | 专业入口和服务端权限关闭，普通用户能力保留 |

专业身份为 `DOCTOR`、`CONSULTANT`、`INSTITUTION_LEGAL_REPRESENTATIVE`。同一个普通账号可以同时拥有多个有效专业身份；不得把专业身份误写为平台管理员角色。

`DECISION-01`：待审专业身份执行正式管理员运营规则。`PENDING` 仅允许平台管理员 `APPROVE` 或 `REJECT`；申请人提出取消诉求时，由管理员选择 `REJECT`、记录“申请人请求取消”等真实原因，最终状态为 `REJECTED`，不得伪造为 `WITHDRAWN`。

`DECISION-02`：已生效专业身份同样执行正式管理员运营规则。`ACTIVE` 仅由平台管理员填写原因并执行 `REVOKE`，结果为 `REVOKED`；这不是发布阻断，也不要求提供用户自助撤销入口。

以上两项决策只适用于专业身份申请及专业角色，不适用于医生、咨询师的 `JOIN/LEAVE` 机构关系申请，也不适用于平台项目或机构项目申请。后两类对象继续使用各自的发起人、审核人、撤回和状态规则，不能由管理员专业身份操作代替。

### 3.3 医生、咨询师机构关系状态

| 操作阶段 | 申请状态 | 当前关系 | 权限结果 |
|---|---|---|---|
| 申请加入 | `JOIN/PENDING` | `NONE` | 不提前获得机构权限 |
| 加入驳回或撤回 | `JOIN/REJECTED` 或 `WITHDRAWN` | `NONE` | 可重新申请 |
| 加入通过 | `JOIN/APPROVED` | `APPROVED` | 机构进入本人可见范围 |
| 申请退出 | `LEAVE/PENDING` | `APPROVED` | 审核期间关系继续有效 |
| 退出驳回或撤回 | `LEAVE/REJECTED` 或 `WITHDRAWN` | `APPROVED` | 原关系继续有效 |
| 退出通过 | `LEAVE/APPROVED` | `NONE` | 从当前机构及新业务候选中移除 |

机构法人身份通过时由平台自动创建或恢复机构及法人关系，不再走一次“加入机构”审核。

## 4. 审核职责矩阵

| 事项 | 发起人 | 正常审核人 | 正常入口 |
|---|---|---|---|
| 法人、医生、咨询师身份申请 | 普通用户；取消诉求由用户提出 | 平台管理员 `APPROVE/REJECT`；取消诉求按 `REJECTED` 处理并记录原因 | Web 管理端“身份与入驻审核 → 身份申请” |
| 医生加入或退出机构 | 医生本人 | 目标机构法人 | 用户端“专业管理 → 法人 → 机构关系审核” |
| 咨询师加入或退出机构 | 咨询师本人 | 目标机构法人 | 用户端“专业管理 → 法人 → 机构关系审核” |
| 平台项目创建申请 | 已认证医生 | 平台管理员 | 管理端平台项目申请审核 |
| 机构项目创建、加入或编辑申请 | 与机构有有效关系的医生 | 目标机构法人 | 用户端对应机构项目审核入口 |
| `ACTIVE` 专业身份撤销 | 用户可提出诉求但不直接改状态 | 平台管理员填写原因并 `REVOKE` | 管理端“职业身份 → 撤销” |
| 单个机构关系强制撤销 | 无用户自助强制入口 | 平台管理员 | 管理端关系投影页 |
| 用户暂停、恢复 | 平台管理员 | 平台管理员 | 管理端用户管理 |

平台管理员在后端具有部分关系审核兜底权限，但标准 GUI 主链路必须使用机构法人审核。管理端旧“医生执业”页和旧顾问成员页不是新 `JOIN/LEAVE` 账本的正常审批入口。“机构成员 → 新增任职关系”属于平台人工覆盖路径：顾问关系创建后立即生效，法人等其他成员关系先进入 `PENDING`，还需管理员点击“通过”；两种方式都不得代替医生、咨询师“本人申请、目标法人审核”的标准链路。

部分历史兼容接口虽然使用 `/api/admin/**` 路径，但并非都在安全层统一要求平台管理员。权限测试必须以具体接口和业务对象授权为准，不能仅凭 URL 前缀判定。

### 阶段 8：账号注销与重新注册

#### ALL-P0-18 普通用户注销与重新注册

只允许使用 `U-02` 这类无交易、无专业身份、无待审申请、无机构关系、无评价和无私信的专用账号，并确认：

注销前让 `U-02` 创建一组安全可删内容：测试日记及媒体、评论、点赞、收藏、AI 会话、分享和举报，并记录所有对象 ID；仍不得创建订单、评价、私信、钱包、专业身份或机构关系。当前没有关注写入口，点赞/评论也不会生成通知，关注和通知仅在环境提供受控 API 或自动化夹具时作为条件项验证，否则手工流程记 `N/A`，不得直接改库凑数据。随后执行“账号与安全 → 注销账号”：预检、短信二次验证、输入严格大写 `DELETE`、最终确认、逐项核对已记录对象、旧会话失效、管理端终态核对、原手机号重新注册。

按三类边界记录结果：

| 数据类别 | 本用例判定 |
|---|---|
| 注销流程应处理 | 账号进入 `ERASED`、PII 清空、令牌和会话失效；本人日记、评论、点赞、收藏、AI 数据、分享、报告和媒体按当前清理规则下架、清空、匿名化或进入异步删除；关注、通知仅在受控夹具存在时追加验证 |
| 当前必须由 blocker 阻止 | 订单、支付、退款、钱包和结算尚未纳入完整注销清理；存在这些数据时不得使用开发 bypass 强行注销 |
| 当前边界未完整定义 | 评价和私信不由现有注销清理器完整处理；本 P0 账号必须预先不存在这些数据，并另行记录产品保留/删除策略缺口 |

预期：旧账号为 `ERASED` 且不可恢复；新账号 userId 与旧账号不同。生产环境当前固定禁用注销并返回 503；专业身份按 `DECISION-01/02` 由管理员处理待审取消诉求和生效身份撤销，账号注销仍须独立满足注销预检，不得把专业身份操作当作账号注销，也不得把隔离账号通过误写成“全部业务数据已完成注销清理”。

完成 `U-02` 终态核对后，按管理员分册 `ADM-P0-13` 让 `A-01` 完成改密、服务端退出和重新登录。管理员自身角色或账号状态变更不适用；核对旧管理会话失效且 `A-01` 仍可用。

| DECISION-02 | `ACTIVE` 专业身份仅由管理员 `REVOKE` | 管理员填写撤销原因并核对 `REVOKED`、权限失效及历史数据保留；不再作为发布阻断 |

`DECISION-01/02` 不适用于医生、咨询师的 `JOIN/LEAVE`，也不适用于平台项目或机构项目申请；这些对象仍按各自状态机执行本人撤回、目标法人审核或平台管理员审核。

## 12. 放行门槛

### 身份与权限门槛

- `ALL-P0-00` 至 `ALL-P0-09`、`ALL-P0-15` 至 `ALL-P0-17` 全部通过；
- 三套状态机没有混写、提前授权或残留权限；
- 私有材料不公开，跨用户和跨机构不存在越权；
- 医生、咨询师身份通过不自动入机构，机构关系通过不自动入项目。

### 完整业务门槛

- `ALL-P0-10` 至 `ALL-P0-14` 在生产等价环境全部通过；
- 咨询师订单工作台、真实支付、完成和评价闭环不再处于阻断状态；
- 普通用户、医生、咨询师和管理员看到的是同一订单事实。

### 账号终态门槛

- 暂停、恢复和令牌失效通过；
- `DECISION-01/02` 的管理员审批、代办取消诉求和身份撤销均可完成且留痕；`JOIN/LEAVE` 机构关系仍按独立状态机形成闭环；
- 生产注销开放，真实交易 blocker、数据删除/匿名化和重新注册通过；
- 管理员关键操作具备可追踪审计。
