# 医生完整链路手工联调测试

统一执行入口：[全角色生命周期联调测试总流程](README.md)。本文件只负责医生身份、档案和机构关系专项细节。

## 1. 测试目标

验证用户从注册普通账号，到申请并获得医生身份、完善公开档案、加入/退出机构、账号暂停恢复、身份撤销与重认，以及注销安全边界的完整前后端链路。

本轮重点确认：

- 普通用户注册、医生身份申请、平台审核和专业权限生效形成闭环；
- 医生身份审核与医生加入机构是两条独立状态机；
- 医生私有认证材料不会进入公开档案；
- 医生公开联系电话可自行填写，并可与登录手机号不同；
- 医生只能编辑本人档案、申请本人机构关系，机构法人只能审核本人管理的机构；
- 机构 JOIN/LEAVE 的撤回、驳回、批准与专业身份的管理员驳回、撤销不会造成关系或权限错乱；
- 中文、英文、窄屏和大字体下关键页面可阅读、可操作。

## 2. 测试范围与重要边界

### 2.1 完整主链路

`注册普通用户 → 提交医生身份申请 → 平台管理员审核 → 医生身份生效 → 完善医生档案 → 申请加入机构 → 目标机构法人审核 → 医生机构权限生效 → 账号暂停/恢复 → 退出并重新加入机构 → 平台管理员撤销身份 → 重新认证 → 注销预检或安全阻断`

### 2.2 审核职责

| 阶段 | 发起人 | 审核人 | 审核入口 |
|---|---|---|---|
| 医生身份认证 | 普通用户 | 平台管理员 | 管理端“身份与入驻审核 → 身份申请” |
| 待审医生身份取消诉求 | 用户提出取消诉求，平台管理员代办 | 平台管理员 | 在身份申请审核页选择“驳回”，填写“申请人请求取消”等明确原因，终态记为 `REJECTED` |
| 已生效医生身份撤销 | 用户提出运营诉求或平台风控发起 | 平台管理员 | 管理端“职业身份 → 撤销”，终态记为 `REVOKED` |
| 医生加入或退出机构 | 已认证医生本人 | 目标机构法人；平台管理员也具有接口级审核权限 | 用户端“我的 → 专业管理 → 法人 → 机构关系审核”；也可从“我的 → 机构关系”进入，此时页面标题为“成员关系审核” |

必须注意：管理端网页“身份与入驻审核 → 医生执业”读取 `doctor_institutions` 关系投影；新的 `JOIN/PENDING` 只存在申请账本中，因此不会显示在这里。该页可能显示遗留的待审关系投影和“通过”按钮，但后端会固定拒绝直接批准；它只适合核对已批准或已撤销关系，以及在没有待审关系申请时执行撤销。新的加入申请应由目标机构法人在用户端审核，不可把平台网页“医生执业”写成加入机构的正常审批入口。

医生专业身份采用管理员运营模式：`PENDING` 申请只能由平台管理员批准或驳回；用户要求取消时，由管理员以 `REJECTED` 加明确原因代办，不使用 `WITHDRAWN`。`ACTIVE` 身份只能由平台管理员执行 `REVOKE`。该规则不改变医生本人对机构 `JOIN/LEAVE` 待审申请的撤回能力，也不改变机构法人对关系申请的审核职责。

### 2.3 身份与账号边界

- 审核通过后，账号的平台基础角色仍为普通用户，同时新增有效的 `DOCTOR` 专业身份；
- 医生身份审核不会自动绑定医院或医美机构；
- 医生认证申请中没有联系电话，也不允许提交 `hospitalName`；
- 联系电话在认证通过后的“医生档案”中由医生自行填写；
- 加入机构后不会自动加入任何机构项目，项目合作需要另行申请；
- 分账功能本期不启用，相关配置、比例、提案和收益分配验收统一标记为 `N/A`；项目价格和订单必要数据仍按本文件准备；
- 本文只对项目、文章和订单入口做冒烟检查，详细业务规则应单独编写模块测试。

|---|---|---|---|---|---|
| 注册完成 | 无 | 无 | 无 | 无 | 只具有普通用户功能 |
| 身份待审 | `PENDING` | 尚未创建 | 无 | 无 | 不能使用医生专业功能 |
| 身份驳回 | `REJECTED` | 尚未创建 | 无 | 无 | 显示原因，可以重新申请 |
| 身份通过 | `APPROVED` | `ACTIVE` | 已创建、已认证 | 当前关系 `NONE` | 可编辑本人档案，可申请加入机构 |
| 加入待审 | `APPROVED` | `ACTIVE` | 正常 | 申请 `JOIN/PENDING`，当前关系 `NONE` | 当前机构仍为空 |
| 加入通过 | `APPROVED` | `ACTIVE` | 正常 | 申请 `JOIN/APPROVED`，当前关系 `APPROVED` | 首个机构成为主机构，权限上下文更新 |
| 账号暂停 | `APPROVED` | 仍为 `ACTIVE` | 保留 | 当前关系保持 `APPROVED` | 本人不能登录，旧 token 失效；从全部公开入口和新预约候选移除，新订单拒绝，业务对象不删除 |
| 账号恢复 | `APPROVED` | 仍为 `ACTIVE` | 保留 | 当前关系保持 `APPROVED` | 重新登录后恢复公开展示和候选资格，无需重建专业身份、机构关系或项目绑定 |

### DOC-P0-14 账号注销边界

状态：边界可执行；生产环境和含医生业务数据的账号不得强行注销。

1. 在重新认证后对 `D-01` 发起注销预检，核对有效 `DOCTOR` 产生 `PROFESSIONAL_ROLE` blocker；
2. 另制作可恢复的隔离库副本，只在副本中再次撤销医生身份并重做预检；
3. 核对医生钱包、平台/机构项目申请、项目绑定、订单、支付、退款或结算是否形成 blocker；
4. 若任何商业或当前未定义清理策略的数据存在，停止并丢弃副本；生产环境应固定返回 503。

预期：有效专业身份时绝不进入最终确认；撤销身份也不代表医生业务数据可安全删除。不得对有历史订单、资金或项目数据的 `D-01` 开启 commerce bypass，不要求本用例把账号变为 `ERASED`；这是一条明确的安全终态，而不是漏测。

## 7. P1 身份申请与审核用例

本章需要管理员并发或幂等验证时，使用唯一固定管理员 `A-01` 的两个独立并行请求或会话；不得假设存在第二管理员。

`D-R01` 的 R1 驳回、R2 重提和双管理员并发批准只实际执行一次，唯一规范准备入口为管理员分册 `ADM-P0-05`；本章 `DOC-ID-P1-15/16` 提供医生侧数据和预期并复核已保存的两个 applicationId、材料及审核证据。独立执行医生分册时也应先完成 `ADM-P0-05` 对应步骤；需要重跑则从未提交申请的独立可恢复副本执行，不得在主库重复申请。

| 编号 | 场景 | 预期结果 |
|---|---|---|
| DOC-ID-P1-01 | 七个字段逐项留空 | 页面或后端阻止提交，指出对应必填项 |
| DOC-ID-P1-02 | 真实姓名输入 1 个字符或超过 50 个字符 | 阻止提交，原申请列表不变 |
| DOC-ID-P1-03 | 证件号码输入 5 位、31 位、空格、中文或特殊符号 | 阻止提交，仅接受 6–30 位字母数字 |
| DOC-ID-P1-04 | 科室、职称、两类证书编号分别超过 100 个字符 | 阻止提交并显示可理解的错误 |
| DOC-ID-P1-05 | 申请理由超过 500 个字符 | 阻止提交 |
| DOC-ID-P1-06 | 请求额外包含 `hospitalName` | 400，提示医生身份申请不允许填写执业机构 |
| DOC-ID-P1-07 | 缺少五类材料中的任意一种 | 阻止提交，明确缺少的材料 |
| DOC-ID-P1-08 | 直接构造请求，重复引用同一 `fileId`，或令文件上传用途与申请声明类型不一致 | 400；分别上传同一个本地文件会生成不同 `fileId`，当前不按文件内容去重 |
| DOC-ID-P1-09 | 使用其他用户的文件 ID、已失效文件或提交后删除材料 | 拒绝访问或删除，私有文件归属不被绕过 |
| DOC-ID-P1-10 | 上传空文件、不支持的 MIME、声明 MIME 与真实文件签名不一致或超过 10 MB | 上传失败，不把无效文件加入申请；仅修改原始文件名后缀当前不是独立拒绝条件 |
| DOC-ID-P1-11 | 材料总数超过 10 个 | 400，申请不创建 |
| DOC-ID-P1-12 | 已有同身份 `PENDING` 时再次提交 | 只保留一条待审记录 |
| DOC-ID-P1-13 | 已有有效 `DOCTOR` 身份时再次申请 | 提示该身份已经认证通过 |
| DOC-ID-P1-14 | 管理员驳回时不填原因 | 管理端阻止审核，申请仍为 `PENDING` |
| DOC-ID-P1-15 | 使用 `D-R01` 首次数据申请，管理员填写“医师执业证图片不清晰，请重新上传”后驳回 | 申请为 `REJECTED`，不创建医生档案、角色和钱包 |

## 9. P1 机构关系生命周期用例

### 9.1 加入申请的撤回与驳回

| DOC-REL-P1-02 | 其他用户撤回医生 A 的申请 | 403，申请不变 |

| DOC-REL-P1-05 | 法人填写原因后驳回 `JOIN` | 状态为 `REJECTED`，关系仍不存在；医生看到审核意见并可重提 |

### 9.2 退出机构

前置条件：医生已加入 `I-01`。若需验证多机构，先通过正常关系申请加入 `I-02`。

步骤：

1. 医生选择“申请退出”，确认候选只包含当前有效机构；
2. 提交退出 `I-01`；
3. 在待审期间继续查看当前机构和相关权限；
4. 先执行一次法人驳回，核对关系仍有效；
5. 再次申请并由医生撤回，核对关系仍有效；
6. 第三次申请由法人批准；
7. 刷新医生上下文、档案、项目和订单；
8. 多机构场景下核对新主机构。

预期结果：

- `LEAVE/PENDING` 时 `I-01` 仍在当前机构列表，并标记“退出审核中”；
- 驳回或撤回只改变申请状态，关系继续有效；
- 批准后 `I-01` 的关系变为撤销，机构从当前列表和可见范围移除；
- 目标机构的 `doctor_projects` 绑定被物理删除，`doctor_institution_project_configs` 被软删除；
- 目标机构的 `doctor_project_change_requests` 按退出规则结束，不保留可继续处理的待审项目变更；
- 目标机构待处理的 `professional_project_requests` 变为 `REJECTED`，原因为“医生已退出机构”；
- 登录会话若以目标机构的 `DOCTOR` 为 `active_role`，则回退 `USER` 并清空机构上下文；
- 其他机构关系和历史订单不受影响；
- 如果退出的是主机构，系统从剩余有效关系中重新选择主机构；
- 如果没有剩余机构，主机构和机构摘要清空；
- 已撤销的机构重新出现在可加入候选中，可重新申请。

### 9.3 并发和失效边界

| 编号 | 场景 | 预期结果 |
|---|---|---|
| DOC-REL-P1-09 | 重复点击或两个客户端同时向同一机构提交 | 只产生一条 `PENDING`，其余请求返回冲突 |
| DOC-REL-P1-10 | 两名有权限审核人同时处理 | 一个成功，另一个 409；申请与关系无部分写入 |
| DOC-REL-P1-11 | 从 `LEG-P0-13` 前 `D-01` 身份有效、`I-01B` 已认证且 `L-01` 有任职的基线制作两个独立副本：JOIN 副本先让 `D-01` 向 `I-01B` 提交 JOIN，LEAVE 副本先批准该 JOIN 再提交 LEAVE；随后仅在副本中由 `A-01` 取消认证或删除 `I-01B` 后让 `L-01` 审核 | 两个副本中的批准和驳回均失败，申请保持 `PENDING`；LEAVE 副本原有效关系保留；分别丢弃副本，不破坏主夹具 |
| DOC-REL-P1-12 | 后端并发/服务测试令待审关系审核与医生身份失效竞争 | 正常身份撤销会被待审关系阻止，普通手工流程不可先造失效身份；并发测试应保证审核冲突且不产生部分关系 |
| DOC-REL-P1-13 | 法人身份或机构管理关系失效后继续审核 | 403，不改变申请 |
| DOC-REL-P1-14 | 请求包含未知字段、非法职业类型、非法动作或非法决定 | 400，不改变数据 |

## 10. P1 身份和关系撤销

### DOC-REVOKE-P1-01 有待审关系时撤销医生身份

步骤：医生先提交一条待审加入或退出申请，管理员随后撤销 `DOCTOR` 身份。

预期结果：

- 撤销被冲突阻止；
- 医生身份、档案认证状态、现有机构关系均不发生部分变化；
- 管理员先处理或由医生撤回待审申请后，才可再次执行撤销。

### DOC-REVOKE-P1-02 撤销医生身份后的完整结果

步骤：清空所有待审关系申请后，由平台管理员填写原因并撤销医生身份。`ACTIVE → REVOKED` 是正式管理员运营流程，不提供医生自助撤销入口。

预期结果：

- `user_roles.DOCTOR` 变为 `REVOKED`；
- 医生档案认证状态变为未认证；
- 全部医生机构关系撤销，并清理对应下游绑定；
- 登录会话若以 `DOCTOR` 为 `active_role`，则回退 `USER` 并清空机构上下文；
- “专业管理”中的医生功能组消失，或进入后显示没有可用专业能力；顶层“机构关系”仍可点击，但应提示当前没有可用专业身份；医生档案更新和关系申请接口均被拒绝；
- 普通用户登录、浏览和历史数据仍保留；
- 再次申请并获批时只恢复医生身份、档案认证和钱包，不自动恢复已撤销的机构关系。

### DOC-REVOKE-P1-03 撤销后重新认证不覆盖公开档案

步骤：撤销医生身份前记录医生自行编辑的公开档案；完成撤销后使用新申请重新认证并通过。

预期结果：

- 原有医生档案行被恢复认证，不创建重复医生档案；
- 新身份申请中的姓名、职称、理由和证书编号不会覆盖医生此前自行编辑的公开姓名、职称、简介或公开资历；
- 原 USD 钱包复用，不创建重复钱包；
- 已撤销机构关系不自动恢复，医生必须重新申请加入。

### DOC-REVOKE-P1-04 只撤销单个机构关系

步骤：医生同时加入 `I-01`、`I-02`；管理员在没有待审关系申请时撤销 `I-01` 的执业关系。

预期结果：

- 只撤销 `I-01`，`I-02` 保持有效；
- `I-01` 的项目绑定和待审下游业务按规则清理；
- 主机构正确重选；
- 如果该对关系有待审加入或退出申请，直接撤销应先被阻止。

## 16. 放行标准

- `DOC-P0-01` 至 `DOC-P0-14` 全部通过，或 `DOC-P0-14` 按预期保存安全阻断证据；
- 身份审批与机构关系审批职责正确，没有使用错误入口完成主流程；
- 私有认证材料没有进入公开医生档案或公开文件地址；
- 医生公开联系电话能够自行填写，且不会改变登录手机号；
- 未通过身份审核时不能使用医生能力，加入待审时不能提前获得机构权限；
- 待审身份的用户取消诉求由管理员以 `REJECTED + 原因` 代办；已生效身份仅由管理员执行 `REVOKE`，两类操作均完整留痕；
- 医生、机构法人、普通用户和其他机构法人之间不存在越权读取或写入；
- 重复提交、并发审核和撤销操作不会产生重复角色、档案、钱包或机构关系；
- P1 不存在影响身份、权限、隐私、关系状态或数据一致性的未解决问题；
- P2 排版和国际化问题不影响关键内容阅读、材料审核、提交、保存或撤回。
