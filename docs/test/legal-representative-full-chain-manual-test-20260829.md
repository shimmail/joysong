# 机构法人完整链路手工联调测试

最后更新：2026-08-29

统一执行入口：[全角色生命周期联调测试总流程](README.md)。本分册负责机构法人从普通用户到身份终态的独立完整链路；跨角色执行顺序和全局放行门槛以总流程为准。

相关用户说明：[机构法人用户指南](../guide/INSTITUTION_LEGAL_REPRESENTATIVE_USER_GUIDE.md)。

## 1. 测试目标

完整验证以下链路：

`普通用户注册 → 法人申请 → 私有材料上传 → 平台管理员审核 → 机构/法人关系/机构钱包初始化 → 机构公开档案 → 审核医生和顾问的 JOIN/LEAVE → 审核机构项目 → 多机构与越权 → 暂停/恢复 → 替代法人准备 → 平台管理员撤销法人身份 → 注销边界`

同时确认：

- 法人身份不等于平台管理员，基础平台角色仍为 `USER`；
- 法人审批通过后才获得对已批准任职机构的管理权；
- 法人只能审核本人管理机构的医生、顾问关系和机构项目申请；
- 法人认证私有材料不进入机构公开档案；
- 联系电话由申请人自行填写，可与登录手机号不同；
- 法人撤销不应误停用机构，也不应删除医生、顾问、项目、订单和机构钱包历史。

## 2. 状态分层与审核职责

测试记录必须分开三层状态，不得只记录页面上的一个“已认证”：

| 层级 | 本轮主状态 | 含义 |
|---|---|---|
| 账号 | `ACTIVE ↔ ADMIN_SUSPENDED`，或终态 `ERASED` | 决定是否能登录和写入 |
| 法人专业身份 | 无 → `PENDING` → `REJECTED/APPROVED` → `ACTIVE/REVOKED` | `PENDING` 由管理员批准或驳回；`ACTIVE` 仅由管理员撤销；决定法人专业能力是否开放 |
| 法人机构任职 | 无 → `APPROVED` → `REVOKED` | 决定 `managedInstitutionIds` 和具体机构管理范围 |

| 事项 | 发起人 | 正常审核人 | 标准入口 |
|---|---|---|---|
| 法人身份申请 | 普通用户 | 平台管理员 | Web 管理端“身份与入驻审核 → 身份申请” |
| 待审法人身份取消诉求 | 用户提出取消诉求，平台管理员代办 | 平台管理员 | 在身份申请审核页选择“驳回”，填写“申请人请求取消”等明确原因，终态记为 `REJECTED` |
| 医生、顾问 JOIN/LEAVE | 医生或顾问本人 | 目标机构法人 | 用户端“专业管理 → 法人 → 机构关系审核” |
| 平台项目创建申请 | 已认证医生 | 平台管理员 | Web 管理端平台项目申请审核 |
| 机构项目新增、加入、资料编辑 | 与机构有有效关系的医生 | 目标机构法人 | 用户端机构项目审核入口 |
| 已生效法人身份撤销 | 用户提出运营诉求或平台风控发起；撤销前必须完成替代法人交接 | 平台管理员 | Web 管理端“职业身份 → 撤销”，终态记为 `REVOKED` |

法人专业身份采用管理员运营模式：`PENDING` 申请只能由平台管理员批准或驳回；用户要求取消时，由管理员以 `REJECTED` 加明确原因代办，不使用 `WITHDRAWN`。`ACTIVE` 身份只能由平台管理员执行 `REVOKE`。该规则不改变医生、顾问本人发起或撤回机构 `JOIN/LEAVE` 的职责，也不改变机构法人对关系申请和项目申请的审核职责。

## 3. 当前可执行范围与已知阻断

| 结论 | 范围 |
|---|---|
| 可执行 | 注册、申请、管理员代办取消诉求、驳回后重申、管理员批准、机构/法人关系/钱包初始化、机构档案、关系审核、机构项目审核、跨机构拒绝、暂停/恢复、替代法人交接后由管理员撤销法人身份 |
| 条件可执行 | 多机构法人、替代法人关系由平台“机构管理/机构成员”路径在隔离环境准备；非生产环境中的账号注销边界 |
| 本期不适用（N/A） | 分账功能不启用；不执行分账配置、比例、双边提案或收益分配验收，项目价格和订单必要数据仍按本文件准备 |
| 当前阻断 | 生产账号注销固定关闭；交易阻断器未完整接入；系统尚未强制阻止“没有替代法人”的撤销，标准运营流程必须先完成替代法人交接 |

注意：平台管理员后端对部分机构关系审核具有兜底权限，但标准 GUI 主链路仍由目标机构法人审核。管理端旧“医生执业”页和旧顾问成员页不得代替新 `JOIN/LEAVE` 账本主链路。

3. 核对 `IPJ-01` 的机构项目、医生绑定和表中项目价格均按审核结果生效；
4. 加入：`D-01` 另行申请加入 `IPJ-02`，只填写服务说明、医生项目价格和备注，由 `L-01` 批准；
5. 资料编辑 R1：`D-01` 对 `IPJ-02` 提交 `PROFILE_UPDATE`，详情填 `IPJ-E2E-003-R1 待补充完整详情`、备注填 `IPJ-E2E-003-R1 资料编辑驳回分支`；`L-01` 使用第 5.5 节项目驳回文案拒绝；
6. 资料编辑 R2：`D-01` 按第 5.6 节 PROFILE_UPDATE 最终值创建新申请，`L-01` 批准；
7. 核对项目列表、详情和订单选项读取批准后的项目价格。

预期：

- `L-02` 不能审核 `I-01` 的项目申请；
- 新增 `IPJ-01` 批准后，机构项目、`D-01` 初始项目绑定和表中项目价格在同一业务结果中生效；
- 加入 `IPJ-02` 只新增医生项目绑定，不重复创建机构项目；
- 资料编辑审核只能接受或拒绝医生申请中的值；批准后医生价格为 `530.00`，机构基础价/原价为 `520.00/600.00`；
- 法人不能批准未通过平台审核的上游平台项目。

## 11. P0 医生与顾问退出机构审核

### LEG-P0-08 医生和顾问 LEAVE 驳回与批准

`D-01`、`C-01` 分别执行：

1. 提交第一笔 `LEAVE`，待审时验证 `I-01/APPROVED` 关系和既有权限继续有效；
2. `L-01` 驳回，记录原因，验证原关系不变；
3. 本人提交第二笔 LEAVE，`L-01` 批准；
4. 刷新个人上下文、机构公开列表、新业务候选和历史对象；
5. 尝试重新审核已驳回和已批准申请。
6. 为了验证后续法人撤销不误伤机构人员，`D-01`、`C-01` 分别新建 JOIN，由 `L-01` 批准后再进入第 12 节。

预期：

- `LEAVE/PENDING` 和 `LEAVE/REJECTED` 均不提前撤销实际关系；
- `LEAVE/APPROVED` 后实际关系为 `NONE`，当前机构和新业务候选中移除该专业人员；
- 历史关系申请及已存在订单快照保留；
- 重新加入必须新建 JOIN，不能复用旧申请；最后两人与 `I-01` 均恢复为 `APPROVED`。医生重新加入机构不会自动恢复已清理的机构项目绑定，后续需要另行申请加入 `IPJ-02`。

## 12. P0 多机构与越权收口

### LEG-P0-09 `I-01` 与 `I-02` 跨机构隔离

1. 核对前置阶段已经正常准备的 `L-02/I-02`：法人角色和唯一任职均为 `ACTIVE/APPROVED`；不得再次注册或重复提交法人申请；
2. 核对 `L-01.managedInstitutionIds={I-01}`、`L-02.managedInstitutionIds={I-02}`；
3. 两个法人交叉尝试查看和修改对方机构档案；
4. 准备明确的待审对象：`D-01`、`C-01` 分别向 `I-02` 提交 JOIN；由于第 11 节退出已清理 `D-01` 的医生项目绑定，`D-01` 再按总流程第 5.2 节的 JOIN 字段对 `I-01/IPJ-02` 提交申请，并把备注写为 `LEGAL-CROSS-SCOPE-001`；记录三个 requestId；
5. `L-01` 尝试查看/审核两笔 `I-02` JOIN，`L-02` 尝试查看/审核 `I-01/IPJ-02` JOIN；全部应被拒绝。随后由各自有权法人驳回对应申请，确认进入下一步前没有待审对象；
6. 为验证“页面打开后撤权”，先制作本轮隔离库的可恢复副本；只在副本中让 `L-02` 打开 `I-02` 页面后，由 `A-01` 撤销 `L-02/I-02` 法人任职，再刷新和提交审核；保存证据后丢弃副本，原库中的 `L-02/I-02` 保持有效供后续使用。

预期：跨机构列表不返回对方数据，猜测对象 ID 的详情和写操作被拒绝，三个待审对象只能由对应机构法人处理且清理后无残留；页面打开后的权限变化必须在刷新或写请求时重新校验，不依赖旧缓存。

### LEG-P0-10 `L-01` 多机构选择与审核范围

前置：`A-01` 按第 5.3 节在管理端创建已认证的 `I-01B`，再从“机构成员 → 新增任职关系”为 `L-01` 建立法人任职并点击“通过”；记录 institutionId 和 membershipId。

验证：

- `managedInstitutionIds` 同时包含 `I-01`、`I-01B`，但不包含 `I-02`；
- 进入档案和审核入口时有明确机构选择，不默认依赖列表顺序；
- 先由 `D-01` 向 `I-01B` 提交备注为 `LEGAL-MULTI-INST-001` 的医生 JOIN，记录 requestId；`L-01` 在选择 `I-01B` 后能看到并驳回该请求，而 `I-01` 审核列表不出现它；同时修改 `I-01` 档案不会交叉污染 `I-01B`；
- 三条关系均有效时先制作可恢复副本；只在副本中撤销 `L-01/I-01B` 任职，验证 `I-01` 仍在管理范围，保存证据后丢弃副本；原库继续保持 `I-01/I-01B` 两条任职有效；
- 机构钱包按机构 owner 分离，不得把两个机构余额合并为法人个人钱包。

## 13. P0 账号状态、替代法人与身份终态

### LEG-P0-11 法人账号暂停与恢复

在 `L-01` 身份和 `I-01/I-01B` 任职均有效时：

1. 保存旧 access token、refresh token、机构档案和待审列表证据；
2. `A-01` 暂停 `L-01`；
3. 使用旧 token 读取和写入机构档案、审核关系和项目申请，并尝试密码、验证码登录；
4. 使用其他账号查看 `I-01` 公开页、医生/顾问关系和机构项目；
5. `A-01` 恢复 `L-01`，先复用旧 token，再重新登录。

预期：

- 暂停后旧 access/refresh token 失效，所有登录方式被拒绝，不得只禁止页面入口；
- 法人专业身份、任职、机构、钱包、医生、顾问和项目不会因账号暂停被自动删除或撤销；
- 机构公开页仍可用，但如果没有第二法人，待审队列在暂停期间无人处理，记录运营连续性风险；
- 恢复后旧 token 仍不可用，必须重新登录；原 userId、身份和关系不变。

### LEG-P0-12 替代法人准备

1. `L-03` 使用第 5 节数据从普通用户提交法人申请，由 `A-01` 批准；
2. 将该批准创建的自有预备机构记录为 `I-03`，确认它不会因名称、地址或信用代码相似自动绑定 `I-01`；
3. `A-01` 通过平台“机构成员 → 新增任职关系”分别为 `L-03` 新增 `I-01`、`I-01B` 法人任职；
4. 确认新关系先为 `PENDING`，由 `A-01` 点击“通过”后才变为 `APPROVED`；
5. `L-03` 重新登录，验证可选择并管理 `I-03`、`I-01`、`I-01B` 三个机构，且不能管理 `I-02`。

预期：至少两条替代任职均为 `APPROVED` 后才能继续撤销 `L-01`。现有流程是平台人工覆盖路径，不得写成法人自助“转交机构”功能。

### LEG-P0-13 平台撤销 `L-01` 法人身份

前置：`L-03` 已可管理 `I-01/I-01B`，且保存撤销前机构、任职、钱包、医生、顾问、项目、订单及 `L-01` 会话证据。

1. `L-01` 先执行账号注销预检并记录 `PROFESSIONAL_ROLE/INSTITUTION_MEMBERSHIP` blocker；再保持 `I-01` 机构档案页和一张关系/项目审核页打开，保存旧 access/refresh token，并修改一个尚未保存的测试字段；
2. 先用空原因撤销，预期被拒绝；
3. `A-01` 使用第 5.5 节原因撤销 `L-01` 的 `INSTITUTION_LEGAL_REPRESENTATIVE`；
4. 在旧页面刷新并尝试保存、审核，同时用旧 token 发起读取和写请求；
5. 刷新 `L-01` 的身份总览、专业入口、机构范围和原会话上下文；
6. 使用 `L-03`、`U-01`、`D-01`、`C-01` 重新查看 `I-01/I-01B` 与关联对象。

预期：

- `L-01` 法人角色为 `REVOKED`，其对应法人任职为 `REVOKED`，`managedInstitutionIds` 不再包含 `I-01/I-01B`；
- 以法人为 active role 的会话回退到 `USER` 并清空法人机构上下文；
- `L-01` 普通用户资料和普通能力保留，但机构档案、关系审核、项目审核和机构钱包授权立即失效；
- 撤销前已打开的页面和旧 token 不能继续读取私有管理数据或提交写操作，未保存的测试字段不得落库；
- `I-01/I-01B` 保持已认证，机构钱包记录不删除；医生、顾问、项目和历史订单不被级联撤销；
- `L-03` 仍可管理目标 `I-01/I-01B` 及自有 `I-03`，合计三机构，且不能管理 `I-02`；
- 没有替代法人时不得执行正式撤销；若隔离风险用例发现系统仍允许撤销原法人，应记录高优先级缺陷，机构不得以无人处理审核队列的状态放行。

### LEG-P0-14 账号注销边界

本用例验证边界，不要在生产或含真实交易数据的 `L-01` 上强行完成注销。

| 阶段 | 操作 | 预期 |
|---|---|---|
| `LEG-P0-13` 第 1 步、法人身份和任职仍有效时 | `L-01` 进入账号注销预检 | 返回 `PROFESSIONAL_ROLE`、`INSTITUTION_MEMBERSHIP` 等 blocker；账号、身份、机构和关系不变；本行只引用已保存证据，不在撤销后重复构造 |
| 生产环境 | 发起注销 | 当前功能固定禁用并返回 503，不得使用开关或数据库绕过 |
| 法人撤销且替代关系已生效后 | 非生产隔离环境再做预检 | 仍必须检查待审申请、任职、专业角色和交易 blocker；任一存在即不注销 |
| `L-B02` 完成 `LEG-P1-11` 负向验证后 | 注销预检 | 唯一任职仍为 `APPROVED`，必须返回 `PROFESSIONAL_ROLE/INSTITUTION_MEMBERSHIP`，不能继续注销 |
| 仅在可恢复副本中先为 `L-B02` 的机构准备已批准替代法人，再由 `A-01` 撤销其法人角色，并确认无待审、无交易、无评价和私信 | 非生产隔离环境可选执行完整注销 | 旧账号进入 `ERASED`、旧会话失效；机构及替代法人关系保留，原手机号重新注册产生不同 userId |

当前交易 blocker 尚未完整接入。即使非生产夹具通过，也不能宣称“法人及机构全部业务数据已完成注销清理”。全局 `ERASED` 终态仍以总流程的专用普通账号用例为基准。

## 18. 探索性风险用例

这些场景用于发现当前实现缺口，不作为主链路放行前的唯一阻塞条件。

| 编号 | 场景 | 观察与判定 |
|---|---|---|
| IP-RISK-01 | 联系电话填写纯文字或明显无效号码 | 当前前后端可能接受；记录是否需要格式或必填校验 |
| IP-RISK-02 | 名称超过200字、地址超过500字、城市超过100字、电话超过50字、营业时间超过200字 | 应返回友好校验且不覆盖原数据；如出现500或数据库错误，记录后端校验缺口 |
| IP-RISK-03 | 两台设备同时打开同一档案，设备1保存后设备2再保存旧快照 | 当前为完整覆盖且没有版本冲突；若后保存静默覆盖先保存，记录并发丢失更新风险 |
| IP-RISK-04 | 图片上传成功后不保存档案，直接离开页面 | 检查是否产生无法从档案删除的孤立公开文件 |
| IP-RISK-05 | 保存后立即查看公开页 | 应读取新数据；如仍显示旧内容，记录缓存刷新问题 |
| IP-RISK-06 | 法人直接修改机构公开资质后保存 | 当前不需要再次审核；确认这是否符合产品合规要求 |
| LEG-RISK-01 | 两个法人使用相同或近似机构名称、信用代码分别申请并批准 | 当前初始化逻辑不依据名称或信用代码自动合并，可能创建两个机构；记录主体去重与人工处置风险 |
| LEG-RISK-02 | 多机构法人撤销后再认证 | 当前只恢复一条历史法人任职；如恢复对象不符合业务预期，记录为严重归属风险 |
| LEG-RISK-03 | 撤销唯一法人或暂停唯一法人 | 机构仍公开且人员、项目不变，但审核和运营管理可能中断；应增加替代法人或交接前置 |
| LEG-RISK-04 | 待审法人账号先被暂停，再由管理员批准申请 | 可能在不可登录账号上激活角色、创建机构与钱包；需明确是拒绝审核还是允许准备 |
| LEG-RISK-05 | 撤销法人后执行账号注销 | 本地 blocker 仅看有效身份/任职等数据，机构及机构钱包并不因用户注销自动删除；必须先明确法人历史、审核记录和机构保留政策 |
| LEG-RISK-06 | 法人撤销时仍有待审医生/顾问/项目申请 | 当前法人撤销没有完整的审核队列交接校验；请求可能保留并等待其他法人处理 |
| LEG-RISK-07 | 法人申请、任职、暂停、恢复和撤销的管理员审计 | 核对操作人、原因、时间和对象 ID；当前账号管理审计尚未完整时明确记录缺口 |

## 20. 放行标准

### 身份与机构管理基线

- `LEG-P0-01`至`LEG-P0-13`、`IP-P0-01`至`IP-P0-09` 全部通过；
- 批准只生成一个初始机构、一条初始法人任职和一个机构钱包；
- 法人不获得平台管理员权限，医生、顾问和异机构法人不存在越权；
- 医生、顾问的 JOIN/LEAVE 及机构项目申请没有提前生效、重复生效或跨机构审核；
- 机构联系电话由法人自行填写，不改变登录手机号；私有法人材料不进入公开机构档案；
- P1 无会导致机构归属错误、权限残留、重复资产或隐私泄露的未解决问题；P2 问题不影响申请、审核、保存和撤销。

### 运营连续性门槛

- 暂停、恢复及旧 token 失效结果符合 `LEG-P0-11`；
- 撤销主法人前，`L-03` 的 `I-01/I-01B` 任职已实际批准并完成登录验证；
- 撤销只关闭 `L-01` 法人权限，不误删机构、钱包、医生、顾问、项目和历史订单；
- 唯一法人暂停/撤销、多机构再认证恢复对象和待审队列交接的产品规则已明确，不得用人工解释掩盖系统缺口。

### 完整生命周期声明

法人专业身份采用正式管理员运营流程：待审取消诉求以 `REJECTED + 原因` 代办，生效身份仅由管理员在替代法人交接完成后执行 `REVOKE`，两项均不再作为产品阻断。`LEG-P0-14` 按当前边界得到预期 blocker 仍只能证明“没有误注销”；在以下项目完成前，不得宣称法人账号注销和机构交接保护已经完整闭环：

- 撤销唯一法人前的替代人或审核队列交接保护；
- 生产账号注销开放，以及真实订单、支付、退款、钱包和结算 blocker 完整接入；
- 法人申请、任职变更、暂停/恢复和身份撤销的完整、可追踪管理审计。
