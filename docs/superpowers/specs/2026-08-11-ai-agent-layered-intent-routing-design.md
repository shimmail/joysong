# AI Agent 分层意图识别设计

## 目标

优化 AI Agent 的中英文意图识别顺序，确保当前消息中的明确表达优先于历史上下文，同时减少不必要的大模型解析调用。路由顺序固定为：当前消息关键词匹配、上下文补全、大模型兜底。

## 范围

本次只调整服务端 Agent 意图路由、意图模型名称配置与相关测试，不改变对外 REST 契约、意图枚举、数据库结构或 Flutter 展示逻辑。继续使用现有 `AgentIntentRouter`、`AgentRouteAssessment` 和 `ChatService` 编排边界，不引入新的 NLP 框架或运行时依赖。

## 路由原则

### 第一层：当前消息判别

路由器首先仅分析当前用户消息，不拼接或读取历史消息。分析过程包括：

- 对中英文文本进行大小写、空白和常见标点归一化；
- 识别意图关键词、查询目标关键词、安全关键词和约束词；
- 识别中英文否定表达及其有限作用域；
- 分别产出当前消息已明确的 `intent` 和 `queryTarget`；
- 记录冲突、指代不明和低置信度等歧义原因。

当前消息一旦明确给出意图或目标，上下文和大模型都不得覆盖。例如，历史在讨论医生，而当前消息为“对比一下机构”，结果必须是 `COMPARISON + INSTITUTION`。

安全信号保持最高优先级，但被明确否定的安全状态不触发 `SAFETY_SCREENING`。例如“我没有怀孕，想比较项目”和 “I am not pregnant; compare treatments” 应忽略被否定的怀孕信号，再根据剩余内容识别为项目对比。

### 否定识别

否定识别采用可审计的规则和有限作用域，不因句中出现一个否定词而反转整句：

- 中文否定词覆盖“不、不要、不想、不是、没有、无需、别”等常见表达；
- 英文覆盖 `no`、`not`、`don't`、`do not`、`isn't`、`is not`、`without` 等常见表达；
- 否定作用于其后邻近的关键词或已知短语，并在转折词、分隔符或新的明确动作处停止；
- 被否定的目标、意图或安全词不参与正向匹配；
- 双重否定、否定范围不清或状态时间含糊时，不强行反转，记录歧义并交给后续层处理。

示例：

- “不看医生，推荐机构”识别为 `CATALOG_QA + INSTITUTION`；
- “不要方案，只比较项目”识别为 `COMPARISON + PROJECT`；
- “I don't want a doctor; show me clinics”识别为 `CATALOG_QA + INSTITUTION`；
- “Don't compare them, just summarize”不匹配比较意图，按剩余表达识别总结意图。

### 第二层：上下文补全

只有当前消息缺少意图或目标时才读取上下文。上下文来源保持有界，优先使用最近有效路由结果和会话摘要中的结构化主题，不把完整历史文本直接拼成第一层查询。

上下文只能填写缺失字段，不能修改第一层已经明确的字段。例如，上一轮讨论热玛吉医生，当前消息为“对比一下”，可以补全为 `COMPARISON + DOCTOR`；当前消息若为“对比机构”，则不得继承 `DOCTOR`。

如果上下文包含多个相互冲突的候选，保留本地最高可信候选并记录 `CONFLICTING_CONTEXT`，进入第三层。

### 第三层：大模型兜底

仅当经过前两层后仍存在目标冲突、指代不明、否定范围不清或置信度不足时，且意图解析开关已启用，才调用大模型结构化解析。

传给模型的约束包括第一层已确定字段、允许的意图和目标枚举、当前消息以及必要的有界上下文。模型只能补全未确定字段，不能覆盖当前消息明确字段，也不能降低本地检测到的未否定安全信号。

若模型调用失败、超时、返回非法枚举或结构不完整，则使用第二层形成的本地最佳判断继续生成响应，不因意图解析失败而使整个请求失败。模型返回的额外搜索关键词仅在解析结果有效时使用。

意图解析允许单独配置模型名称，例如通过 `OPENAI_INTENT_MODEL` 映射到 Agent 配置属性。未设置或为空时回退到主 Agent 的 `AI_AGENT_MODEL`，保持现有部署兼容性。除模型名称外，意图解析必须复用主 Agent 的 API Key、Base URL、代理、连接与读取超时、客户端安全策略和供应商协议，不增加第二套模型服务连接配置。

## 组件调整

### `AgentIntentRouter`

将当前一次性 `contains` 判别拆为内部小步骤，但保持公开职责集中：

- 当前消息归一化；
- 否定作用域标注；
- 未否定关键词匹配；
- 当前消息字段判别与置信度评估；
- 用结构化上下文补全缺失字段；
- 校验模型返回并合并未确定字段。

可在 `AgentRouteAssessment` 中增加路由来源或字段确定性信息；若现有调用方不需要公开该信息，则使用内部数据类，避免扩大跨模块接口。

### `ChatService`

调整 `generateTurn` 的顺序：

1. 用原始 `content` 执行第一层路由；
2. 仅在字段缺失时，从最近消息或摘要提取有界上下文并执行第二层；
3. 仅在最终评估要求时调用 `parseAmbiguousRoute`；
4. 合并结果后再构造目录搜索查询和生成提示词。

现有机构项目名称的数据库命中补偿保留，但仅用于补全未识别的目标，不能覆盖当前消息已经明确的其他目标。

### Agent 模型配置

在现有 Agent 配置对象中增加可选的意图模型名称。意图解析调用选择“显式意图模型，否则主 Agent 模型”，最终回答生成始终使用主 Agent 模型。两类调用共享同一个受控 HTTP 客户端及除模型名称外的全部 Agent 配置，避免密钥、端点、代理或超时策略发生漂移。

### 会话上下文

优先复用 `AgentSessionSummary.unresolvedTopics` 中已校验的结构化路由主题。最近用户消息只在摘要不足时作为有界补充，并且只用于第二层。上下文读取失败时直接保留第一层结果，不影响本地路由。

## 数据流

用户消息先进入当前消息分析器，得到已确定字段、未确定字段、置信度和歧义原因。若字段完整且无关键歧义，直接形成最终路由。否则，上下文补全器只填写空缺字段并重新评估。仍不明确时调用大模型解析器，校验其结构化输出后只合并空缺字段。任何模型异常都回退到上下文层的本地最佳结果。最终路由再驱动目录搜索、提示词构建和回答生成。

## 错误与安全处理

- 未否定的安全关键词始终优先，模型不得降级安全路由；
- 明确否定的安全关键词不触发安全路由，但含糊否定进入兜底；
- 上下文加载或解析失败不阻断请求；
- 大模型解析失败不阻断请求，记录受控诊断信息并使用本地结果；
- 意图模型名称为空时使用主 Agent 模型；显式模型被供应商拒绝时按模型调用失败处理并使用本地最佳路由，不建立独立端点或密钥配置；
- 日志不记录完整敏感对话，只记录意图、目标、路由层级、置信度、歧义代码和回退分类。

## 测试策略

首先扩展 `AgentIntentRouterTest`，覆盖：

- 中文与英文明确关键词；
- 中英文目标否定、意图否定和安全否定；
- 否定后转折并出现新的正向意图；
- 当前明确字段不被上下文覆盖；
- 当前缺失字段由上下文补全；
- 多目标冲突、指代不明和否定范围不清；
- 未否定安全信号始终优先。

然后扩展最接近 `ChatService` 路由编排的测试，验证：

- 明确当前消息不调用模型解析；
- 只有上下文补全仍不确定时才调用模型；
- 模型只能补全缺失字段；
- 模型失败或非法输出时采用本地最佳判断继续响应；
- 显式配置意图模型时，只有意图解析调用使用该模型，最终回答仍使用主 Agent 模型；
- 未配置意图模型时，两类调用均使用主 Agent 模型；
- 意图解析与回答生成复用相同的端点、密钥、代理和超时配置；
- 机构项目数据库命中不会覆盖当前明确目标。

相关测试通过后，按项目规则最多执行一次服务端全量测试；不涉及迁移，因此不启动数据库迁移验证。

## 验收标准

- 路由严格遵循“当前消息关键词、上下文补全、大模型兜底”的顺序；
- 当前消息的明确意图和目标不被历史或模型覆盖；
- 中英文常见否定表达不会产生被否定关键词的正向匹配；
- 明确否定的安全状态不触发 `SAFETY_SCREENING`；
- 模糊输入仍可使用上下文和模型补全；
- 意图模型不可用时请求使用本地最佳判断继续完成；
- 意图解析可独立选择模型名称，未配置时回退主 Agent 模型，其他连接配置与主 Agent 完全一致；
- 无新增运行时依赖、数据库迁移或客户端契约变化。
