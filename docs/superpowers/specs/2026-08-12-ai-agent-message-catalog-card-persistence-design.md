# AI Agent 消息卡片持久化设计

## 目标

AI Agent 回答引用医生、机构、项目或机构项目时，将轻量卡片绑定到产生引用的 AI 消息。卡片在继续对话后仍保留，重新进入会话并加载历史消息时仍显示在原消息下方。

本次支持以下四类目录卡片：

- `DOCTOR`
- `INSTITUTION`
- `PROJECT`
- `INSTITUTION_PROJECT`

未知类型不展示。卡片只承担识别与跳转作用，不承载分析报告、详细属性或咨询操作。

## 现状与问题

发送消息接口返回的 `ChatTurnResponse` 已包含 `catalogItems` 和 `catalogReport`。后端完成回合时，也已将这些字段写入 assistant 消息的 `metadata_json`，幂等重放能够从元数据恢复。

但历史消息接口只返回消息正文和基础字段，Flutter 状态又只保存一个 `latestTurn`。页面把该回合的卡片统一渲染在消息列表底部，并在下一次发送或重新打开会话时清空。因此卡片没有稳定归属，也无法从历史恢复。

## 选定方案

扩展历史消息契约，把已持久化的目录引用投影到对应的 assistant 消息；Flutter 将卡片作为消息数据的一部分渲染。

不新增卡片表或数据库迁移。现有 `agent_messages.metadata_json` 是卡片引用的唯一持久化来源。

## 后端设计

### 历史消息响应

在 `ChatMessageResponse` 中增加可选或默认空列表字段：

```text
catalogItems: List<AgentCatalogItemResponse> = []
```

历史消息映射规则：

- USER 消息始终返回空列表。
- ASSISTANT 消息从 `metadata_json.catalogItems` 恢复目录引用。
- 仅保留 `DOCTOR`、`INSTITUTION`、`PROJECT`、`INSTITUTION_PROJECT`。
- 旧消息的元数据为空、缺少字段或无法解析时，返回空列表，不让整个历史请求失败。
- 保持现有消息顺序、分页和最近消息限制不变。

发送消息接口继续返回 `ChatTurnResponse`，以避免破坏现有客户端流程。其 `message.catalogItems` 与顶层 `catalogItems` 应表达同一组经过类型过滤的引用；Flutter以消息字段作为最终展示来源。

### 持久化与兼容性

回合完成时继续把目录引用写入 assistant 消息元数据。历史恢复和幂等重放共用相同的安全解析逻辑，避免两套投影规则漂移。

“持久化”沿用当前聊天消息保留策略：卡片与所属消息同生共灭，受最近 20 条和 7 天等既有清理策略约束。清空消息、删除回合或删除会话时，卡片随消息删除。

## Flutter 设计

### 消息模型与状态

`ChatMessage` 增加 `catalogItems`，JSON 解码缺省为空列表。

收到新 `ChatTurn` 后，将顶层目录引用合并进返回的 assistant 消息，再追加到消息列表。加载历史时直接使用每条消息自带的目录引用。

移除卡片展示对单一 `latestTurn` 的依赖。下一轮发送可以更新当前投递状态，但不得删除旧 assistant 消息中的卡片。

### 渲染位置

消息列表按顺序渲染：

1. AI 消息气泡。
2. 该消息的轻量目录卡片列表。
3. 下一条聊天消息。

USER 消息不渲染目录卡片。Flutter 在渲染边界再次过滤允许类型，防止旧服务端或异常数据显示医生及未知卡片。

### 卡片外观与交互

卡片参考发现页的视觉语言，但不强行复用要求完整 `DiscoverItem` 的组件。保留 Agent 目录项到详情页所需的轻量适配，避免额外请求和重复模型。

每张卡片只显示：

- 类型视觉标识或占位图。
- 名称。
- 可选的一行副标题。
- 表示可进入详情的尾部箭头。

整张卡片可点击，复用现有跳转回调：

- 医生跳转医生详情。
- 机构跳转机构详情。
- 项目跳转项目详情。
- 机构项目使用 `institutionId + projectId` 跳转对应详情。

不显示 attributes、summary、报告标题、报告摘要、对比表、warnings、真人咨询或单独的“查看详情”按钮。缺少跳转所需 ID 的项目不响应点击；卡片仍可安全展示名称，不附加错误信息。

## 错误处理

- 历史元数据解析失败仅丢弃该消息的卡片，不丢弃消息正文。
- 单个目录项解析失败或类型不支持时跳过该项，不影响同一消息的其他卡片。
- Flutter 收到缺少 `catalogItems` 的旧响应时按空列表处理。
- 卡片跳转参数不完整时禁用点击，不发起无效导航。

## 测试范围

### 后端

- 完成带目录引用的回合后再发送普通消息，历史接口仍在第一条 assistant 消息返回卡片。
- 四种允许类型被保留，未知类型被过滤。
- USER 消息不返回卡片。
- 空、缺字段或异常 `metadata_json` 不导致历史接口失败。
- 幂等重放和历史恢复使用一致的卡片投影。

### Flutter

- `ChatMessage` 可解析历史响应中的目录引用，缺省字段为空列表。
- 连续发送两轮后，第一轮卡片仍显示在原 AI 消息下。
- 重新打开会话后，历史卡片恢复在原消息下。
- 四种允许类型整卡点击触发现有跳转回调；未知类型不渲染。
- 属性、摘要、报告信息、真人咨询和独立详情按钮不显示。
- 跳转 ID 不完整时不触发回调。

## 非目标

- 不恢复或新增 SSE 流式接口。
- 不新增目录卡片数据库表或迁移。
- 不在卡片中展示价格、评分、完整图片或其他需要额外接口取数的信息。
- 不改变现有聊天消息保留、清理和分页策略。
