# 医美顾问全端命名与分账配置设计

## 目标

将真人职业身份 `CONSULTANT` 的产品名称在管理端、Flutter 客户端、服务端用户提示和业务文档中统一为“医美顾问”，消除“咨询师”“机构咨询师”“顾问”等混用。同时明确订单所选医美顾问是现有顾问分账的受益方，修正分账配置页面对 `commissionRate` 的错误解释，并在保存配置前保证四方比例有效。

## 核心定义

- `user_roles` 中有效的 `CONSULTANT` 表示用户拥有医美顾问职业身份。
- `institution_memberships` 中 `member_role = 'CONSULTANT'` 且 `status = 'APPROVED'` 表示该医美顾问已获对应机构确认，可以服务该机构。
- “机构咨询师”不是第二种职业身份；需要表达机构范围时，产品文案使用“该机构的医美顾问”。
- 同一医美顾问可以拥有多家机构的有效任职关系。
- `commissionRate` / `commission_rate` 的既有业务含义统一确认为医美顾问分账比例，不是医生或项目发布者分账比例。

## 兼容边界

本次不修改以下内部契约：

- 角色编码 `CONSULTANT`；
- API 路径中的 `/consultants`；
- `consultantId`、`consultantName`、`consultantAmount`、`consultantRate`、`commissionRate` 等字段；
- `CONSULTANT_PROOF` 材料编码；
- `user_roles`、`institution_memberships`、订单快照及结算表结构。

不修改已经执行的 Flyway 迁移文件及 checksum，不新增数据库迁移。AI 聊天人格中的 `CONSULTANT` 与真人职业身份相互独立，不在本次产品改名范围内。

## 身份与机构关系

医美顾问的职业身份与机构任职关系继续分层管理：

1. 用户通过身份申请和审核取得有效 `CONSULTANT` 职业身份。
2. 管理员通过现有“新增任职关系”将已认证医美顾问加入机构。
3. 预约只返回目标机构已批准的医美顾问。
4. 创建订单时固化 `consultantId` 和 `consultantName`。
5. 医美顾问后续离开机构时，历史订单快照及已形成的分账归属不发生变化。

管理端删除专用“添加咨询师”按钮、弹窗及其专用候选加载和提交状态代码。保留通用“新增任职关系”入口，并继续允许选择已经取得有效 `CONSULTANT` 身份的用户。

后端 `POST /api/admin/identity/consultants`、原子绑定服务及现有测试保持不变，用于 API 兼容；本次只移除管理端入口，不通过后端强制取消管理员直绑能力。

## 全端产品文案

### 管理端

- 身份申请、职业身份和机构成员列表将 `CONSULTANT` 显示为“医美顾问”。
- 删除“添加咨询师”专用入口及弹窗。
- 页面说明中的真人“顾问”统一为“医美顾问”。
- “咨询师佣金比例”或“医生/项目发布者佣金比例”统一为“医美顾问分账比例”。
- “咨询师佣金”统一为“医美顾问分账金额”。
- “医生佣金”统一为“医生分账金额”或“医生分账比例”。

### Flutter

- 身份中心将 `CONSULTANT` 显示为“医美顾问”。
- 预约页面使用“选择医美顾问”和“该机构暂时没有可预约的医美顾问”。
- 预约校验提示使用“请选择医美顾问”。
- 身份申请材料显示为“医美顾问证明”。

### 服务端与文档

- 用户可见错误使用“医美顾问”，例如“所选医美顾问未加入该机构或尚未确认”“订单必须关联医美顾问”。
- 业务文档统一真人职业身份名称，同时保留代码示例中的既有英文标识。
- 医美顾问继续被定义为非医师，不因名称统一获得诊断、处方或医疗执业权限。

## 订单与分账语义

订单继续从机构已批准成员中选择医美顾问，并固化医美顾问快照。最终结算中的 `consultantAmount` 明确归属于订单快照中的医美顾问。

本次沿用现有分账计算、比例配置和金额舍入规则，不新增钱包、提现或实际支付渠道。分账提案仍只由医生与合作医疗机构双方协商和确认；医美顾问是订单分账受益方，不新增提案确认权限。

## 分账策略接口

新增只读接口：

```http
GET /api/admin/order-split-policy
```

响应继续使用 `BaseResponse`，数据结构为：

```json
{
  "platformRate": 40.00
}
```

`platformRate` 必须来自 `OrderSplitProperties`。管理端不硬编码 40%，当前默认配置为 40%。项目分账配置和分账协商页面均在编辑或提交前读取该策略。

该接口只允许现有分账配置参与者访问，沿用项目分账配置与提案页面的认证和数据访问边界，不作为公开接口。服务端同时验证平台配置位于 `0～100` 且最多两位小数；配置非法时接口明确失败，不向管理端返回可继续使用的比例。

策略加载失败时，页面不得使用猜测值继续计算，必须显示加载错误并禁用保存或提交。

## 比例配置与计算

项目分账配置及分账提案统一展示四方比例：

- 平台分账比例：服务端提供，只读；
- 合作医疗机构分成比例：可填写，继续使用 `institutionRate`；
- 医美顾问分账比例：可填写，继续使用 `commissionRate`；
- 医生分账比例：实时派生，只读，不提交。

计算公式为：

```text
医生分账比例 = 100% - 平台分账比例 - 合作医疗机构分成比例 - 医美顾问分账比例
```

例如平台 40%、机构 35%、医美顾问 10%，医生分账比例为 15%。

管理端以百分比基点计算，例如 `10.25% = 1025`，避免 JavaScript 浮点误差。所有比例最多保留两位小数。

API 请求继续只提交 `commissionRate` 和 `institutionRate`，不增加 `doctorRate` 请求字段。医生比例由服务端使用当前平台配置重新计算，不能信任客户端派生值。

## 共享校验

后端建立单一的分账比例计算与校验组件，由分账策略查询、管理员直接保存、分账提案和最终结算共同使用。校验规则为：

- 平台、机构和医美顾问比例分别位于 `0～100`；
- 机构和医美顾问输入最多两位小数；
- `平台比例 + 机构比例 + 医美顾问比例 <= 100%`；
- 合计等于 100% 时医生比例为 0%，允许保存；
- 合计超过 100% 时，在保存配置或提交提案时立即拒绝。

统一错误提示为：

> 平台、合作医疗机构和医美顾问分账比例合计不能超过 100%

最终结算继续执行防御性校验。金额仍分别计算平台、机构和医美顾问分账，医生取得最终金额余数，保证四方金额之和严格等于订单可分账金额。

如果已有历史配置在当前平台比例下产生负数医生比例，列表保留可见但标记“配置无效”；该配置再次编辑时必须修正后才能保存，最终结算继续拒绝无效配置。

## 测试设计

### 后端

- 分账策略接口返回 `OrderSplitProperties` 中的实际平台比例，证明没有写死 40%。
- `40 + 35 + 10 + 15 = 100`，医生比例正确派生。
- 平台、机构和医美顾问合计正好 100% 时医生比例为 0%，允许保存。
- 管理员直接配置和分账提案均拒绝合计超过 100% 的输入。
- 小数比例及金额舍入后，平台、机构、医美顾问和医生金额总和不变。
- 无项目配置时保持当前默认结果：平台 40%、机构 40%、医美顾问 0%、医生 20%。
- 医美顾问机构关系、订单快照和历史订单结算语义继续通过现有测试。

### 管理端

- 抽取纯比例计算函数，并使用轻量 Vitest 覆盖正常值、两位小数、医生比例为 0 和超限输入。
- 验证两个配置页面继续提交 `commissionRate` 和 `institutionRate`，不提交派生的 `doctorRate`。
- 验证平台策略加载失败时禁止提交。
- 执行管理端测试、TypeScript build 和 lint。

### Flutter

- 验证 `CONSULTANT` 的展示名称为“医美顾问”。
- 更新预约校验、选择标题和空状态文案断言。
- 保留 `/consultants` API 路径测试，证明内部契约未变。
- 执行相关 Flutter 测试和静态分析。

### 回归验证

- 执行后端完整测试和现有 MySQL Testcontainers 集成测试。
- 验证管理端不再出现专用“添加咨询师”入口。
- 验证分账配置、分账提案、订单创建和最终结算的既有权限边界未改变。

## 非目标

- 不更名内部 `CONSULTANT`、`consultant*` 或 `commissionRate` 标识。
- 不删除机构任职关系。
- 不改变平台、机构、医美顾问或医生的既有分账算法。
- 不按具体医美顾问配置个性化比例；比例仍按医生与机构项目维度配置。
- 不让医美顾问参与分账提案确认。
- 不新增钱包、提现、支付渠道或实际打款流程。
- 不修改 AI 医美助手人格。

## 验收标准

1. 全端真人 `CONSULTANT` 产品名称统一为“医美顾问”，不存在面向用户的“机构咨询师”身份。
2. 管理端专用“添加咨询师”按钮及弹窗消失，通用任职关系流程仍可绑定已认证医美顾问。
3. 两个分账配置页面将 `commissionRate` 显示和填写为“医美顾问分账比例”。
4. 管理端只读展示服务端平台比例，并实时显示只读医生剩余比例。
5. 任一保存入口都不能持久化会使医生比例为负的配置。
6. 订单所选医美顾问继续获得现有顾问分账金额，四方金额之和保持不变。
7. API、数据库结构、Flyway checksum 和历史订单快照保持兼容。
