# AI Agent 多标签意图与否定作用域加固设计

## 目标

在现有“当前消息关键词、上下文补全、大模型兜底”的路由顺序上，将当前的单意图、全局确定性模型重构为多标签、逐标签确定性模型。路由器使用全句扫描发现中英文意图、目标和安全标签，再通过轻量句式约束判断每个标签自身的肯定、否定或不确定状态。当前消息中的明确标签必须保持锁定，任何其他标签的歧义都不能将其解锁。

## 范围

本轮修改服务端 `AgentIntentRouter`、`ChatService` 及其既有测试。保留现有 `AgentIntentDecision.intent` 和 `queryTarget` 作为兼容主路由，不改变 REST 合同、数据库、会话持久化结构、Flutter 客户端或运行时依赖。多标签证据先作为服务端内部编排数据，供下游提示词和决策逻辑使用。

## 核心模型

新增逐标签证据模型，至少记录：

- 标签类型和值：意图、目标或安全约束；
- 极性：`POSITIVE`、`NEGATIVE`、`UNCERTAIN`；
- 确定性：明确或待补全；
- 来源：当前消息、上下文或大模型；
- 是否锁定：当前消息中的明确正向或明确否定证据不可被后续层覆盖。

`AgentRouteAssessment` 保存完整标签证据集合，同时保留由统一策略选择出的 `decision`。旧的全局 `explicitIntent` 和 `explicitQueryTarget` 只作为兼容派生值，不再参与合并授权；真正的覆盖权限由每个标签自身的状态决定。

## 全句扫描与轻量句式约束

路由器先对完整当前消息执行一次中英文信号扫描，保留所有命中，不按优先级立即压缩。英文匹配使用词边界并覆盖常见单复数形式。

扫描后使用轻量句式约束确定否定作用域：

- 动作否定优先绑定动作，例如 `don't compare`、`不要比较`；
- 状态否定优先绑定状态实体，例如 `not pregnant`、`没有怀孕`；
- `don't know if`、`not sure whether`、`不确定是否`标记相关状态为不确定，而不是明确否定；
- `while`、`but`、`instead`、`同时`、`但是`、`而是`等连接词用于结束或转换作用域；
- 双重否定或无法唯一绑定的表达只将相关候选标签标记为不确定；
- 不得把某个否定词机械绑定到其后任意类别的第一个路由关键词。

例如：

- `Don't compare treatments while pregnant`：比较意图为否定，怀孕安全标签为明确正向；
- `I don't know if I am pregnant`：怀孕安全标签为不确定，进入兜底；
- `I am not pregnant; compare treatments`：安全标签为明确否定，比较和项目标签为明确正向；
- `I do not not want a doctor; compare clinics`：医生相关标签不确定，但明确的 `COMPARISON + INSTITUTION` 保持锁定。

## 多意图与主路由

同一消息可以产生多个正向意图标签。例如：

- “怀孕期间比较两个机构”产生 `SAFETY_SCREENING`、`COMPARISON` 和目标 `INSTITUTION`；
- “比较这些项目并制定方案”产生 `COMPARISON`、`PLANNING` 和目标 `PROJECT`。

完整标签集合交由下游进一步决策。为兼容现有消费者，新增单一 `selectPrimary` 策略产生主路由：明确或经兜底确认的安全标签优先，其余意图沿用现有业务优先级。主路由选择不能删除其他标签；搜索、提示词或后续编排仍可读取完整集合。

## 上下文与大模型合并

上下文和大模型按标签合并：

- 只能补充缺失或不确定的标签；
- 不能删除、替换或降级当前消息中已锁定的标签；
- 一个标签的歧义不能影响其他标签的锁定状态；
- 未否定的安全标签不得被降级；
- 不确定安全状态允许经大模型升级为安全标签，而不要求模型返回与主路由相同的目标；
- 模型失败、超时或输出非法时继续使用本地标签和主路由。

解析器在过渡期兼容现有单一 `intent` 字段，并可接受可选的 `intents` 数组。模型结果转换为标签证据后再合并，不直接替换整个 `AgentIntentDecision`。意图解析继续保持 3 秒连接、8 秒读取快速超时，只共享主 Agent 的 Key、Base URL、代理和 HTTP 安全策略；模型名称仍可单独配置。

## 下游兼容

现有搜索策略、生成档位、安全提示、规划边界、报告展示、持久化和 REST 返回继续消费主路由，避免本轮扩大接口或迁移范围。完整多标签集合至少注入生成提示词，并留给内部下游编排决策。若未来需要向客户端公开多标签，再以可选字段和版本化摘要单独演进。

## 测试策略

先扩展 `AgentIntentRouterTest`，用失败测试覆盖：

- 中英文动作否定、状态否定、不确定句式、双重否定和连接词边界；
- 一个标签的歧义不会解锁其他明确意图或目标；
- 单句产生多个意图与目标标签；
- 安全与业务意图并存时完整标签保留、主路由稳定；
- 英文单复数和词边界不回归；
- 上下文只补充缺失标签。

再扩展 `AgentWorkflowCoreTest`，覆盖：

- 大模型只能补充不确定标签；
- 不确定安全状态可在生产合并路径升级；
- 完整标签进入下游提示词；
- 现有主路由仍控制搜索、安全和规划行为；
- 解析器失败继续本地响应。

按项目规则先运行最小相关测试类，相关测试通过后最多运行一次后端全量测试。本轮不涉及迁移或数据库测试。

## 验收标准

- 全句扫描能够保留多个中英文意图、目标和安全标签；
- 否定与不确定作用域由轻量句式约束决定，不再采用“后续第一个关键词”机制；
- 标签确定性和锁定状态彼此独立，不存在全局解锁；
- 当前消息明确标签不被历史或大模型覆盖；
- 多标签交由下游使用，同时现有单一主路由兼容行为保持稳定；
- 明确否定的安全状态不触发安全路由，未否定或经模型确认的安全状态保持最高优先级；
- 不新增运行时 NLP 依赖、REST 变更或数据库迁移。
