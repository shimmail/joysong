# 医生项目单一价格源与地接服务费设计

**状态：** 已确认  
**日期：** 2026-08-23  
**范围：** Kotlin 服务端、React 后台管理系统、演示数据与支付活动图

## 1. 目标

同一机构项目可以绑定多位医生，每位医生独立配置一个 USD 项目价格。该价格同时作为旅游地接服务费的唯一计费基数：

```text
旅游地接服务费 = 医生项目价格 × 40%
```

费用按 USD 美分使用 HALF_UP 规则取整。例如：

- 医生 A：USD 3,999.00，地接服务费 USD 1,599.60；
- 医生 B：USD 4,299.00，地接服务费 USD 1,719.60。

本次同时修复机构项目保存时未提交医生价格而返回“医生项目价格不能为空且不能小于 0”的问题，并重新构造符合新支付流程的演示数据。

## 2. 核心决策

### 2.1 唯一价格源

`doctor_projects.price` 是“医生 × 机构项目”的唯一有效价格，复合键继续使用 `(doctor_id, institution_project_id)`。

- `institution_projects.price/original_price` 仅保留为机构项目的展示或参考信息，不参与订单计费。
- `doctor_institution_project_configs.medical_list_price` 暂不删除，仅作为旧接口和旧申请数据的兼容镜像，不再作为运行时计费来源，也不再提供独立编辑入口。
- 历史订单继续使用订单中已经固化的金额快照，不回算、不修改。

所有仍可能写入 `medical_list_price` 的兼容链路必须在同一事务中把相同金额写入 `doctor_projects.price`；若两个兼容字段同时出现但金额不同，服务端拒绝请求，不能猜测采用哪一个。

### 2.2 费率与金额

旅游地接服务费继续由 `TravelGroundServicePricing` 统一计算。平台比例取服务端 `OrderSplitProperties.platformRate`，当前业务配置固定为 `40.00%`；后台只读展示，不允许用户编辑。

派生的地接服务费不写入医生配置表。创建订单时仍固化：

- 医生项目价格分币快照；
- 平台服务比例基点快照（4000 bps）；
- 旅游地接服务费分币快照。

为避免数据库迁移，现有订单列 `medical_list_price_minor` 继续承载医生项目价格快照，接口语义和文档明确其兼容含义。

## 3. 后台管理交互

### 3.1 机构项目编辑

`InstitutionProjectsPage` 的机构项目弹窗直接维护医生绑定列表。每行包含：

1. 医生；
2. 医生项目价格（USD，必填、正数、最多两位小数）；
3. 只读旅游地接服务费（按当前 40% 实时计算）。

请求只提交：

```json
{
  "doctorBindings": [
    { "doctorId": "doctor-a", "price": 3999.00 },
    { "doctorId": "doctor-b", "price": 4299.00 }
  ]
}
```

不再发送无价格的 `doctorBindings`，也不再发送冗余 `doctorIds`。同一医生不能重复；医生必须与当前机构存在有效关系。

编辑已有机构项目时，接口返回的 `doctors[].price` 用于回填。修改价格后必须更新已有 `doctor_projects` 行，同时保留该医生已有的个人介绍、标签、排班、封面和案例图片。

### 3.2 消除重复入口

后台导航不再提供独立的“医生项目价格配置/项目分账配置”编辑入口。旧路由保留兼容跳转，旧接口暂时保留，但任何旧接口写入都必须更新同一 `doctor_projects.price`，不能形成第二份有效价格。

医生侧项目资料修改申请只展示一个“医生项目价格（USD）”输入。为兼容旧请求结构，客户端可暂时同时提交 `priceSuggestion` 与 `medicalListPrice`，但两者必须相等；审核通过后服务端更新唯一价格源并同步兼容镜像。

## 4. 服务端数据流

### 4.1 保存机构项目

创建或更新机构项目均在单一事务中完成：

1. 校验机构、公共项目、医生关系及医生价格；
2. 使用 `TravelGroundServicePricing.quote(price)` 验证价格能够产生至少 USD 0.01 的地接服务费；
3. 保存机构项目；
4. 按 `(doctor_id, institution_project_id)` 同步医生绑定：
   - 新医生：新增 `doctor_projects`；
   - 保留医生：仅更新价格和 `updated_at`，保留个人资料字段；
   - 移除医生：沿用现有逻辑删除绑定、软删除兼容配置并撤回待处理申请；
5. 将相同价格写入或恢复对应的兼容配置 `medical_list_price`。

任一步失败时整个事务回滚。

### 4.2 报价与下单

报价接口和订单创建均先读取选定的 `DoctorProjectEntity`：

1. 验证医生确实绑定该机构项目；
2. 读取 `doctor_projects.price`；
3. 调用 `TravelGroundServicePricing.quote(price)`；
4. 返回报价或写入订单快照。

运行时不再因为缺少 `doctor_institution_project_configs` 而拒绝下单。

## 5. 校验和错误处理

- 医生项目价格必须大于 0、符合 USD 两位小数和现有金额上限。
- 价格计算后的地接服务费必须至少为 USD 0.01。
- 医生未绑定当前机构、重复医生、缺少价格或金额精度非法时，保存前返回明确错误。
- 平台费率加载失败时，后台不显示猜测金额；服务端仍是最终校验方。
- 兼容字段金额与唯一价格源不一致时拒绝写入。
- 更新已有医生价格不得重建实体或清空个人资料。

## 6. 演示数据重新初始化

演示数据只通过 `seed.demo.enabled=true` 的 Kotlin initializer 生成。修改后必须在全新的隔离数据库中验证；不得清理或重置共享开发数据库。

新的种子数据至少包含：

- 同一个机构项目绑定两位医生，价格分别为 USD 3,999.00 和 USD 4,299.00；
- 兼容配置中的镜像价格与 `doctor_projects.price` 相同；
- 仅包含 `TRAVEL_GROUND_SERVICE_ONLY` 订单；
- 支付记录只允许 `TRAVEL_GROUND_SERVICE_FEE`，不得再生成 `CONSULTATION_FEE` 或 `BALANCE`；
- 订单示例精简覆盖 `PENDING_SERVICE_FEE`、`SERVICE_ACTIVE` 和 `COMPLETED`；
- 日记和评价若引用订单，只能引用有效的新流程订单。

初始化器仍使用稳定 ID 并保持幂等。旧数据库不会因 `INSERT IGNORE` 自动刷新，因此验收以新建空数据库为准。

## 7. 数据库与兼容策略

本次不新增 Flyway migration，不删除列、不改历史订单。

- 表结构已经支持按医生定价。
- `medical_list_price` 及相关申请字段保留一轮兼容期。
- 后续确认没有旧客户端或历史申请依赖后，可另立任务删除兼容字段；不纳入本次最小改动。

## 8. 测试策略

### 服务端

- 机构项目创建：同一项目两位医生分别保存不同价格。
- 机构项目更新：修改保留医生的价格并证明个人资料未丢失。
- 校验：缺少价格、负数、精度非法、重复医生和无机构关系均被拒绝。
- 报价和下单：同一机构项目选择不同医生得到不同的 40% 地接服务费。
- 兼容接口：写入时唯一价格源与镜像保持一致；不一致请求被拒绝。
- 初始化器：全新数据库中不存在旧支付流程、旧支付类型或无效医生绑定。

### 后台管理系统

- 新建和编辑弹窗能分别录入两位医生的价格。
- 每行实时显示正确的 USD 地接服务费。
- 提交载荷包含每位医生的 `price`，不包含冗余派生费用。
- 编辑回填与保存后数据保持一致。
- 费率不可用时不展示猜测金额。

### 隔离数据库验收

在功能 worktree 中按目录名推导 `WORKTREE_ID`，数据库名必须为 `myapp_<WORKTREE_ID>` 且以 `myapp_worktree_` 开头。执行迁移或初始化前必须输出实际数据库主机和库名。使用全新空数据库验证 Flyway 和全部 initializer，不连接共享开发数据库。
