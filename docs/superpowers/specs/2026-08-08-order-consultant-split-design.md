# 订单咨询师分账关联设计

## 目标

所有新建订单必须关联一个机构项目、一个已确认的机构咨询师和一个已确认可服务该机构项目的医生。订单创建时固化机构、咨询师和医生的标识与名称；创建分账记录时只读取这些订单快照。历史订单保留可查询能力，但关联信息不完整时不得分账。

## 数据模型

`orders` 增加 `consultant_id` 与 `consultant_name`。两列允许为空以兼容历史记录；应用层保证新订单写入非空值。机构与医生继续使用已有的 `institution_id`、`institution_name`、`doctor_id` 和 `doctor_name` 快照字段。

咨询师身份以 `institution_memberships` 中 `member_role = 'CONSULTANT'` 且 `status = 'APPROVED'` 为准，名称来自 `users.nickname`。医生仍须存在于 `doctor_projects` 的目标机构项目中。

## 下单与查询

创建订单请求增加必填 `consultantId`。订单服务拒绝缺少机构项目、医生或咨询师的请求；校验项目归属、机构项目启用状态、医生可服务关系及咨询师机构任职关系。机构项目详情提供其已确认咨询师列表，预约客户端要求选择一名咨询师并将其 ID 提交。

## 分账

`SettlementService.saveSettlement` 在查找分账比例前校验订单快照中的机构、机构项目、咨询师和医生标识及名称均完整。缺失任一项时抛出明确的不可分账错误，不创建结算记录。费率仍读取医生-机构项目生效配置，但收款对象身份只来自订单快照。

## 验证

订单服务测试覆盖缺少机构项目、医生和咨询师的拒绝路径，以及成功订单对咨询师快照的保存。结算服务测试覆盖历史订单缺少任一关联快照时拒绝分账和完整新订单可分账。
