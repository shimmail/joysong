| 受邀试点 | 受控账号和规模；关闭真实在线收款；限制敏感数据；人工运营兜底 | 仅限受邀试点 |
| 开发演示 | 虚构测试数据、无真实资金能力、与开发和生产隔离的受控演示配置；本机可使用开发配置，远程环境不得公网暴露 `dev` profile | 仅用于开发或演示 |

### 2.2 优先级和状态

- MUST：正式上线前必须完成并验证，任一未完成均可阻断发布。
- SHOULD：不阻断核心闭环，但未完成时必须隐藏入口或提供明确降级。
- OUT：不属于首发 MVP，不得对用户展示或承诺。

当前状态使用以下定义：

- 已实现待验收：已有真实代码链路，但尚无生产等价环境的完整证据。
- 部分实现：仅完成部分链路，或当前行为与 MVP 规则不一致。
- 未实现：不存在可用链路。
- 外部依赖未完成：依赖商户、短信、证书、域名、应用商店账号等外部条件。
- 已验证：已在生产等价环境通过验收并保存证据。

页面存在、开发环境模拟成功或历史测试通过，都不等于“已验证”。

状态统计时，表格中“状态机已实现”“代码已存在”等表述统一按上述五类归档。已有完整代码链路但缺本次运行或生产等价证据的，归为“已实现待验收”；只有局部链路、当前行为与规则冲突或仍需接口/UI 复核的，归为“部分实现”。本次没有运行测试或部署验收，因此没有任何条目因本次复核升级为“已验证”。

## 3. 产品边界

### 3.1 用户、服务与数据地域

| 项目 | 首发范围 |
|---|---|
| 用户来源 | 美国 |
| 应用上架地区 | 美国 |
| 客户端 | Flutter Android App、Flutter iOS App |
| 服务发生地 | 中国 |
| 业务时间基准 | 北京时间 UTC+8 |
| 生产后端 | 中国大陆 |
| 生产数据库 | 中国大陆 |
| 身份材料私有存储 | 中国大陆 |
| AI 服务 | 允许由位于中国大陆的第三方大模型服务商处理限定数据 |
| 平台管理 | 独立 React Web 管理后台，不进入 Flutter App |

面向美国用户、在中国大陆处理和存储数据所需的隐私披露、跨境数据说明、供应商协议和适用法律审查，必须在发布前由具备资质的专业人员确认。本文不替代法律意见。

### 3.2 商业和支付边界

平台首发只在线收取以 USD 计价的旅游地接服务费：

- 用户通过 Alipay+ 支付；
- 医疗费用由用户到院后直接向医院支付；
- 平台不代收医疗费用；
- 不提供医疗分账、余额、钱包或提现；
- 不启用 Stripe 新支付链路；
- 不提供咨询费、面诊金或医疗尾款在线收取。

### 3.3 Flutter App 角色

所有用户和专业身份均在同一个 Flutter App 中申请并查看审核结果。机构法定代表人、医生和顾问均已有专业工作台；顾问订单工作台的当前代码链路已实现，仍需真实账号端到端、对象级越权和身份撤销验收。

| 角色 | 首发职责 |
|---|---|
| 游客 | 浏览允许匿名访问的公开目录、公开内容、分享页和法律文档 |
| 普通用户 | 注册登录、浏览发现、AI 咨询、真人咨询、预约下单、支付、订单会话、退款、评价、内容互动和账号管理 |
| 医美顾问 | 维护有效机构关系、浏览项目目录、查看分配给本人的订单，并在服务端允许时回复订单会话；当前实现待端到端和对象级权限验收 |
| 医生 | 维护专业资料和机构关系；申请或维护授权项目；查看当前权限允许的专业订单 |
| 机构法定代表人 | 维护本人机构资料；审核机构成员关系和项目协作请求 |

首发范围不包含“机构客服”身份、申请或工作台；当前管理端和服务端仍保留该角色，发布前必须移除其管理端入口，并在服务端拒绝新建、审核或激活。其咨询职能由医美顾问承担。顾问不发起“服务已完成”请求。平台管理员继续使用独立 Web 管理后台。

## 4. 核心用户闭环

首发 MVP 必须支持以下完整流程：

> 使用美国 +1 手机号注册或找回密码 → 手机号和密码登录 → 浏览项目、机构、医生和内容 → AI 问答或转接真人顾问 → 选择项目、医生、有效机构顾问及预约时间 → 创建订单 → 支付 USD 旅游地接服务费 → 顾问资料和订单专属会话开放 → 顾问提供订单服务 → 用户确认完成或系统自动完成 → 用户评价。

发生退款时：

> 用户在订单完成前申请整笔退款 → 平台人工审核 → Alipay+ 原渠道退款 → 订单会话保留为只读。

### 5.10 账号注销和数据处理

账号注销必须遵守以下确定流程：

1. 用户在 App 内提交注销；
2. 系统检查进行中的订单、支付、退款、拒付和争议，以及已有专业身份；
3. 存在任一阻断事项时，立即拒绝本次注销并展示具体原因；
4. 被拒绝的注销申请不保存、不自动继续，也不提供“撤销注销申请”；
5. 用户处理完全部事项后必须重新提交；
6. 专业用户必须先完成专业身份注销审核并解除机构关系；
7. 无阻断事项时，立即永久注销账号并执行数据清理。

| 手机号、邮箱、密码、昵称、头像、证件和个人资料 | 永久删除或不可逆擦除 |

| AI 会话及相关用户数据 | 删除 |

| 已完成订单评价 | 匿名保留为“已注销用户” |
| 普通评论 | 匿名保留为“已注销用户” |
| 用户日记及日记图片 | 删除 |

## 7. 安全、部署和发布门槛

### 7.1 安全与数据

正式处理真实用户和身份材料前，必须完成：

1. 所有公网通信使用 TLS；正式客户端只允许生产 HTTPS API 和受信任跳转域名；
2. 身份材料迁移到中国大陆私有对象存储，使用加密/KMS、短期授权 URL、最小权限、访问审计和可验证删除；
3. Token、验证码、证件、聊天和支付数据不得进入普通日志；
4. AI 调用在服务端执行数据分类和字段白名单，禁止私信、订单私密信息、身份和资金数据外发；
5. 验证码、登录和敏感接口使用共享限流状态，覆盖手机号、IP、设备和全局维度；
6. 管理端身份、隐私和资金操作执行最小权限及不可篡改审计；
7. 密钥不进入仓库，生产启动时拒绝开发默认值和缺失配置；
8. 完成适用于美国用户、中国服务和中国大陆数据处理路径的专业法律与安全审查。

### 9.4 三档判定

| 目标 | 当前结论 | 原因与边界 |
|---|---|---|
| 正式落地 MVP | **No-Go** | 真实资金、安全、隐私、账号注销、核心订单规则、运营和生产交付均存在 P0；93 个 MUST 中没有已验证项 |
| 关闭收款的受邀试点 | **No-Go** | 真实受邀用户仍会触发认证、隐私、注销、敏感材料和运维义务；关闭支付不足以放行。若只使用虚构账号和虚构数据，应归类为开发演示而不是试点 |
| 开发演示 | **Conditional Go** | 独立、虚构数据、单实例、非交易 Demo 的目录执行器和安全 profile 已实现并通过隔离 MySQL 验证；当前仍缺真实远端资源/凭据、HTTPS、运行时冒烟、管理端与 APK 制品验收，不能直接标记 Go |

本次“开发演示”按可交付给指定验收人的独立远程 Demo 评估，不等同于开发人员本机启动。远程 Demo 放行前至少需要：独立数据库和资源权限边界、有效 HTTPS、禁止公网运行 `dev` profile、全部虚构数据、禁用真实交易、可重放演示目录及只读校验、Release APK/管理端制品，以及浏览、登录、AI、翻译和必要短信流程的留证冒烟。若要演示模拟支付，必须另建无真实资金能力的安全 Demo profile；当前模拟网关不得暴露公网。
