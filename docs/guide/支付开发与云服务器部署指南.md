# Stripe 支付开发与云服务器部署指南

> 适用范围：当前 Alipay+ USD 旅游地接服务费；历史 Stripe 查询/退款责任兼容
> 文档状态：Alipay+ 商户注册与真实网关尚未完成；开发环境提供显式隔离的模拟网关，历史 Stripe 测试链路仅作兼容参考
> 更新时间：2026-08-28

> **优先级说明（2026-08-22）：** 当前新订单已切换为下述 Alipay+ 旅游地接服务费合同。本文原有 Stripe 章节保留用于 `LEGACY_MEDICAL` 历史查询/退款责任和后续参考，不得用于创建 `TRAVEL_GROUND_SERVICE_ONLY` 新支付。

## 0. 当前 Alipay+ 旅游地接服务费流程（优先）

### 0.1 当前能力和真实可用性

平台只收一笔 USD `旅游地接服务费`：

```text
travelGroundServiceFeeMinor = roundHalfUp(
    medicalListPriceMinor * platformServiceRateBps / 10000
)
```

`medicalListPrice` 由医生维护。地接服务费率来自独立配置 `order.pricing.travel-ground-service.service-fee-rate`，不读取也不受 `order.split` 的历史分账配置影响；`platformServiceRateBps` 仅保留为兼容字段名。服务费不乘数量、不使用优惠券。用户到院后直接向医院支付医疗费，平台不为医疗费创建支付、退款、分账、结算或钱包记录。

订单创建时固化 `currency`、`medicalListPriceMinor`、`platformServiceRateBps`（兼容字段）、`travelGroundServiceFeeMinor` 和不可变的 `pricingPolicyRevision`。已实现：USD 报价和订单快照、顾问立即绑定、固定支付合同、30 分钟尝试状态规则、HTTPS redirect 校验、验签/查单/幂等的通用骨架、人工全额退款状态机，以及显式隔离的开发环境下单后自动支付。

尚未实现：Alipay+ 商户注册和收单参数仍在安排，代码没有真实 Alipay+ `PaymentGateway`，因此当前不能真实收款或退款。`dev` profile 可启用模拟网关跑通支付和退款业务链路，但它不具备任何真实资金能力。订单服务通知也是后续工作；姓名、护照、航班、酒店备案不在本期。

### 0.2 固定接口

报价：

```http
GET /api/discover/travel-ground-service-quote
    ?doctorId={doctorId}
    &institutionProjectId={institutionProjectId}
```

创建尝试：

```http
POST /api/orders/{orderId}/service-fee-payment-attempts
Authorization: Bearer <access-token>
Idempotency-Key: <稳定复用的 8..100 字符值>
```

请求没有 JSON body。服务端固定：

```text
paymentType = TRAVEL_GROUND_SERVICE_FEE
provider = ALIPAY_PLUS
paymentMethod = ALIPAY_PLUS_CASHIER
currency = USD
amountMinor = 订单 travelGroundServiceFeeMinor 快照
```

真实 gateway 接入后，客户端只接受 `nextAction.type=REDIRECT` 的 HTTPS URL，且主机必须等于或从属于受信任收银台域名。当前 Flutter 新流程白名单为 `cashier.alipayplus.com`；最终签约域名不同则先更新白名单和测试，不能放开任意 URL。用户境内外都可点击，不判断 GPS、IP 或国家。

查询：

```http
GET /api/orders/{orderId}/payments/latest
    ?paymentType=TRAVEL_GROUND_SERVICE_FEE
    &refresh=true

GET /api/payments/{paymentId}?refresh=true
```

App 回前台只刷新服务端状态。浏览器回跳、用户点击“已完成”和客户端本地计时都不能确认到账。

### 0.3 当前不可用结果和 30 分钟规则

provider registry 在本地尝试落库前检查 gateway。生产环境当前无真实 gateway，创建接口的正确结果是：

```text
HTTP 503
PAYMENT_PROVIDER_UNAVAILABLE
```

生产环境必须确认 `payments` 零新增、订单仍为 `PENDING_SERVICE_FEE`、顾问详情和订单会话仍锁定，并且没有 DEMO、硬编码 redirect 或模拟成功。

本地开发的两个开关彼此独立，base 和 `prod` 默认均为 `false`，`application-dev.example.yml` 示例均为 `true`：

```yaml
payment:
  alipay-plus:
    simulated-enabled: true
    auto-pay-on-order-create-enabled: true
```

`payment.alipay-plus.simulated-enabled=true` 只注册开发专用模拟网关；单独开启时，用户仍从订单详情手动点击“立即支付”。只有同时满足 `dev & !prod`、`simulated-enabled=true` 和 `auto-pay-on-order-create-enabled=true`，下单事务返回后才调用 `DevelopmentOrderAutoPaymentService`。该服务在订单创建事务之外复用真实 `PaymentService` 和支付持久化链路，以稳定幂等键 `dev-order-autopay-{orderId}` 发起地接服务费支付，并在成功、失败、结果未知和补偿成功的所有结果下重新读取规范订单后返回。

自动支付只有规范订单真正进入 `SERVICE_ACTIVE` 才表现为激活。provider 失败、结果未知或扣款进入补偿流程时，创建接口仍成功返回规范订单，订单保持 `PENDING_SERVICE_FEE` 或既有可恢复状态，不生成第二个幂等键，也不伪装支付成功。所有模拟支付和退款 ID 都以 `simulated-alipay-plus-` 开头，模拟退款拒绝处理非模拟支付 ID。

生产环境始终要求真实 provider，并保留订单详情的用户手动支付入口；它绝不会装配模拟网关、执行创建后自动支付或模拟成功。base 和 `application-prod.yml` 中的两个 false 是 fail-safe 默认值，不应描述成能覆盖更高优先级 Spring 环境属性的不可绕过边界。真正不可绕过的生产安全边界是模拟网关与 `DevelopmentOrderAutoPaymentService` 都使用 `@Profile("dev & !prod")`：即使两个属性最终解析值均为 true，只要 profile 含 `prod`（包括仅 `prod` 或同时启用 `dev,prod`），二者都不会装配或执行。

支付真实状态为 `CREATED`、`REQUIRES_ACTION`、`PROCESSING`、`SUCCEEDED`、`FAILED`、`CANCELLED`、`EXPIRED`、`PARTIALLY_REFUNDED`、`REFUNDED`。只有已超时的 `CREATED` / `REQUIRES_ACTION` 可以本地进入 `EXPIRED`；`PROCESSING` 或结果未知必须主动查单/对账，绝不能仅按本地时钟关闭。尝试明确失败、取消或过期不取消订单，用户可创建新尝试。

### 0.4 人工全额退款、完成与失败重试

用户可从 `SERVICE_ACTIVE` 或 `COMPLETED` 通过 `POST /api/orders/{orderId}/refund` 申请旅游地接服务费全额退款。申请时服务端保存 `originalStatus` 并进入 `REFUND_REVIEW`；`COMPLETED` 只表示地接履约完成，保留顾问公开资料和历史会话只读，不能发送，也不会进入医疗核验、尾款、`PENDING_SETTLEMENT`、分账或钱包。

用户在 `REFUND_REVIEW` 取消申请、或管理员拒绝时，订单必须恢复该退款记录的 `originalStatus`：恢复 `SERVICE_ACTIVE` 时重新允许发送，恢复 `COMPLETED` 时继续只读。管理员提交审核决定：

```http
PUT /api/admin/refunds/{refundId}/status
Content-Type: application/json

{ "status": "APPROVED" }
```

拒绝为 `{ "status": "REJECTED", "rejectReason": "..." }`。批准后订单进入 `REFUND_PROCESSING`，仅对原成功旅游地接服务费支付创建退款项；渠道确认成功才进入 `REFUNDED`。结果未知或任一退款项失败时父订单保持 `REFUND_PROCESSING`，绝不能报告为成功。

管理端通过 `GET /api/admin/refunds` 查看每个退款项的 `provider`、`status`、`providerRefundId`、`failureCode`、`failureMessage` 和时间戳。仅当父退款为 `REFUND_PROCESSING` 且存在 `FAILED` 项，才可调用：

```http
POST /api/admin/refunds/{refundId}/retry
```

重试只处理原 `FAILED` 项：有 `providerRefundId` 时查询或续办原渠道退款；没有 ID 时使用原幂等键重发；已 `SUCCEEDED` 的项绝不触碰。管理端在重试请求完成后刷新列表；即使刷新失败也必须释放重试按钮锁并如实提示刷新错误。

渠道若确认了无法激活订单的异常扣款（错额、错币种、重复/晚到成功，或订单已取消、删除、缺失），服务端保存真实成功支付，并为每个 `paymentId` 唯一建立 `payment_compensation_cases`。后台人员通过以下接口查看并审核触发精确实收金额的原渠道退款：

```http
GET /api/admin/payment-compensations
POST /api/admin/payment-compensations/{compensationId}/retry
```

已有 `providerRefundId` 时只查原退款；没有 ID 时始终复用 `payment-compensation-{paymentId}` 幂等键。渠道未知结果保持 `PROCESSING`，明确失败保持 `FAILED`，均不得伪装成功。该异常款独立于用户的正常旅游地接服务费退款，第二笔成功扣款不会阻塞原订单退款。

医疗费始终由用户到院直接支付医院，平台不创建医疗费支付、退款、结算、分账或钱包记录。Alipay+ 商户/收单参数未就绪时，生产支付和退款联调仍被阻塞；开发模拟成功不得被理解为真实渠道确认。

### 0.5 部署与旧 Stripe 安全门

真实 Alipay+ gateway 合入前不要发明或配置猜测性的 `ALIPAY_*` 变量。必须先从最终签约收单方确认商户号、产品、USD 能力、正式 API/收银台域名、签名和证书轮换、原始通知、查单、退款、幂等、过期时间及对账合同，再把实现、配置校验和本指南一起更新。

当前生产默认：

```dotenv
STRIPE_LEGACY_ENABLED=false
PAYMENT_RECONCILIATION_ENABLED=true
```

Stripe adapter 只处理历史责任。关闭时，启动安全门会检查进行中支付、可退款支付、未知状态和未完成退款；查询失败或存在责任均 fail-closed，并以 `STRIPE_LEGACY_PAYMENTS_REQUIRE_ADAPTER` 阻止启动。只有核对出真实历史责任时才可受控启用旧 adapter，这不是新支付方案。

支付迁移为追加的 `V29__travel_ground_service_order_flow.sql`、`V30__order_service_conversations.sql`、`V31__store_raw_payment_event_payload.sql`、`V32__payment_compensation_and_usd_price_precision.sql` 和 `V35__snapshot_order_pricing_policy_revision.sql`，不得删除旧订单。V32 新增异常扣款补偿工单，并把医生医疗套餐 USD 配置收紧为两位小数：历史四位小数按半入规则转换，超出当前应用金额上限的老数据保留供后台修正，在修正前会被统一金额校验拒绝使用。V35 为既有旅游订单按 `platform_service_rate_bps` 回填 revision，并强制 `TRAVEL_GROUND_SERVICE_ONLY` 行的 `pricing_policy_revision` 非空。部署前须在 worktree 隔离的新空数据库验证 fresh migration，并验证 V28 历史行升级后仍为 `LEGACY_MEDICAL`。

## 1. 历史 Stripe 边界（仅 `LEGACY_MEDICAL`）

- 客户端：Flutter Android/iOS 共用支付流程，使用系统浏览器打开 Stripe Hosted Checkout。
- 支付阶段：订单面诊金 `CONSULTATION_FEE` 和尾款 `BALANCE` 分开支付，每个阶段独立生成支付尝试。
- 渠道：当前只启用 `STRIPE`，客户端支付方式传 `CARD`；PayPal、微信支付、支付宝暂不启用。
- 币种：目标业务统一使用 `USD`，金额在渠道边界使用最小货币单位整数（例如 `$30.00` 对应 `3000`）。
- 最终事实：成功页和浏览器返回不是收款凭证，只有 Stripe Webhook 验签或服务端查单确认成功，才推进本地订单。

历史 Stripe 流程图已归档移除；当前支付活动图见 [`TRAVEL_GROUND_SERVICE_PAYMENT_WORKFLOW.puml`](../../design/TRAVEL_GROUND_SERVICE_PAYMENT_WORKFLOW.puml)。

## 2. 历史 Stripe 支付链路（仅 `LEGACY_MEDICAL`）

1. App 点击“支付面诊费”或“支付尾款”。
2. App 调用 `POST /api/orders/{orderId}/payment-attempts`，带稳定的 `Idempotency-Key`、支付阶段、`STRIPE` 和 `CARD`。
3. 服务端锁定订单，使用订单金额快照创建本地 `payments` 记录，不信任客户端金额。
4. 服务端调用 Stripe `POST /v1/checkout/sessions`，返回 Hosted Checkout URL。
5. App 校验 HTTPS 和 `checkout.stripe.com` 白名单后使用系统浏览器打开 URL。
6. Stripe 完成卡支付或 3DS 验证，并异步 POST 到 `/api/payment-webhooks/STRIPE`。
7. 服务端验签、核对 payment/order metadata、USD 和最小单位金额，幂等推进支付和订单状态。
8. App 回到前台后调用查单接口；`SUCCEEDED` 才展示支付成功。

## 3. 如何获得 Stripe 配置（仅历史责任）

### 3.1 测试密钥

1. 登录 Stripe Dashboard：<https://dashboard.stripe.com>。
2. 切换右上角 **Test mode**。
3. 打开 **Developers → API keys**，复制：
   - `Publishable key`：本项目 Hosted Checkout 不需要放进 App；
   - `Secret key`：`sk_test_...`，只放服务端。

### 3.2 Webhook Secret

本地测试推荐 Stripe CLI：

```powershell
stripe login
stripe listen --forward-to http://127.0.0.1:8080/api/payment-webhooks/STRIPE
```

命令输出的 `whsec_...` 就是本地 `STRIPE_WEBHOOK_SECRET`。每个 Stripe Webhook Endpoint 都有独立 signing secret，不能混用。

云服务器配置：

1. Dashboard → **Developers → Webhooks → Add endpoint**。
2. 填写 `https://api.example.com/api/payment-webhooks/STRIPE`。
3. 订阅：
   - `checkout.session.completed`
   - `checkout.session.async_payment_succeeded`
   - `checkout.session.async_payment_failed`
   - `checkout.session.expired`
4. 打开 Endpoint 的 **Reveal signing secret**，复制新的 `whsec_...` 到云服务器 Secret Manager。

### 3.3 回跳地址

服务端启动时强制要求成功页和取消页为公网 HTTPS 且有主机名：

```dotenv
STRIPE_SUCCESS_URL=https://app.example.com/payment/success?session_id={CHECKOUT_SESSION_ID}
STRIPE_CANCEL_URL=https://app.example.com/payment/cancel
```

开发环境可以暂时使用一个 HTTPS 测试页；不要使用 `joysong://`、`localhost` 或裸域名。正式 App 回跳应使用已配置 Android App Links / iOS Universal Links 的域名。

### 3.4 其他 Stripe 配置

- `STRIPE_API_BASE`：固定为 `https://api.stripe.com`，除非使用受控代理。
- `STRIPE_API_VERSION`：留空使用账户默认版本，升级时需回归测试。
- `STRIPE_PRODUCT_NAME`：Checkout 页面商品名称，例如 `Joysong consultation fee`。
- `STRIPE_WEBHOOK_TOLERANCE_SECONDS`：签名时间窗口，代码要求 `60..900`，默认 `300`。

## 5. 历史支付接口契约（不得用于新流程）

### 创建支付尝试

```http
POST /api/orders/{orderId}/payment-attempts
Authorization: Bearer <access-token>
Idempotency-Key: <稳定唯一值>
Content-Type: application/json

{
  "paymentType": "CONSULTATION_FEE",
  "provider": "STRIPE",
  "paymentMethod": "CARD"
}
```

尾款只把 `paymentType` 改为 `BALANCE`。响应中的 `nextAction.type=REDIRECT` 且 `nextAction.url` 为 Stripe Checkout URL 时打开浏览器。

### 查询与确认

```http
GET /api/payments/{paymentId}?refresh=true
POST /api/payments/{paymentId}/confirm
```

`confirm` 仍然由服务端查 Stripe，不接受客户端伪造成功。

### 退款

用户申请：

```http
POST /api/orders/{orderId}/refund
{
  "reason": "不想去了",
  "description": "用户说明",
  "evidenceUrl": "",
  "reasonCode": "USER_CHANGED_MIND"
}
```

管理员审核并执行原路退款：

```http
PUT /api/admin/refunds/{refundId}/status
{
  "status": "APPROVED"
}
```

服务端会按 `refund_items` 找到原成功支付，并调用 Stripe Refund；网络不确定时进入 `REFUND_PROCESSING`，由补偿任务重试。

## 6. 历史 Stripe 测试验收

Stripe Test mode 使用：

```text
卡号：4242 4242 4242 4242
有效期：任意未来日期
CVC：任意三位数
```

支付成功必须同时满足：

- Checkout 页面完成支付；
- Webhook 返回 HTTP 2xx，或服务端查单得到 `payment_status=paid`；
- `payments.status=SUCCEEDED`、`provider_payment_id` 和交易 ID 非空；
- `currency=USD`，`amount_minor` 与订单快照一致；
- 面诊金成功只推进面诊金阶段，尾款成功后订单剩余金额为零。

退款成功必须同时满足：

- `refunds.status=APPROVED`；
- `refund_items.status=SUCCEEDED`；
- `provider_refund_id` 非空（Stripe 通常为 `re_...`）；
- `orders.status=REFUNDED`、`refund_status=APPROVED`；
- Dashboard Test mode 中 Refund 状态为 succeeded。

数据库核验：

```sql
SELECT id, order_id, payment_type, provider, payment_method, currency,
       amount_minor, status, provider_payment_id, provider_transaction_id, paid_at
FROM payments WHERE order_id = '<order-id>' ORDER BY created_at;

SELECT id, refund_id, payment_id, provider, amount_minor, currency,
       status, provider_refund_id, completed_at, failure_code
FROM refund_items WHERE refund_id = '<refund-id>';
```

必须测试：取消支付、卡片失败、3DS、重复 `Idempotency-Key`、重复 Webhook、Webhook 延迟、主动查单、部分退款和全额退款。

## 7. 云服务器必须更换的配置

### 7.1 域名和网络

- `api.example.com`：Spring Boot API 和 Stripe Webhook；
- `app.example.com`：支付成功/取消页和 App Link/Universal Link；
- DNS 指向云服务器；Nginx 终止 TLS；外网只开放 `80/443`，不开放 `8080/3306`；
- Webhook 反向代理必须保留原始请求体和 `Stripe-Signature`。

### 7.2 服务端生产环境变量

以下变量必须替换为正式云环境值：

`ADMIN_PHONE` 是长期保留的唯一固定管理员裸 11 位号码。只有迁移后 `users=0` 的首次启动才临时追加 `ADMIN_PASSWORD=<12-128位强密码>`；创建成功后立即从部署环境移除，再以同一 `ADMIN_PHONE` 无密码变量重启验证。后续重启不读取该变量，再次设置也不会重置管理员密码。完整流程见[项目配置指南](CONFIGURATION_GUIDE.md#24-仅首次创建管理员的临时密码)。

`UPLOAD_PRIVATE_DIR` 保存私有身份材料，只允许 Java 进程读写，不能与 `UPLOAD_LOCAL_DIR` 或 Nginx `/images/` alias 共用，并须纳入备份恢复。

获取方式：DB/JWT 密钥使用密码管理器生成；首次管理员密码也由密码管理器生成，但只在上述首次创建阶段临时注入。OSS/SMS/AI 从对应云服务控制台创建生产凭证。Stripe Live 凭证仅在处理已核对的历史责任时配置，不能用于新订单，也不能复用测试密钥。

### 7.3 Flutter Release 配置

```text
--dart-define=APP_ENV=production
--dart-define=API_BASE_URL=https://api.example.com
--dart-define=GOOGLE_SERVER_CLIENT_ID=<Web OAuth Client ID>
# 仅 iOS 增加：
--dart-define=GOOGLE_IOS_CLIENT_ID=<iOS OAuth Client ID>
```

Release 包不能使用局域网 IP、`10.0.2.2`、HTTP 或测试 API。新流程 provider、method 和金额由固定服务端接口决定，不使用 `PAYMENT_PROVIDERS=STRIPE`；Alipay+ redirect 仅走代码中的受信任 HTTPS 白名单。

### 7.4 历史 Stripe 责任处理（不用于新流程）

1. 完成 Stripe 商户主体、KYC、银行账户和收款地区审核。
2. Dashboard 切换 **Live mode → Developers → API keys**，创建/复制 `sk_live_...`。
3. 在 Live mode 新建 Webhook Endpoint，地址为 `https://api.example.com/api/payment-webhooks/STRIPE`。
4. 订阅四个 Checkout Session 事件并复制该 Endpoint 专属 `whsec_...`。
5. 仅在安全门确认存在历史责任且运维批准后，把生产 Secret 写入云 Secret Manager，并临时设置 `STRIPE_LEGACY_ENABLED=true` 后重启服务。
6. 只验证历史查询/退款责任；不得用此 adapter 创建旅游地接服务费新支付，也不存在“逐步放量”新 Stripe 订单。

## 8. 上线检查与安全

- `ConfigValidator` 在 `prod` 会 fail-closed 检查数据库、OSS、短信、管理员和 AI 等基础配置；启动日志必须出现 `All required configuration values are present.`。历史 Stripe 责任另由 `StripeLegacyPaymentGuard` 独立 fail-closed 检查。
- 生产 Alipay+ gateway 尚未实现时，不能把服务启动成功理解为支付可用；固定创建接口必须继续返回 503 / `PAYMENT_PROVIDER_UNAVAILABLE` 且零本地尝试。开发模拟器不得进入 `prod` profile。
- 健康检查：`GET https://api.example.com/actuator/health`。
- 查看后端：`journalctl -u joysong -f`；查看 Webhook 失败和长期 `PROCESSING`。
- Secret 不得进入 Git、Flutter、日志、截图或工单；发现已提交的密钥必须立即在 Stripe 撤销并重新创建。
- 当前新订单金额固定 USD 分币；上线前须确认历史订单迁移和所有导入接口不会覆盖新订单的金额、币种、比例或顾问快照。
